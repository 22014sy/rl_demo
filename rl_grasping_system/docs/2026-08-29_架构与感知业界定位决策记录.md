# 2026-08-29 · 架构与感知的业界定位（决策记录）

> 背景：投递准备期的三问自查——① 残差架构（标称+残差）业界认可吗？② 现在的感知是深度相机吗？
> ③ 训练端要不要换成深度相机？
> 结论：**架构是业界主流范式（可作简历主打叙事）；感知当前是 oracle+噪声（刻意的方法论选择）；
> 训练端暂不换深度相机（岗位匹配与性价比），升级路径已铺好。**

---

## 1. 残差架构（标称轨迹 + RL 残差）业界认同度

### 结论：**是业界认同的主流做法（Residual RL）**

### 1.1 学术依据（有明确出处）
| 出处 | 内容 |
|---|---|
| **Johannink et al. 2018**（arXiv:1812.03201，ICRA 2019） | *Residual Reinforcement Learning for Robot Control*——正式提出"在已有控制器输出上学习残差"，与 `v = v_nominal + Δv` 同构 |
| **RMA**（Xia et al. 2021，Meta/CoRL） | 四足机器人 Rapid Motor Adaptation：基础策略 + 域自适应模块 |
| **波士顿动力 Spot**（公开架构） | 腿部控制 = 参考轨迹 + 学习残差 |
| 学术界 2020+ | 动态避障主流为 MPC/CBF/反应式势场/**RL 残差**（见 `docs/混合控制架构设计.md` §3） |

### 1.2 为什么业界认同（相对端到端）
1. **样本效率**：只学"偏差"，不重学整个任务（本项目三路消融实证）；
2. **可审计/安全**：标称合规可查、残差受限、异常归零回安全标称；
3. **sim2real 友好**：标称保证域一致性，残差受域差影响小（D6/消融实证：端到端对域变化最敏感、残差最鲁棒）；
4. **工业集成**：工厂已有 PID/规划器，残差是增量升级不是推倒重来。

### 1.3 工业应用实例
- 汽车/3C 产线力控装配（KUKA/ABB/发那科：力控回路 + 学习补偿）
- 人形机器人（Tesla Optimus、Figure：参考轨迹 + 学习修正的分层控制）
- 手术机器人（残差学习补偿组织变形）

### 1.4 契合点与诚实边界（面试必说）
| 契合点（可讲） | 诚实边界（主动交代） |
|---|---|
| 三路消融证明残差必要性（会验证架构决策） | "标称"是 **MuJoCo 速度场仿真替身**（`nominal_trajectory.py`），非真实 MoveIt/OMPL——部署侧才是真 MoveIt |
| 残差幅度"静态小/动态大"分工 | 业界共识"残差适合小修正、不适合大偏离"——本项目动态避障正是"微小修正"（每步 2mm） |
| 有 sim2real 契约（速度级 IK = Servo twist） | 大偏离场景：残差归零 + 触发重新规划/模式切换（安全层兜底） |

### 1.5 面试话术
> 残差策略是学术与工业共同认可的分层控制范式（Johannink 2018、RMA、Spot）。核心价值：RL 只学
> 已有控制器覆盖不了的偏差，保留标称的确定性、可审计性与域一致性。我用三路消融（端到端/残差/
> 纯标称）本地验证了该选择，用"残差幅度静态小/动态大"作架构分工证据——符合业界"标称负责规划内、
> 学习负责规划外修正"的分工原则。

## 2. 感知现状（2026-08-29 核实）

### 2.1 训练端
| 项 | 现状 |
|---|---|
| 观测 | **oracle（物理真值）** + 可选噪声（`perception_noise_std/dropout`）——不是相机图像 |
| 深度相机基础设施 | **已落地但默认关闭**：MJCF 有 `eye_to_hand` 相机；`get_depth_image()`/`get_camera_image()` 已实现（environment.py 1696/1725 行）；`depth_enabled: bool = False`（默认关=零渲染开销）→ 尚未接入观测 |

### 2.2 部署端（兄弟仓库）
- **是深度相机链路**：Gazebo RealSense 仿真插件 + YOLO 检测 + 深度反投影 + TF（`obj_detect.py`/`det_tf.py`）——但 RL 桥未打通，独立系统。

### 2.3 为什么这样设计（面试话术）
1. **隔离变量**：先证明控制层收敛（oracle），再用噪声量化感知容忍度（D6 实证 σ≤3cm/漏检20% 不降）；
2. **训练效率**：全分辨率深度图训练慢，ROADMAP 明确"降维特征优先、CNN 后置"；
3. **两端契约**：训练端"等价感知观测"（oracle+噪声）模拟部署侧相机分布，防部署时观测分布突变（sim2real 核心）。

## 3. 训练端是否换深度相机（决策：当前不换）

### 3.1 结论与理由
| 理由 | 说明 |
|---|---|
| 岗位不要求视觉输入 | RL 运动控制岗考察 MDP/奖励/训练/归因/控制架构——oracle 下已充分展示 |
| 感知鲁棒性已证明 | D6 已量化感知容忍度，感知叙事够用 |
| 成本高、收益不确定 | 深度图进观测 → 重训 + 训练变慢 + 收敛不确定（CNN 为后续增强） |
| 对任务冗余 | 目标位置已知 + oracle 观测已给目标，深度图的定位信息冗余 |

### 3.2 什么情况值得换
1. 目标岗位偏**具身智能/视觉-运动操作**（面试官期待视觉输入）；
2. 时间充裕（>2 周）；
3. 想要"视觉抓取"叙事。

### 3.3 轻量升级路径（若换，不用 CNN）
- 用已就绪 `get_depth_image()` + `eye_to_hand` 相机提取**降维特征**（目标 ROI 中心 / 最近障碍距离/方向）替换/拼接 oracle 槽位；
- 投入约 1 周（改观测 + 重训）；全分辨率 CNN（ROADMAP Phase 2 C）不建议（慢 + 边际收益）。

### 3.4 面试话术（不换时的诚实定位）
> 训练端刻意用 oracle+感知噪声，是隔离变量的方法论选择：先证明控制层收敛，再用噪声量化容忍度
> （D6 实证 σ≤3cm 不降，说明感知误差不是瓶颈）。深度相机链路已分两层就绪——训练侧
> `get_depth_image()` 渲染函数已实现（Phase 2 接入），部署侧是真 RealSense+YOLO+深度反投影
> （兄弟仓库），两端感知特征契约对齐。若任务需要视觉泛化，升级路径已铺好（降维深度特征 → 可选 CNN）。

## 4. 简历定位汇总（2026-08-29 定稿方向）

| 维度 | 简历怎么写 | 面试怎么答 |
|---|---|---|
| 架构 | "混合残差架构"（Residual RL 范式） | 有学术出处 + 工业应用 + 本地消融证据 |
| 感知 | "感知鲁棒性"（oracle+噪声验证） | 隔离变量方法论 + D6 量化 + 升级路径就绪 |
| 部署 | 部署契约 + 三层架构设计（不写"已部署"） | 仿真验证控制/奖励架构，真机为后续阶段 |
