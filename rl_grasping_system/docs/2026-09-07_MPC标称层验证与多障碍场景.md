# MPC 标称层验证与多障碍场景（2026-09-07 / P2c）

> 目的：验证 `nominal_mode='mpc'` 标称层在 residual 残差架构下的纯 MPC 行为，
> 与 `scripts/mpc_ur5_grasp.py` 基线对齐；并验证多障碍（static3/mixed3/mixed_z）与
> z 方向运动的 per-obstacle 规格支持，为 Stage 2「MPC 之上训练 RL 残差」提供基线/动机数据。

## 1. 架构与对齐口径

混合残差：`v_servo = v_nominal(t) + Δv`；验证时 `action=0 → Δv=0 → v_servo = v_MPC(t)`，
即**同一 residual 环境/夹爪状态机**下的纯 MPC（`scripts/mpc_nominal_verify.py`）。

MPC 求解与 `mpc_ur5_grasp.py` 基线同口径（逐项核对）：

## 3. 调试中修复的关键 bug（对齐基线的必经之路）

1. **`u0` 二维喂 SLSQP → `ValueError: 'x0' must only have one dimension`**：
   scipy `minimize` 每步抛异常 → 每步 fallback → 输出≈P 控制 → 无避障 → dyn_both 碰撞 50%。
   修复：`minimize(_obj, u0.ravel(), ...)`（对齐基线 `x0.ravel()`）。修复后碰撞 50%→0%。
2. **static 场景误配 `obstacle=("legacy", 1, 0.0)`**：应为 `("off", 0, 0.0)`。
   原来 static 实际带 1 个静态障碍（堵 hover）→ 0% 超时；修复后 90%。
3. **`solve_time` 计时 t0 在 `minimize` 之后赋值**：avg_solve 恒 0.0s；t0 前移修复。

> **v_max=0.125 的 trade-off（2026-09-07 实证）**：静态/核心场景（static/dyn_target/dyn_both）
> 无回归甚至改善（len 缩短）；多障碍下因场景而异——mixed_z 改善、mixed3 变差。这构成
> **Stage 2 RL 残差的直接动机**：RL 残差在 MPC 提速后学会"高速下仍安全规避"，把 mixed3 的
> 33.3% 碰撞压回安全地板、把 mixed_z 的部分成功提升为可靠成功。

> 配置修复：多障碍场景（count>1 或 specs）须 `obstacle_on_nominal_path=True` 走
> `_place_obstacles_on_path` 的**横向障碍墙自动布局**（防重叠/防初始接触）。
> 原先 legacy count=3 非 on-path 时 3 障碍全叠 `obstacle_fixed_pos=(0.06,0.40,0.35)`（距

## 5. 结论与 Stage 2 意义

- **对齐达成**：三核心场景（static/dyn_target/dyn_both）纯 MPC 行为与基线一致
  （collision 全 0%、成功率差异落在 n=30 噪声区间内），MPC 标称层可作为 residual 架构的
  drop-in 标称。v_max 对齐契约 0.125 后 static/dyn_both 平均收敛步数明显缩短
  （static 77.2→66.2、dyn_both 131.2→111.0），dyn_target 不变（噪声内）。
- **MPC 局限（Stage 2 动机数据）**：
  1. 多静态障碍（横向墙）+ D_SAFE=0.20 → 到不了 hover（static3 0%）；
  2. 非匀速运动（z 三角波）→ 线性外推预测失效 → 碰撞（mixed_z 13.3% coll）；
  3. **v_max 提速后 mixed3 碰撞 0→33.3%**（更激进撞 random 动态障碍；含种子混淆）——
     「MPC 提速换取收敛」在随机动态障碍下的代价，正是 RL 残差要修复的。
  这些正是「随机/非匀速动态下精确模型失效、RL 靠经验学统计性规避」的叙事证据
  （基线实验文档 H1），为 Stage 2「在 MPC 之上训练 RL 残差」提供基线。

- **待办**：~~基线 dyn_both n=30 复测~~ → 完成（2026-09-02 基线 70.0%/0%/len 127.5；本实现
  v_max=0.125 复测 80.0%/0%/len 111.0，+10pp，CI 重叠不显著）。差异归因：障碍速度来源——
  本实现用 freejoint **qvel 真值**（与 RL 观测槽位 obstacle_vel 同源），基线用上一步位置
  **差分**；真值在随机游走下预测更准 → 成功率略高。两者均 collision 0%，对齐达成。

## 6. v_max 对齐修复（2026-09-07 受控对比，含统计诚实性记录）

**背景**：`mpc_nominal.py` 最初 `v_max = nominal_approach_speed = 0.12`（速度场标称的接近
速度语义），而基线 `mpc_ur5_grasp.py` 用契约 `V_MAX = 0.125`（= max_ee_delta/T）。
dyn_target 初测 70%（旧）vs 基线 80%，一度怀疑是 v_max 差 4% 导致追击相位滞后。

**受控对比过程**：
1. n=10 smoke：v_max=0.12 → 70.0%；v_max=0.125 → 80.0%。表面看"+10pp 恢复"。
2. n=30 正式：v_max=0.125 → **66.7%**（旧 0.12 口径 70%）。**n=10 的 +10pp 是样本噪声
   误判**（8/10 vs 7/10 的二项噪声）；正式样本下 v_max 对 dyn_target 无可验证改善。

**结论（修正早期假设）**：
- **v_max 不是 dyn_target -10pp 的根因**；n=30 下 66.7% vs 基线 80% 的差距落在二项
  95%CI 内（[49.8,83.6] vs [65.7,94.3]，重叠），不可判定。
- **仍保留 v_max=0.125 为默认**（专用字段 `mpc_nominal_v_max`，不复用 `nominal_approach_speed`
  语义），理由：① 与基线/部署契约完全同口径；② static/dyn_both 收敛步数明显缩短；
  ③ mixed_z 碰撞 33.3→13.3% 且出现部分成功。
- **代价**：mixed3 碰撞 0→33.3%（seed 混淆，但方向可信）——如实记录为 Stage 2 动机。
- 结果落盘：`results/mpc_nominal/{static,dyn_target,dyn_both,static3,mixed3,mixed_z}.json`
  （n=30，逐 episode success/collision/len/solve/fallback）。

**方法论备忘**：本阶段多次"±10pp 现象"（v_max 恢复、dyn_both +10pp、dyn_target -10pp）
均在 n=30 ±8~17pp 的二项噪声内。**后续 Stage 2 判定必须固定 n 与判定线**（目标 ≥80~86.7%
远超噪声区间，碰撞 ≤5% 判定碰撞率），避免单次 n=30 下的方向性误读。
