## 2. 关键澄清：MoveIt2 是"部署侧"的规避，训练侧不用它

| 侧 | 奇异处理 | 说明 |
|---|---|---|
| 训练侧（rl_grasping_system，纯 MuJoCo RL） | 奇异检测 + 速度置零（防御） | RL 是策略探索式学习，不调规划器；训练环境无 ROS/MoveIt2 |
| 部署侧（ros2_moveit2_ur5e_grasp，MoveIt2） | Trac-IK/KDL + 奇异规避 + 碰撞检测兜底 | 契约 §8 明确分工；属 D1 桥接阶段（另仓） |

契约 §8 原文："奇异规避：速度雅可比病态检测；**部署侧由 MoveIt2**（Trac-IK/KDL + 关节限位 + 碰撞检测）兜底"

## 3. 实机部署工程规范视角：sim-to-real 一致性

评判核心：**训练侧行为必须与实机部署行为对齐**。
实机上奇异语义 = MoveIt2/Trac-IK 规划失败、UR 控制器奇异附近报错/限速 = "**这一步不可达/该状态应被避免**"，由**规划/控制层兜底**。

| 方案 | 实机一致性 | 工程判断 |
|---|---|---|
| A · 奇异时环境自动移回 safe_config | ❌ | 实机没有"环境自动救回"；会教策略依赖环境兜底 → 行为断裂。不推荐 |
| B · 奇异 = 失败信号（终止/惩罚） | ✅ | 与部署语义（规划失败/任务失败）完全对齐；策略学会"别进奇异"。最符合工程规范 |
| C · 放宽奇异检测 | ❌ | 训练允许奇异区乱动、实机拒绝 → 不一致 |
| D · 增大 velocity_ik 阻尼 | ⚠️ | 数值稳定补充（类实机奇异降速），但不能替代规避机制；阻尼过大会降正常实现率 |
| E · 现状（置零卡 300 步） | ⚠️ | 实机也会"停/限制"，但实机是短暂受限+重规划/失败，不是"卡到超时"；浪费训练步数 |

## 4. 推荐方案：B 为核心 + D 数值补充

工程细化（避免"任何奇异瞬间就终止"太激进，训练早期会全是失败）：

- **奇异步计罚**：处于奇异状态每步给小的负奖励（shaping 惩罚）
- **连续困在奇异超过阈值（如 50 步）→ `truncated=True` 提前终止**（对应实机"持续不可达 → 任务失败"）
- **短暂路过奇异**（误入后立刻脱出）不终止
- `velocity_ik` 阻尼 λ 0.05 → 0.08（奇异邻域数值稳定，类实机奇异降速）

语义闭环：
> 训练侧：奇异 = 应避免的状态，困住过久 = episode 失败 → 策略学会规避
> 部署侧：MoveIt2（Trac-IK/KDL + 关节限位 + 碰撞检测）规划层兜底 → 实机永不进入奇异

契约 §8 无需改动（分工本就如此，训练侧从"卡住"改为"失败信号"）。

## 5. 实施要点

1. `config.py`：新增 `singularity_penalty`、`singularity_max_streak=50`；`velocity_ik_lam` 0.05→0.08
2. `environment.py`：奇异时 `_vel_target` 置零（保留安全停止）+ 累计 `_singularity_streak`；每奇异步扣罚
   （计入 `episode_breakdown['r_singularity']` 与返回 reward）；`streak >= singularity_max_streak` → `truncated`
3. 重启可视化训练验证：早期 episode"卡 300 步"消失，策略更快远离奇异

## 6. 实施结果（2026-08-21）

已完成并冒烟验证：
- `config.py`：`velocity_ik_lam=0.08`、`singularity_penalty=-0.5`、`singularity_max_streak=50`
- `environment.py`：
  - reset 初始化 `_singularity_streak=0`、`_singularity_penalty=0.0`；`episode_breakdown` 增加 `r_singularity` 键

  - 奖励：`reward += penalty`，并计入 `episode_breakdown['r_singularity']`
  - `truncated`：`streak >= 50` → 提前终止
- 冒烟（构造 elbow=0 肘奇异）：
