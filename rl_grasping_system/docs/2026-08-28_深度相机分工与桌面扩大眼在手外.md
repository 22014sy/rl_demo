## 1. 决策一：深度相机在训练端还是部署侧

### 1.1 结论

| 端 | 相机形态 | 职责 |
|---|---|---|
| **部署侧** | 真相机（Gazebo 仿真插件 → 真机 RealSense D435i） | 目标 3D 定位（YOLO + 深度反投影）+ 障碍点云 → 碰撞体 |
| **训练端** | **不加真相机，加"等价感知观测"** | 模拟部署侧相机输出特征的分布（非像素） |

### 1.2 理由（为什么训练端不加真相机）

1. **物理必然**：训练是批量并行仿真（MuJoCo），没有也不应依赖相机硬件；真机相机只有部署环境一台。
2. **感知分布一致性（sim2real 核心）**：部署侧相机产出带噪目标位置/障碍距离，训练端若继续吃 oracle 真值，策略上线时观测分布突变（perception distribution shift）→ 直接失效。
3. **训练效率**：ROADMAP 明确"深度图不进全分辨率（训练慢），用**降维特征**优先，CNN 编码器作为后续增强"。
4. **隔离变量**：先保持动作/奖励不变、只换观测（Phase 2 降级方案），失败可归因。

### 1.3 训练端感知的三个递进层级（成本从低到高）

| 方案 | 做法 | 状态 |
|---|---|---|
| A. 噪声降级（先做） | oracle 特征 + 高斯噪声 + 随机漏检，模拟相机测量误差 | D6 验证方向；验收线"成功率下降 <10%" |
| **B. 仿真渲染（本次落地基础）** | `mujoco.Renderer` 渲染眼在手外深度图（本次新增 `environment.get_depth_image`），提取与部署侧点云管线**同构的降维特征** | ✅ 基础设施本次落地 |
| C. CNN 编码器（后续） | 全分辨率深度图直接进网络 | 文档明确"后续增强"，不做优先 |

## 2. 感知特征接口契约（两端对齐）

**原则：部署侧相机产出什么特征、什么噪声特性，训练端就喂同格式、同噪声统计的合成特征。**

| 感知通道 | 部署侧（真机 D435i） | 训练端（仿真等价） |
|---|---|---|
| 目标 3D 位置 | YOLO bbox + 深度反投影 + TF | 物理真值 + 高斯噪声 + 随机漏检（方案 A）；后续由深度图提取（方案 B） |
| 障碍距离/方向 | 点云 → 平面移除 → 欧式聚类 → 最近障碍 | `_get_obstacle_distance` 真值 + 噪声（D6） |
| 障碍速度 | 帧间差分 + 平滑 | 物理速度 + 噪声 |
| 相机布局 | 眼在手外固定安装 | MJCF `<camera name="eye_to_hand">`（同构位置/朝向/fovy） |

> D1 决策记录 §3 结论："对残差绕障需要的观测（obstacle_rel 相对位姿 + obstacle_vel 速度），
> 单深度相机原理上足够"。"只用深度相机"落地 = 对 obstacle_rel/vel 加噪声 + 漏检，
> 成功率下降 <10%（ROADMAP 验收线）。

## 3. 决策二：扩大现有桌面范围

### 3.1 现状与约束

- 桌面半边长 **0.24**（0.48m 见方），中心 (0.1, 0.42)，顶面 z=0.30。
- 历史教训（DEV_LOG 轮 9-B3）：半边长 0.45 时桌面伸到上臂活动区（y<0.14）
  → `upper_arm_link↔table` 接触产生 **356 N·m** 约束，把速度环压崩 → 缩至 0.24。
- workspace_bounds：X(-0.15, 0.1)、Y(0.32, 0.42)，受 IK 可达域约束。

### 3.2 决策（2026-08-28）

| 项 | 旧值 | 新值 | 说明 |
|---|---|---|---|
| 桌面半边长 | 0.24 | **0.35** | 0.70m 见方，更接近真实实验台 |
| 桌面中心 | (0.1, 0.42) | **(0.1, 0.53)** | 保持 Y 下界 = 0.18 ≥ 历史安全值，不碰下臂 |
| 桌面范围 | X[-0.14,0.34]×Y[0.18,0.66] | X[-0.25,0.45]×Y[0.18,0.88] | 顶面 z=0.30 不变 |
| workspace_bounds | X(-0.15,0.1) Y(0.32,0.42) | **X(-0.18,0.13) Y(0.26,0.42)** | 面积约 +90% |
| obstacle_wander_bounds | X(-0.18,0.15) Y(0.28,0.48) | **X(-0.22,0.18) Y(0.22,0.50)** | 随 workspace 同步扩大，仍在桌面内 |

> 物体/障碍放置范围必须 ⊆ 桌面范围，且物体范围在 IK 可达域内。

### 3.3 IK 可达性验证（从 home 位形 DLS-IK 打点）

| 范围 | 打点结果 |
|---|---|
| 现状 X(-0.15,0.1) Y(0.32,0.42) | 78 点 0 不可达（100%） |
| 扩大后 X(-0.18,0.13) Y(0.26,0.42) | 各子区域组合 100% 可达（详见 §6） |

> 关键：打点必须**每次把机械臂重置回 home 位形**再解 IK，否则 DLS 从上一收敛位形出发
> 会落局部极小造成大量假不可达（与 `verify_radius_006_reachability.py` 的做法一致）。

## 4. 决策三：眼在手外（eye-to-hand）相机布局

### 4.1 布局定义

```
相机 (0.1, 0.42, 1.20)  [固定，垂直向下看]
        │  fovy=60° / 640×480（相机参数见 config.GraspingConfig）
        ▼
工作区中心 (0.1, 0.42, 0.30) = cam_target
        │
   ┌────┴────┐ 桌面 (半边长 0.35, 中心 (0.1, 0.53), 顶面 z=0.30)
```

- **眼在手外**：相机固定在抓取工作区正上方，**不随机械臂运动**（区别于 eye-in-hand 装在手端）。
- MJCF 实现：`<camera name="eye_to_hand" mode="target" target="cam_target" ...>`，
  target 模式保证朝向始终对准工作区中心；`cam_target` 为不可见靶标 body。
- 对应部署侧 RealSense D435i 支架：眼在手外固定安装（俯视工作区）。

### 4.2 为什么选眼在手外（而非眼在手上）

| 维度 | 眼在手外（eye-to-hand） | 眼在手上（eye-in-hand） |
|---|---|---|
| 障碍观测 | 障碍始终在视野内，3D 定位稳定 | 障碍被末端遮挡，接近时反而丢失 |
| 标定 | 一次性手眼标定（固定外参） | 随关节运动外参变化，标定/补偿成本高 |
| 部署 | 支架固定，简单可靠 | 需挂载 + 线缆 + 标定板 |
| 对应训练 | MJCF 固定相机，与部署同构 | 相机随末端，渲染/特征需额外变换 |
| 结论 | ✅ 采用 | 单相机遮挡/视盲（D1 §3 工程边界），后续多视角补充 |

### 4.3 训练端渲染支持（本次落地）

`environment.py` 新增（感知 Phase 2 基础设施）：
- `get_depth_image()`：眼在手外深度图（米，float32 (H,W)），`depth_enabled=True` 时生效；
- `get_camera_image()`：RGB 图像（uint8 (H,W,3)）；
- `_get_offscreen_renderer(depth)`：惰性离屏渲染器（与 GUI renderer 分离，子进程内创建，
  云端需 `MUJOCO_GL=egl/osmesa`，失败降级 None，不影响训练）。

> 默认 `depth_enabled=False` → 训练零渲染开销；Phase 2 开启后可先做"渲染 → 提取降维特征"，
> 与部署侧点云管线（RANSAC → 欧式聚类 → 最近障碍距离/方向）同构。
