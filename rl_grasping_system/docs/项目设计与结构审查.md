> 审查对象：`rl_grasping_system/`（MuJoCo + Panda + PPO 抓取训练）。
> 日期：2026-08-19。本文件记录**结构性问题**、已修复项与**工程规范建议**，供后续迭代对照。
> 行为级 bug（奖励反向、量级失衡等）已在 `P1_奖励与收敛修复.md` 详细记录，此处只做结构层面总结。

## 1. 模块地图与职责

```
rl_grasping_system/
├── config.py               # 集中配置（GraspingConfig/NetworkConfig/TrainingConfig/RewardConfig/SystemConfig）
├── environment.py          # PandaGraspingEnv(gym.Env)：reset/step/渲染/奇异点/监控 全部耦合在这里
├── state.py                # 状态特征提取 get_proprioceptive_state + 近似物理特征
├── action_wrapper.py       # SafeActionWrapper：动作裁剪/奇异点回退/安全初始动作
├── singularity_handler.py  # 奇异点检测与渐进安全配置
├── reward.py               # 奖励函数（P1.3 势能塑形）+ 分量诊断
├── agent.py                # PPO 训练循环、模型存档、早停、EvaluatePolicy
├── training_monitor.py     # 训练期监控：TensorBoard/CSV/回调
├── train_with_monitor.py   # 本地训练入口
├── train_cloud.py          # 云端训练入口（EGL 后端、长训练）
├── evaluate.py             # 评估入口
├── vec_normalize_wrapper.py# VecNormalize 封装（P1 中已关闭奖励归一化，近乎死代码）
├── scripts/
│   ├── verify_p1_incremental_control.py  # P1 全量回归验证（11 组断言）
│   ├── diag_orientation_reward.py        # 方向奖励诊断
│   └── smoke_train_p1.py                 # 短训练冒烟
└── docs/                  # 迭代记录（P0-1/P0-2/P1）
```

依赖方向（理想为分层单向依赖）：`scripts → environment → {state, action_wrapper, singularity_handler, reward} → config`。

## 2. 结构性问题（按严重度）

### P0 级（已修复，本轮）
| 问题 | 修复 |
|---|---|
| `environment.py` 内部**硬编码写死 `MUJOCO_GL`**，无条件覆盖云端 EGL 设置，云端训练渲染必崩 | 移除内部写死；`train_cloud` 设 EGL、`train_with_monitor` `setdefault('glfw')` |
| 默认 `render_gui=True`，无人值守训练开 GUI 窗口 | 默认改 `False`（显式 `--gui` 开启） |
| 配置漂移：README 与代码不符（`total_timesteps=2000000` vs 实际 `50000`；`normalize_rewards=True` vs 实际 `False`；奖励权重 500/1000 vs 实际 5/10） | README 同步为真实值；`config.py` 删除从未消费的字段（`policy_activation`/`value_activation`/`eval_freq`/`log_freq`/`log_level`/`use_wandb`/`wandb_project`） |
| 源码残留**疑问式注释**（`#具体含义？data.ctrl是`、`#语法？`、`#什么意思？`） | 清理/改写为说明性注释 |

### P1 级（已修复，本轮）
| 问题 | 修复 |
|---|---|
| 死代码 ×3：`state.tendon_dynamics`（从未被调用）、`SafeActionWrapper.tendon_dynamics`（从未被调用）、`SingularityHandler.add_singularity_penalty`（从未被调用，且签名与 `calculate_reward` 不兼容） | 删除 |
| `agent.py` 从错误路径导入 `EvalCallback`（`from stable_baselines3.common.callbacks import ...` 试图导入不存在的类） | 修正为 `from sb3_contrib import EvalCallback` |
| `calculate_reward` 签名含从未使用的 `action` 参数，且用 `sum(values())` 求和把诊断键算进奖励 | 移除 `action` 参数；`REWARD_KEYS` 白名单 + 诊断键移入 `b['diag']`（详见 P1.3） |
| 子工程构建产物（`install/ log/ ros2_ws/ build/`）未忽略 | `.gitignore` 补 `install/ log/ ros2_ws/`（`build/` 已忽略） |

### P2 级（建议，未实施）
1. **`environment.step` 职责过载**：物理推进、奇异点处理、渲染、监控记录、奖励计算、终止判定全在一处，约 400 行。
   - 建议：保持现结构可运行，但把「奇异点处理」与「监控记录」抽成策略回调或独立组件，`step` 只做「动作→状态/奖励/terminated」。
2. **动作/观测契约是隐式 dict**：`safe_action` 依赖 `'joint_commands'`/`'tendon_command'`/`'gripper_command'` 三个键，无类型校验；`gripper_command` 在 MuJoCo `ctrl[7]` 上如何映射未写清。
   - 建议：定义 `ActionT` / `ObsT`（TypedDict 或 dataclass），并加 `assert`/`validate`。
3. **观测含冗余/近似特征**：手写 `calculate_finger_forces`、`calculate_tendon_tension`、可操作度等 53 维里存在近似项，网络 `[512,512,256]` 偏大。
   - 建议：做消融/特征精简，网络降到 `[256,128]` 对比。
4. **三个训练入口职责未收口**：`train_cloud` / `train_with_monitor` / `evaluate` 各有自己的入口逻辑，配置参数靠命令行复制。
   - 建议：统一到 `main()` + 单一 `--mode {train,eval,cloud}`。
5. **无自动化测试与 CI**：唯一“测试”是 `scripts/verify_p1_*.py` 手动跑。
   - 建议：把 verify 脚本收敛为 `pytest`（奖励纯函数可秒级断言；环境级用例标记 `@pytest.mark.slow`），并接 `.github/workflows/`。

## 4. 工程规范建议（可执行清单）

### 4.1 Git 提交
- 提交信息用 `[P0-2] env: 移除内部硬编码 MUJOCO_GL` 这类「前缀 + 模块 + 中文描述」；一次提交只改一个主题，避免把「删死代码」和「改奖励」混在一起。
- 二进制/日志/模型不进 git：`logs/ *.log models/*.zip cloud_training.log training.log`（模型建议存外部存储，git 里只放 `models/.gitkeep`）。

### 4.2 配置单一来源
- 现状已用 dataclass（好）；建议补 `config.to_dict()` + 每次训练把配置落盘为 `results/<run>/config.json`，保证「这个模型是用什么参数训出来的」可追溯。
- README 中任何配置示例必须与 `config.py` 同步，否则视为 bug（本次漂移即为此类）。

### 4.3 奖励与可复现性
- 奖励函数保持纯函数 + 显式 `REWARD_KEYS` 白名单（已做到）；任何新奖励键必须二选一：进白名单或进 `diag`，禁止 `sum(values())`。
- 仿真/训练确定性：固定 `seed`（已支持 `--seed`）；记录 MuJoCo/stable-baselines3 版本到配置。

### 4.4 验证脚本作为回归资产
- `scripts/verify_p1_incremental_control.py` 的 11 组断言是**纯奖励函数级回归**，应保留并在每次改动奖励/环境后运行（`python scripts/verify_p1_incremental_control.py`）。
- 新增奖励行为时必须先写断言，再实现（先红后绿）。

### 4.5 代码规范
- 注释只回答「为什么」，不写「是什么」（后者由命名承担）；禁止疑问式注释残留（`grep -rn '？' *.py scripts/*.py` 应为 0）。
- 公开函数给 docstring（参数/返回/单位），已在 `reward.py` 做到，其余模块逐步补齐。
- 删除前先 `grep -rn` 确认无调用点（本次三处死代码即按此清理）。

### 4.6 下一步路线（P2）
1. 特征精简 + 网络缩小，做消融。
2. 课程式训练（固定位置 → 随机位置），`workspace_bounds` 按可达性实测收紧。
3. 真·抓取判定（lift/搬运）进入 reward，替代 `grasp_success == is_grasped`。
4. 统一训练入口 + pytest 化 + CI。
