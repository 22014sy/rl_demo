# 2026-09-05 · 毕设方向决策：仿真主线 + 真机可选（残差架构两个任务族）

> 背景：聊完阶段 A/B 后，用户质疑"RL 残差做动态抓取避障对 MPC 没有明显优势"，
> 纠结 A=MPC+RL 动态避障 vs B=MoveIt+RL 接触插入(peg-in-hole) 哪个做毕设。
> 结论：仿真主线 + 真机可选 → **不二选一，一个架构 + 两个任务族**；真机只押 peg-in-hole。

---

## 1. 前提修正：RL 残差对 MPC 的优势在哪

n=30 三数表（阶段B §6）再解读：

| 场景 | 纯标称 | MPC | RL v23 | 碰撞率 |
|---|---|---|---|---|
| static | 83.3% | 93.3% | 96.7% | — |
| dyn_target | 66.7% | 80.0% | 83.3% | — |
| dyn_both(随机障碍) | 70.0% | 70.0% | **86.7%** | MPC **0%** / RL **16.7%** |

- RL 优势**真实但只有一格**（dyn_both +16.7pp；static/dyn_target 在 n=30 下不显著）；
- 优势**是用安全换的**（MPC 碰撞 0% vs RL 16.7%），真机上"高成功率+会撞"并不划算；
- **RL 赢的那一格 = 随机动态障碍 = 真机最贵的一格**（25~50Hz 实时 3D 跟踪随机移动障碍，
  无 motion capture 时是研究级难题）。

→ 用户直觉的准确表述：不是"RL 没优势"，而是"**RL 的优势区=真机部署的死亡区**"。
反观 peg-in-hole：RL 优势区（接触/力反馈）是**部署最便宜、sim2real 最鲁棒**的区。

## 2. 用户决策（2026-09-05）

**仿真主线设计，真机作为可选加分项。**

分支逻辑：
- 有真机毕设 → peg-in-hole 唯一现实（感知≈0，RTDE 力限幅即可安全）；
- 无真机毕设 → 动态避障 MPC+RL 反而更合适（热点、仿真里 oracle 感知可绕开）；
- 真机未定 → 按仿真主线设计，把两个任务族都做成章，真机押 peg-in-hole。

## 3. 推荐结构：一个架构 + 两个任务族

核心 claim（用自己的数据撑起，不押"RL 打败 MPC"）：

> 「标称控制 + RL 残差」分层架构：RL 不替代经典控制，而是把策略价值精准投放在
> 经典控制失败的区——动态避障（MPC 塌陷 70% → RL 86.7%）与接触插入（阻抗 76.7% → RL 100%）。

## 4. 真机可选章（章4）为什么便宜

- 感知≈0：孔板夹具固定 + 示教记录孔位（或相机拍一次），无动态跟踪；
- 规划：MoveIt 接近轨迹 / 残差标称层简单速度场；
- 控制：速度级 IK + UR speedJ（sim 已复刻），决策 25Hz，接触段降速；
- 安全：RTDE 读力矩估计，接触力超限即停（ISO/TS 15066 风格，答辩有故事）；
- 主风险：真实摩擦/间隙 vs MuJoCo，但接触任务反馈闭环可吸收，且复用 sim_to_real动力学匹配方案.md。
