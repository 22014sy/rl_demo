## 2. Q4：为什么 RL 不用经典关节 PID？（用户答案 + 讲解）

### 用户回答要点
- 经典 PID 是位置控制，项目是速度控制
- 与真机一致，sim2real 方便
- 疑惑①位置控制目标短期不变/频率；②实现率为什么差

### 讲解：疑惑点1（入口堵死）
- 位置 PID 输入 = q_des(t) 目标轨迹；RL 手里只有末端速度命令
- 转 q_des 需位置IK：迭代慢（5000次 0.84s/步 vs 决策 0.04s）、多解/奇异退化（tip 偏 12cm）、跳解抖动
- 速度链路绕开：速度IK 单步矩阵 ~2ms（ik.py:58-64）

### 讲解：疑惑点2（实现率差 10 倍的核心）
- 位置 PID：τ=Kp(q_des−q)−Kd·q̇，力矩∝位置误差。小增量→小误差→小力矩→先顶重力后≈0
- 铁证（environment.py:662-665）：纯 P 环大负载 ~18%，加惯性前馈 ~90%+
- 速度 PID：τ=Kp(q̇_des−q̇)+M_eff·q̈_des+qfrc_bias。前馈顶重力/惯性；力矩按速度差给（每秒的量，反应大）；速率积分语义，滞后不积累成位置误差
- 实测：Δp=0.02/T=0.04 脉冲实现率 96% vs 位置伺服 8-41%（config.py:23）
- 比喻：位置伺服=一步踩到3mm前，腿抬不动还被重力拽；速度伺服=告诉速度走，前馈帮扛背包

### Q4 完整答案（面试背诵）
> ① 入口堵死：位置伺服要 q_des，RL 只有速度命令；位置IK 慢/多解/奇异退化
> ② 实现率差10倍：位置环力矩按位置误差给小命令给不出大力矩（18%）；速度环前馈顶重力、力矩按速度差给（96%）
> ③ sim2real 同构：阻尼伪逆速度IK+速度PID = UR speedJ 语义，部署免改写

## 4. MPC 与阻抗控制深入（2026-09-01，基于真实代码讲解）

### MPC：有模型时的最优决策
- 原理：每决策步 预测N步→解带约束优化→只执行第1步→滚动
- 场景：有动力学模型的轨迹优化 / 带约束控制（限位/饱和/避障）/ 动态避障（学界2020+主流之一）/ 移动机器人
- 项目已有：`rl_grasping_system/scripts/mpc_ur5_grasp.py`（末端级 MPC，动态抓取避障，2026-09-02）：
  - 决策 u∈R^{N×3} 未来10步末端速度；预测 p_{k+1}=p_k+u_k·dt（单积分保实时）；成本=到达hover+障碍软约束+平滑+终端硬权重；SLSQP+warm-start+失败降级P；执行与RL同口径 env.step(Δ=v·T)
- 项目已有：`panda/mpc_improved.py`（关节级，线性化 q̈=τ−g−f，scipy，力矩限幅±30）
- 进一步改法：①模型升级（mj_forward 回放预测 vs 单积分）②最值钱：MPC 替代 MoveIt 当标称规划器 + RL 残差叠加（MPC+RL残差 = 学界动态避障主流组合）③硬约束避障

### 阻抗控制：接触时把机械臂变成弹簧
- 原理：F = k·(x_des−x) + d·(v_des−v)；k 大=刚（准但硬），k 小=柔（安全但精度差）→ 主动柔顺
- 场景：接触任务（peg-in-hole/组装/打磨）/ 人机协作安全 / 易碎抓取 / 拖动示教
- 项目已有：`rl_grasping_system/scripts/peg_baseline.py`（peg-in-hole 阻抗基线：阶段1 水平PID对齐 + 阶段2 恒速下压；±5cm扰动下 76.7% vs RL 100% = +23~27pp）；`panda/improved_task_space_control.py:146-162`（total= PID+阻抗 k=1000,d=100+重力+库仑摩擦）
- 进一步改法：①closing 阶段接阻抗（柔顺抓取防撞飞，见抓取冲击抑制方案.md）②最值钱：可变阻抗学习（RL 输出 目标位置+k+d，学「接近硬接触柔」）③peg-in-hole 加接触力惩罚奖励

### 决策框架（4 类 + RL 分层）
| 问题 | 用谁 | 项目对应 |
|---|---|---|
| 无接触/要最优/避障/有模型 | MPC | mpc_ur5_grasp.py |
| 有接触/要柔顺 | 阻抗 | peg_baseline.py |
| 轨迹已知/精确伺服 | PID/速度级联 | environment.py:640-671 |
| 无模型/高层任务/不确定性 | RL | 残差 PPO |

### 全栈面试叙事
> RL 学高层策略（抓哪）→ MPC 可做最优标称（往哪走/避障）→ 阻抗处理接触柔顺（碰到不坏）→ 速度级联做底层伺服（动得准）。四层 = 具身智能操作系统的完整控制栈。RL 不是替代传统控制，而是站在它们之上学决策。

### 用户现状
- 「怎么改才能用到」已解决 60%：MPC 对比 + 阻抗基线都有；剩 40% = 往分层集成走（MPC/阻抗当 RL 的标称层/执行层）

## 5. 追问：用 MPC 替代 MoveIt，真机就不用 MoveIt 了吗？（2026-09-01）

### 核心答案
- MoveIt 是「框架」不是「一个东西」：OMPL规划器 + FCL碰撞检测 + KDL/IKFast运动学 + ROS接口/Servo
- 换 MPC 只是换「规划器」这一格；碰撞/运动学/伺服照样要，但都有替代：

| 能力 | MoveIt 方式 | 不依赖 MoveIt 的方式 |
|---|---|---|
| 轨迹规划 | OMPL/RRT | MPC 滚动时域 / 几何速度场 |
| 碰撞检测 | FCL | 自写距离/几何体/实时感知 |
| 运动学 | KDL/IKFast | ikpy/解析/阻尼伪逆（ik.py） |
| 伺服接口 | MoveIt Servo | ur_rtde 直发 speedJ / ros2_control |

- 证据：nominal_trajectory.py:1-25 注释「MuJoCo 侧没有 MoveIt，用阻尼速度场当标称层替身，
  与真 MoveIt『IK解算→轨迹采样→Servo下发twist』语义对应」

### MPC vs MoveIt 区别
| | MoveIt(OMPL) | MPC |
|---|---|---|
| 规划 | 一次规划/低频重规划 | 每步滚动重解 |
| 环境 | 静态强项 | 动态强项 |
| 依赖 | 无动力学模型 | 需动力学+实时求解 |
| 代价 | 动态重规划频率跟不上 | 算力高/模型不准退化 |

### 关键洞察：RL 策略与标称层实现解耦
- v_servo = v_nominal(t) + Δv；RL 只依赖标称层接口，不关心它是 MoveIt/MPC/速度场
- 换标称层实现，RL 策略零改动 → sim2real 契约（RL_DEPLOY_CONTRACT.md）核心红利

### 面试话术
> 「真机不是用不用 MoveIt 的二选一。我的架构 RL 只对接标称层接口 v_nominal(t)，
> 静态用 MoveIt OMPL、动态可换 MPC 滚动时域（2026-09-02 已验证），换实现策略零改动——
> 这是『策略与底层解耦』的 sim2real 设计。」

## 6. 追问：MPC 能解决问题的话，RL 的意义是什么？（2026-09-01）

### 你自己的实验已经回答了（2026-09-02，n=30）
| 控制器 | static | dyn_target | dyn_both(随机障) | 碰撞率 |
|---|---|---|---|---|
| 纯标称 | 83.3% | 66.7% | 70.0% | 20.0% |
| MPC | 93.3% | 80.0% | **70.0%** | **0.0%** |
| RL 残差 v23 | 96.7% | 83.3% | **86.7%** | 16.7% |

- MPC 随机动态塌陷到 70%（=纯标称）：obs_k=obs+v·k·dt 对随机游走失效，靠大裕度保守绕行
  → 碰撞 0% 但成功率崩
- RL 靠经验学统计性规避 +16.7pp；可预测动态 MPC 不差（static 93.3% / dyn_target 80.0%）
- 结论：MPC 只在「模型可预测」时解决，模型失配时=纯标称；RL 的意义在「模型失配」这一格

### 两种建模方式
| | MPC | RL |
|---|---|---|
| 靠 | 显式模型+优化 | 隐式经验+数据 |
| 模型失配 | 塌陷（实验证明） | 统计性规避 |
| 成本/奖励难写 | 手调 W | 从回报学 |
| 接触/非平滑 | 模型建不出来 | 从接触样本学 |
| 可解释/实时 | 可证明安全/每步解优化 | 黑盒/前向推理快 |

### 最诚实答案（面试核心）
- 如果 MPC 真能解决，RL 就没意义——这是对的，且残差架构已接受：v_servo=v_nominal+Δv，
  MPC 完美则 Δv→0（静态场景残差极小=架构健康证据）
- 正确叙事不是「RL>MPC」而是「三数对比证明分工」：
  可预测环境 MPC 不差甚至更安全；随机动态 MPC 塌陷，RL +16.7pp →
  正确架构=标称(MPC/规划)+RL 残差，让 RL 只学模型失配部分

### 何时必须 RL（扩展弹药）
1. 模型不可得/失配（接触/摩擦/随机动态）
2. 成本函数写不出（语义决策无法量化成 W）
3. 感知→动作端到端（无人工特征）
4. 接触丰富操作（peg-in-hole RL 100% vs 阻抗 76.7%）

## 7. 深水三连问（2026-09-05）：速度IK vs 位置IK / 四元数 vs 欧拉角 / 3D vs 6D

### 7.1 ① 为什么用速度 IK 不用位置 IK（用户答 + 完整 6 条）

**用户答案**：速度 IK 直观反映到电机；位置 IK 增量小时映射不到电机、形成小扰动。

**点评**：命中 6 条里最关键的第 ④ 条（实现率）——这条正是训练真正卡住你的那条（8%→96%）。
但「直观反映到电机」措辞不精确，精确定量是「力矩按速度差给 vs 按位置误差给」；其余 5 条未答出。

| # | 原因 | 证据 |
|---|---|---|
| ① | 链路一致性：速度 IK 输出 dq 直接喂速度环；位置 IK 输出 q_target 属位置伺服链路 | environment.py:655-668 |
| ② | 实时性：速度 IK 单步矩阵运算 ~2ms；位置 IK 5000 次曾实测 0.84s/步卡仿真，修复 500+停滞退出后奇异/不可达仍退化 | ik.py:58-64 / 160-165 |
| ③ | 奇异鲁棒：阻尼伪逆 λ=0.08 压低奇异附近伪逆增益（等价实机奇异降速）；位置 IK 近奇异收敛慢/落局部极小（tip 偏 12cm） | ik.py:63-64 |
| ④ | 实现率/sim2real：速度模式 ~96% vs 位置模式 8%~41%；速度 IK 语义=MoveIt Servo twist/UR speedJ，部署免改写 | ★用户命中；RL_DEPLOY_CONTRACT.md:72 |
| ⑤ | 连续性：速度 IK 小增量局部线性化连续跟踪、无解分支跳变；位置 IK 多解分支相邻两步可跳解抖动 | v_max=0.125，每步 ≤5mm |
| ⑥ | RL 高频决策兼容：25Hz 决策 T=0.04s，位置 IK 迭代成本抖动不可控 | config.py T=0.04 |

> 面试一句话：速度 IK 不是位置 IK 的替代，是「速度伺服级联」链路里唯一自洽的一环
> （输出 dq 喂速度环、单步快、奇异鲁棒、96% 实现率、真机同语义）；位置 IK 属「位置伺服链路」，
> 主链路不用，只留给一次性求关节目标。

### 7.2 ② 四元数 vs 欧拉角（用户答 + 纠错）

**用户答案**：规避万向节死锁；四元数也比较直观、维度上表示方便。

**点评**：万向锁 ✅ 答对（头号理由）。但「四元数比较直观」❌ 说反了——四元数
（4 维 + 单位范数约束 + 双覆盖 q/−q）恰恰比欧拉角更不直观，欧拉角（roll/pitch/yaw）才是人类直观表示。
面试这么说等于反向暴露，必须改口。

**完整理由（四元数真正的优势）**：
1. 表示层无奇异（万向锁）：欧拉角 pitch=±90° 时 roll/yaw 退化成同一自由度 + 24 种约定歧义；
   四元数全局唯一（除 ±q 双覆盖，规范化 w≥0 消除）
2. 平滑插值：四元数 slerp 短弧插值；欧拉角插值在死锁附近剧烈翻滚、旋转方向歧义
3. 代数闭合：旋转组合=一次乘法、逆=共轭、旋转向量↔四元数半角公式（ik.py:68-105）
   → q_rel = q_target ⊗ q_ee⁻¹ 一次乘法（ik.py:184、environment.py:1446）
4. 紧凑 + 数值稳定：4 个数 vs 旋转矩阵 9 个，Shepperd 法鲁棒
5. 相对误差直读进观测：q_rel 4 维显式给策略对齐误差（P2-2），不用自己合成转角；欧拉角做差有符号/跳变歧义
6. 工程事实：MJCF 用 quat（models/universal_robots_ur5e/alignment_report.md:55-56）；ROS/UR/MuJoCo 现代机器人栈默认

> 注意区分：四元数消除的是**表示层奇异**（欧拉角死锁）；机械臂**运动学奇异**（肘伸直/腕奇异）
> 另由阻尼伪逆 + 可操作度观测 + singularity_handler 处理。

### 7.3 ③ 为什么 3D 位置 + 固定朝下（config.py:45）

**用户答案**：加姿态训练更困难；先固定朝下，后期随机物体时再变 6D。

**点评**：方向对（探索空间大→收敛难，是次因）；但漏了项目**最硬的实证**，
且「随机物体→6D」的触发器判断需要修正。

**完整理由**：
1. 硬实证（决定性依据）：6D 姿态维度 w_orient 时梯度为 0（diag 实证）→ 姿态维度无学习信号，
   6D 白耗样本（docs/简历项目知识整理.md:204）
2. 探索空间维度灾难：3D ≪ 6D 探索空间，收敛快（你的直觉，次因）
3. 任务归纳偏置：桌面顶抓姿态本就固定朝下（Q_APPROACH_DOWN=(0,1,0,0)，reward.py:50），
   姿态自由度对任务「多余」
4. 架构分工：姿态由 Q_APPROACH_DOWN 固定 + q_rel 观测显式给对齐误差（environment.py:1438-1446），
   不需要策略去学姿态
5. 触发器修正：「随机物体→6D」❌。正确触发条件 = 需要**侧向/多姿态抓取**
   （ROADMAP:82 代码已支持 action_space_dim 切换）。随机桌面抓取大多顶抓够用；
   且开 6D 会重遇 w_orient 梯度=0 旧坑，需姿态奖励塑形（≥2 周，一周冲刺方案.md:10）——不是简单换维度
