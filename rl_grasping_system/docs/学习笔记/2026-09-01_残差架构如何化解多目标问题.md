# 2026-09-01 · 残差架构如何化解多目标问题（用户质疑：残差不也是两个任务？）

> 起因：Q3 讲完端到端 4 类失败机制后，用户反问「残差修正不也是抓取+避障两个任务同时进行吗？问题到底解决没有？」
> 结论：残差架构不消灭多目标，而是把「平等竞争」改成「层次分工」——问题被转化，残留 trade-off 承认存在。

---

## 1. 核心回答：平等竞争 → 层次分工

```
端到端：  [一个网络]  ← 同时学 到达+抓取+避障，100% 参数共享、梯度打架
残差：    [MoveIt标称] ← 确定性规划器，负责接近+静态避障（算出来的，不用学）
          [PPO残差Δv]  ← 只学偏差：动态追踪/动态避让/精对准（单一主目标+局部修正）
```

- 静态避障从 RL 网络里**拿出去**（交给规划器）→ RL 不是两个任务，是「一个主任务+一个局部修正」

## 2. 逐机制对账表

| 端到端失败机制 | 残差架构化解方式 | 项目具体措施 |
|---|---|---|
| 奖励经济学 | 静态避障不用 RL 管→穿障诱惑消失；动态只剩局部冲突 | 碰撞惩罚 + v16「干净成功」bonus（environment.py:748-750） |
| 任务干扰 | 标称拿走大位移梯度→RL 只学小偏差 | 残差正则 residual_reg 0.5→1.5；30% 无障碍混合采样；课程 S0→S3 渐进 |
| 无信号 | 静态障碍由标称感知；RL 只感知动态障碍 | D1 观测预留 obstacle_rel/vel 槽位 |
| 探索压死 | 不需要「碰撞即失败」极端终止 | 默认 max_streak=0 禁用碰撞终止 |

## 3. 诚实承认残留 trade-off（面试加分）

- 证据：动态+障碍场景残差成功率 86.7% 但碰撞率仍有残余（4周计划 Week1：~80% 为 trade-off 残余）
- 话术：
> 「端到端的多目标问题是结构性的不可调，残差架构把它变成层次分工后残留的可控 trade-off。
> 动态+障碍仍有权衡，但 86.7% vs 43.3% 的差距证明任务分解先把死结解开，
> 剩下的权衡是工程可接受的。」

## 4. 面试第二层追问模板

被问「残差不也是多任务吗」：
1. 先承认表面相似（诚实）
2. 指出本质区别：静态避障移出网络，交给确定性规划器
3. 给对症措施：残差正则/混合采样/课程/干净成功 bonus
4. 承认残余 trade-off + 用消融数字收尾（86.7% vs 43.3%）
