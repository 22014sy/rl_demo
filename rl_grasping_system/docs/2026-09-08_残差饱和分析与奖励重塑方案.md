# 残差饱和分析与奖励重塑方案（Stage 2 后置；v25 训练依据）

> 日期：2026-09-08（v24 评估 2026-09-07 复盘后定稿）
> 关联：`docs/2026-09-07_Stage2_MPC+RL残差训练与评估.md`（Stage 2 主文档，v24 结果与 §4.4 引用本文）
> 结论一句话：**v24 的失败不是「MPC+RL 架构不可行」，而是「残差饱和 + 无稀疏激励」的优化病**；v25 用「残差预算与 MPC 解耦 + L1 稀疏三件套 + 高密度场景课程」三路修复，并按 Go/No-Go 判定线定性。

## 1. 失败归因：证据链（n=30，2026-09-07 评估）

| 场景 | 纯 MPC（复测/存档） | MPC+RL（v24） | 质变 |
|---|---|---|---|
| mixed3 | 13.3% / coll 33.3%，avg_coll **0.9**，失败全部 coll=0（够不到） | 0% / coll **86.7%**，avg_coll **40.0**，单集最高 74 次碰撞 | 安全失败→碰撞爆炸 |
| mixed_z | 13.3% / coll 13.3%，avg_coll **0.23**，成功干净 | 13.3% / coll **80.0%**，avg_coll **25.6**，成功样本也带 6~14 次碰撞 | 成功率持平但安全属性崩塌 |
| dyn_target | 83.3%（同脚本复测） | 73.3% | 残差无正贡献、轻微干扰 |
| static3 | 0% | 0% | 场景超出 MPC 标称能力，残差也救不了 |
| static | 96.7% / 0 coll | 96.7% / 0 coll | 持平 |
| dyn_both | 90.0% / 0 coll（复测） | 86.7% / 3.3% coll | 持平（CI 内） |

残差幅度观测（v24）：`avg_residual_norm` **全场景恒 ≈0.2165**，恰等于 clip 上界
（`max_ee_delta/T=0.125` m/s 逐维 ×3 轴 → 欧氏范数上界 `√3×0.125=0.2165`）。

---

## 2. 根因链（自上而下）

1. **残差输出饱和（现象）**：策略学到的是「恒定满偏置向量」而非「状态→修正量」映射。
   `avg_residual_norm ≡ 0.2165` 全场景恒定、各 episode 恒定，无状态自适应。
2. **饱和是当前奖励下的最优解（原因）**：残差正则项数值上被任务奖励淹没
   （v24 满幅残差 L2 惩罚仅 ~0.094/步 ≈ 18.7/200步，成功 +130）→ PPO 的 tanh 高斯策略
   在 Q 梯度指向边界时自然停在 clip 处。**这是优化问题，不是任务奖励形状缺陷。**
3. **对 MPC 的破坏机制**：残差预算（±0.125）与 MPC `v_max=0.125` **同级**，
   满偏置可完全覆盖 MPC 刚算出的安全速度方向；SLSQP 每步重算也追不回 → 反复碰撞。
4. **训练/评估分布不匹配**：训练 mix（0.2 静态/0.3 动态目标/0.5 动态+1障碍）无高密度障碍
   → static3/mixed3/mixed_z 是零样本分布外硬扛。

> 注：v24 从 v23（velocity_field 标称）热启动继承了「满幅残差」习惯，属次要诱因
> （热启动不是根因——即便从零训练，在无稀疏激励的奖励下 PPO 仍会收敛到满幅残差）。

## 3. 当前奖励结构（v24 实际生效）

`reward.py` 组件（训练 CLI 可覆盖权重；P1.3 势能塑形：r_shape = Φ(s₋₁) − γ·Φ(s)）：

| 键 | 公式 | config 默认 | v24 实际 | 量级 |
|---|---|---|---|---|
| r_dist_xy | Φ_xy 势能差（w_xy·min(d,0.6)/0.3 + 锚定） | w_xy=2 | 同 | 塑形 ±2/步，相消有界 |
| r_dist_z | Φ_z 势能差（w_h·min(dz,0.3)/0.3 + 锚定） | w_h=8 | 同 | 同上 |
| r_orient | w_orient·(−z_axis_z) | 0（3D 动作关闭） | 同 | 0 |
| r_contact | 接触力≥0.1N 电平 +5 | 5 | 同 | 事件 |
| r_close | closing 上升沿 +5 | 5 | 同 | 里程碑 |
| r_grasp | grasp 上升沿 +100 | 100 | 同 | 主事件 |
| r_success | 0（已并入 grasp） | 0 | 同 | — |
| r_obstacle | −w·max(0, 1−d/0.15) | 1 | **3** | 贴障时 −3/步 |
| r_residual | −residual_reg_w·‖Δv‖² | 0.5 | **2.0** | 满幅仅 −0.094/步 ⚠️ |
| r_avoid | 成功且全程 0 碰撞 +bonus | 0 | **30** | +30 |
| r_step | −0.05/步 | 0.05 | 同 | 200 步 −10 |
| r_collision（env 层） | 碰撞当步 −10 | 0 | **−10** | 10 次碰撞≈抵消 1 次成功 |

**经济学账（根因 2 的数值支撑）**：
- 满幅残差成本：200 步 × 0.094 = **18.7**；成功收益：+100 + 30 = **+130** → 满幅残差「几乎免费」。
- collision_penalty −10/次：穿障成功（≤10 次碰撞）仍净赚 → 碰撞经济学也没拦住硬闯。

## 4. v25 修复方案（本文件交付的代码改动，已实现）

### 4.1 残差预算与 MPC 可行域解耦（action space，强制安全）
- 三轴 clip `±0.005`（Δv=0.125 m/s）→ **`±0.002`**（Δv=0.05 m/s，`config.grasping.residual_delta_cap`，MPC v_max 的 40%）。
- 残差只能是「微调」（0.5s 内 ~2.5cm 修正量），不能「覆盖」MPC 安全速度方向。
- 即使未来再次饱和，对 MPC 标称的扰动也在安全裕度内。
- delta 模式不受影响（仍用 max_ee_delta），旧模型/旧语义零回归。

### 4.2 残差稀疏三件套（reward 层，经济学治本）
```
r_residual = −residual_reg_w·‖Δv‖₂²          (L2，保留旧语义，v25 用 2.0)
           − residual_l1_w·‖Δv‖₁             (L1，v25 用 2.0：满幅 3 轴 0.15 → −0.3/步 → 200 步 ≈ −60，与成功同级)
           − residual_step_w·𝟙[‖Δv‖>τ]       (激活硬门控，v25 用 1.0、τ=0.02：持续出手再罚)
```
- 让「常态零残差」成为最优，残差只在收益超过 ~0.35/步 的代价时出手。

### 4.3 残差引起的碰撞双倍罚（§4.5 条）
- `collision 且 ‖Δv‖>τ(=0.02)` → 在 obstacle_collision_penalty(−10) 之外再叠 −10（`residual_collision_penalty_extra`）。
- 让策略学到「不确定时别碰 MPC 标称」，直接对应 dyn_target 的轻微干扰。

### 4.4 高密度场景课程（数据层）
- `--scenario-mix` 扩展为 **5 场景**（旧 3 值兼容）：静态无障 / 动态目标 / 动态+1障碍 / **static3（3 静态 on-path 墙）** / **mixed3（3 动态 on-path 墙）**。
- v25 用 `0.2,0.2,0.35,0.12,0.13`：~25% episode 落在高密度障碍，残差不再零样本硬扛。

### 4.5 不采纳项（记录理由）
- 纯任务奖励微调（contact/close/grasp 数值）——饱和根因在残差代价结构，不在任务奖励形状，改任务奖励治不了根因 2。
- 架构级门控（`Δv=gate(s)·π(s)`，仅在 MPC 预测碰撞/不可行时激活）——改动面大、引入「什么算关键帧」的判别误差；先用 4.1+4.2 出 v25 看效果，若仍不收敛再上。

## 5. 预期指标与判定线（v25 达标线）

| 指标 | 期望 | 判定 |
|---|---|---|
| avg_residual_norm | **双峰：常态 ≈0，偶发尖峰 ≤0.0866**（v24 恒 0.2165） | 分布形态 + 均值 < 0.05 |
| mixed3 / mixed_z 成功率 | ≥ 13.3%（纯 MPC 水平）且 coll ≤ 15% | 关键：安全属性不得劣于纯 MPC |
| dyn_target | ≥ 83.3%（= 纯 MPC 复测） | 残差不干扰 |
| dyn_both | ≥ 86.7%（≥ v24） | 保持 |
| static / static3 | static ≥96.7%；static3 尽力上探（>0% 即可记为正增益） | 残差不得拖累 |

## 6. Go / No-Go 判定（本阶段定性标准，防无限调参）

- **Go（继续 Stage 3）**：混合场景 coll 回落到 ≤ 纯 MPC 水平（≤15%），且至少一个 MPC 硬伤场景
  出现真实残差增益（static3 >0% 或 mixed_z coll 明显 <13.3%）→ 残差有「纯 MPC 给不了的增量」，值得再精调。
- **No-Go（收尾定性）**：修了饱和后残差仍无增益/训练不稳 → 结论「末端速度残差叠加在 MPC 标称上，在本任务不成立」，
  把 v24 定档为架构对照终点，主方向转向纯 MPC 工程化（或回 ROADMAP Phase 4 原设计的 MoveIt2 标称 + 残差）。

## 7. 消融矩阵（v25 达标后可选，v25 未达标时不展开）

| 变体 | 变量 | 回答的问题 |
|---|---|---|
| v25a | cap=0.002 → 0.001 | 残差预算再减半，微调上限 |
| v25b | L1 2.0 → 4.0 | 稀疏压力加大后成功率掉不掉 |
| v25c | 关 step 罚（只留 L1） | 硬门控是否必要 |
| v25d | 3 障碍 mix 移除 | static3/mixed3 增益是否训练课程的贡献 |

## 8. 本次代码改动清单（2026-09-08 提交）

- `config.py`：`GraspingConfig.residual_delta_cap`(0.002)；`RewardConfig.residual_l1_w / residual_step_w / residual_step_threshold / residual_collision_threshold / residual_collision_penalty_extra`（默认全 0 关闭，旧行为零回归）。
- `reward.py`：REWARD_KEYS 加 `r_residual_step`；`r_residual` = L2+L1；新增激活步罚；diag 加 residual_l1。
- `environment.py`：residual 分支独立 clip（cap 解耦）；grasp_info 传 `residual_l1`；残差碰撞双倍罚；scenario_mix 扩展 5 场景 + per-episode 障碍数量/速度 override。
- `train_with_monitor.py`：新增 `--residual-l1-w / --residual-step-w / --residual-step-threshold / --residual-delta-cap / --residual-collision-threshold / --residual-collision-penalty-extra`；`--scenario-mix` 支持 3 或 5 值。
