# Sim-to-Real 实现率不匹配（"全速实现率低→部署电机输出不匹配"）分析与动力学匹配方案

> 2026-08-21 · 训练侧（rl_grasping_system）速度实现率低导致的训练-部署动力学不匹配
> 关联：`environment.py`（接近限速/动作平滑）、`config.py`（max_ee_delta/平滑α）、`docs/RL_DEPLOY_CONTRACT.md §2/§4

## 1. 用户判断（正确）与诊断

用户：全速实现率低会导致部署侧和训练侧电机输出速度不匹配吧？

诊断（当前代码，seed 42，home 起点 +x 移动 20 决策步）：
```
dp=0.02 (v=0.50): 实现 5%
dp=0.01 (v=0.25): 10%
dp=0.005 (v=0.12): 14%
dp=0.0025 (v=0.06): 14%
```
→ **训练侧所有速度实现率仅 5-14%**；部署侧 UR5e `speedJ`/`forward_velocity_controller` 同速可接近 100%。
同一策略动作，实机位移比训练侧大一个量级 → 实机"超调/冲过头"、接近/抓取行为失真。**确认：sim-to-real 动力学不匹配**。

## 2. 根因（两层叠加）

1. **接近限速阈值过宽（主因）**：`gripper_close_distance=0.18` 判据用 base_mount→cube 距离，而
   home 位形该距离 = 0.17 < 0.18 → 限速**几乎全程触发**（v 截到 0.12），扭曲 `max_ee_delta=0.02`(v=0.5) 的语义。
2. **B 平滑 α=0.3 过度**：一阶低通使速度目标从 0 缓慢爬升，速度环每步追变化目标 → 稳态实现率大幅下降。

## 3. 业界做法（动力学匹配三原则）

| 原则 | 做法 |
|---|---|
| ① 动作空间标定到"两端都可靠实现"的速度区 | 训练侧速度环可靠区（v≤0.125 曾达 96%）作为 v_max；部署侧同速限幅（UR 安全限速） |
| ② 控制语义对齐 | 策略输出 Δp/决策周期，两端都以"该周期内实现 Δp"为准（训练侧速度环、部署侧 Servo+限速） |
| ③ 域随机化（进阶） | 训练时随机化实现率/延迟，策略对动力学不确定性鲁棒 |

## 4. 修复方案

1. **收窄接近限速触发区**：判据改用 **pad→cube 距离**、阈值 `approach_speed_dist=0.06`
   （仅抓取最后一段限速，正常运动不限）→ 恢复可靠区实现率
2. **平滑 α 调大**：`action_smoothing_alpha 0.3 → 0.7`（仍滤跳变，速度目标快速建立）
3. **max_ee_delta 标定**：`0.02 → 0.005`（v_max=0.125，训练+部署两端一致；符合 UR 抓取接近速度 ~0.1 实践）
4. **契约 §2/§4**：明确"动作上限 = 两端一致可实现的 v_max=0.125 m/s"，记录本次教训

## 5. 实施要点

1. `config.py`：`max_ee_delta=0.005`、`action_smoothing_alpha=0.7`、新增 `approach_speed_dist=0.06`
2. `environment.py`：接近限速判据改用 pad 中心→cube 距离，阈值 `approach_speed_dist`
3. 验证：dp=0.005（v=0.125）实现率应恢复到 ~90%+；e2e 抓取抬升仍成功
4. 契约 §2/§4 更新 v_max 与动作语义

## 6. 实施结果与根因深挖（2026-08-21）

### 已实施
- `config.py`：`max_ee_delta 0.02→0.005`（v_max=0.125）、`action_smoothing_alpha 0.3→0.7`、新增 `approach_speed_dist=0.06`
- `environment.py`：接近限速改用 pad→cube 距离、阈值 approach_speed_dist（不再被 home 位形全程触发）

### 验证数据（修复后）
```
dp=0.005 (v=0.125): 20步实现 20%   # 修复前 14%，仅略升
dp=0.0025 (v=0.062): 22%
e2e success: True | cube z: 0.505 | steps: 131
```

### 根因深挖（关键）
**手动物理循环（无 env 包装、v=0.125 恒速）400 物理步：x 位移 0.0921 / 理论 0.1 = 92.1%**
（理论 = v×t = 0.125×0.8s = 0.1m；此前误算为 /0.5 得出 18%，实为 92%）
→ **速度环本身实现率正常（92%）**，velocity_ik 阻尼伪逆 lam=0.08 产生 95% 末端速度（J·dq=0.118/0.125）。

### 真正的根因：状态机"假成功"（已修复）
env 里 dp=0.005 20 步仅 20% 的**真相**：i=9 起 `v_smooth=[0,0,0.075]`（lift 竖直速度）——
- home 位形 pad 悬于 cube 上方仅 **0.034m**，base_mount→cube 距离 **0.168 < close_distance(0.18)**
- → reset 后立即触发 closing → 手指闭合碰 cube 顶被误判"抓住" → **lift 提前启动** → arm 停止横向移动
- **修复**：`_update_gripper_state` 的 open→closing 增加 **pad 高度对齐校验**
  （pad 中心 z 与 cube 中心差 < 0.03 才允许闭合）——pad 须下探到 cube 高度才闭合

### 最终验证（修复后）
```
env dp=0.005 (v=0.125) 20步: x 位移 0.0871 / 0.1 = 87.1%    # 之前 20%（lift 提前假象）
e2e success: True | cube z: 0.505 | steps: 150 | phase: closed
```
- 速度环实现率 ~87-92%（正常，与实机一致）
- e2e 需 pad 先下探到 cube 高度再闭合（150 步，合理）

### 结论修正
- **sim-to-real 不匹配的"实现率低"是误判**：速度环 92% 正常；真正 bug 是状态机假成功（已修复）
- 保留加速度前馈（M_eff·d(dq)/dt，匹配实机 UR 速度环前馈）+ 粘性阻尼 + 动作平滑
- 部署侧注意：UR 速度环自带前馈；训练侧现已对齐
