## 1. 决策 1：用不用真 MoveIt2？→ 维持「标称仿真替身」路线

- 真 MoveIt2 代码存在（`../ros2_moveit2_ur5e_grasp`，ROS2 Humble + MoveIt2 + OctoMap + 视觉）。
- 但本周（纯仿真、1 周、投实习）训练阶段有意用 `nominal_trajectory.py` 速度场替身：
  1. 真 MoveIt 在 ROS2/Docker，接入 MuJoCo 训练循环 = 每决策步 OMPL 规划 + ROS2 桥 + 时延同步，
     1 周内集成风险高，且挤占 D2-D5 训练时间。
  2. 替身精确复刻接口契约：真 MoveIt「对当前估计目标位置 OMPL 规划 → Servo 下发 twist v_nominal(t)」；
     替身「v_nominal = clamp(gain·(hover−ee), v_max)」输出同构 6 维 twist。
  3. 替身天然支持动态目标（L2 target_pos 变化自动跟踪），真 MoveIt 动态跟踪是弱项。
- 结论：真 MoveIt 留部署/sim2real 阶段；本周纯仿真替身训练。

## 2. 决策 2：替身能无痛替换成真 MoveIt2 吗？

结论：**RL 训练侧无痛（替换点收敛到一处）；真 MoveIt 侧替换有成本，但解耦于 RL 侧。**

- 唯一替换点：`environment.py` step 471-474 `self.nominal_trajectory.reference_velocity(ee_pos, target_pos, T)`。
  换真 MoveIt = 换成「从 MoveIt 轨迹按时间 t 采样 v_nominal(t)」的桥；策略/观测槽位/动作叠加全不动。
- 无痛成立需满足 4 个契约：
  1. **坐标系**：替身是世界系 twist；真 MoveIt Servo 需 `command_in_type='twist'`（世界/base 系），或桥内转换。
  2. **v_nominal 分布**：替身直线阻尼 ≤0.12；真 MoveIt OMPL 轨迹有拐点/加速度 profile → 替换后需短 fine-tune 适配。
  3. **更新频率**：训练 50Hz 决策读一次；桥按轨迹时间戳 t 采样，不每步重规划。
  4. **ROS2 侧现状**：`../ros2_moveit2_ur5e_grasp` 目前是 Plan&Execute + OctoMap，**还没有 Servo/twist 轨迹下发**
     （混合架构设计文档 Phase 3「gym→ROS2 桥节点」待实现）。
- 建议 D6 加低成本验证：MuJoCo 内「轨迹采样版替身」（从预生成 Cartesian 轨迹按 t 采样 twist 替换
  reference_velocity），跑 check_d1 证明替换点干净（半天）。

## 3. 决策 3：感知动态障碍只用深度相机够吗？

结论：**对残差绕障需要的观测（obstacle_rel 相对位姿 + obstacle_vel 速度），单深度相机原理上足够
——这是 `混合控制架构设计.md` §5.1 的既定设计，不是权宜。**

- §5.1 原话：「深度图不进全分辨率（训练慢），用**降维特征（最近障碍距离 + 方向向量）**优先，CNN 编码器作为后续增强」。
- 深度相机直接提供：障碍 3D 位置（点云→RANSAC 去桌面→欧式聚类，ROS2 `point_cloud_processor.py` + §4.1 流水线）、
  速度（帧间差分+平滑）、相对末端位姿。
- 三个工程边界（非原理障碍）：
  1. **遮挡/视野盲区**：单相机单视角，机械臂/目标/桌面会挡障碍 → 漏检（D6 做随机漏检测试；真机多视角）。
  2. **速度是推算不是量测**：帧间差分+滤波，噪声大于位置，快速障碍滞后。
  3. **深度相机物理限制**：反光/透明/黑色材质（真机才面对，仿真不涉及）。
- 当前训练侧是 oracle（`_get_obstacle_position`/`_get_obstacle_velocity` 直接读 MuJoCo 物理量）。
  「只用深度相机」落地 = D6 对 obstacle_rel/vel 加噪声 + 漏检验证成功率下降 <10%（ROADMAP 验收线）。

## 3.5 决策 1 补充条款：静态/动态避障与 RL 残差的分工（2026-08-24 确认）

以下条款补充进「决策 1」（训练侧替身 / 部署侧真 MoveIt 的分工），明确避障责任的归属，防止后续实现跑偏：

1. **静态避障时 RL 仍在线输出，但不是"模式切换"**：残差策略恒在、恒输出；静态障碍时
   标称直冲路径被挡，RL 输出非零残差 Δv 绕开；静态世界、无障碍时 Δv≈0。
2. **残差是直接叠加，不是"做差"**：`v = v_nominal + Δv`（残差增量叠加到标称参考速度），
   不是「RL 输出与 MoveIt 输出求差」。
3. **训练标称替身不带绕障是刻意设计**：替身（`nominal_trajectory.py` 阻尼速度场）直冲目标、不绕障——
   L1 静态障碍绕障必须由 RL 残差学出来（D2 训练主线）；部署侧静态避障由 MoveIt 规划承担
   （OMPL + planning scene 碰撞体），动态避障/动态抓取由 RL 残差承担。
4. **D6「轨迹采样版替身」≠ 让训练标称绕障**：D6 用预生成 Cartesian 轨迹替换速度场替身，
   只验证「替换点干净」（策略/观测/叠加全不动、成功率不塌），训练侧标称依然直冲。
5. **分工的验证证据 = 残差幅度统计**：静态小 / 动态大（架构分工成立的硬数据，一周冲刺方案 §5 验收线）；
   D2 起在奖励中加入残差幅度正则 `r_residual = -w·‖Δv‖²`，主动把"静态无谓修正"压下去，让统计更有说服力。

## 3.6 决策补充：为什么不拆成"避障模型 + 抓取模型"（2026-08-25 讨论确认）

> 针对"给定轨迹只要学绕障碍就好 / 要不要把避障与抓取分开"的讨论结论，防止后续实现跑偏。

1. **「RL 只学绕障、抓取交给标称/别的」不成立——绕障和抓取不是正交子任务**：绕障的终点必须精确
   落在抓取路径（pre-grasp）上；若策略只管"远离障碍"，会绕到安全区但回不到目标。策略必须同时
   看到 `object` 信息并被 `r_grasp` 驱动——成功 episode 实测 `r_obstacle -16 + r_grasp +100` 同时出现
   （绕障的同时在逼近目标），"绕障是手段、抓取是目的"，割裂即失去锚点。
2. **「让标称替身会绕障、RL 只补残差」违背 §3.5-3 分工**：训练侧替身（`nominal_trajectory.py` 阻尼
   速度场）直冲、无规划器是刻意设计；若训练侧标称绕障，RL 永远见不到"标称没绕好 / 障碍突现来不及
   重规划"→ 动态绕障能力学不出来。真 MoveIt 的 OMPL 绕障只属于部署侧。
3. **不搞两个模型/级联（避障策略 + 抓取策略）**：与 §3.5-1（残差恒在、非模式切换）冲突——级联即
   切模式；且有误差累积 + 协调边界问题（绕障策略不知抓取约束、绕太远抓取策略挽回不了）+ 两套训练成本。
4. **「只学绕障修正」在残差架构里已成立、但不能孤立**：RL 本就不学规划，只输出 Δv；静态场景下 Δv
   的职责主要就是绕障修正。但它必须**内嵌在抓取闭环里学**（同时看目标锚点），不能孤立成"避开障碍"
   的独立动作。
5. **何时才值得拆（触发条件，当前未出现）**：任务复杂到单策略学不动（多障碍 / 长 horizon /
   强时序耦合）、或需要技能复用（绕障独立可移植到别的任务）。当前静态单障碍、单策略收敛段成功率
   69% 且在上升，拆是过度设计。
6. **现有"分阶段"形态**：同一权重延续（stage2_d1 无障抓取 → D3 有障绕障 warm-start），
   **分阶段、不分模型** = 正确的课程化；后续若冲不动 70% 再考虑模块化。

### 冒烟实测发现的 bug 与修复：optimizer state 维度（55 vs 67）

- **现象**：首轮冒烟 rollout 正常（80.8%），首次 `optimizer.step()` 崩溃
  `RuntimeError: tensor a (55) vs tensor b (67)`。
- **根因**：SB3 2.9.0 `PPO.save` 把 optimizer state（Adam `exp_avg/exp_avg_sq`，形状随输入层为 55）写入 zip；
  运行时 `PPO.load(env=67 维)` 重建 67 维参数却加载 55 维 state → 维度不匹配。
- **修复**（`migrate_d1_checkpoint.py`）：改完输入层后重建 optimizer
  `pol.optimizer = pol.optimizer_class(pol.parameters(), lr=1.0, **pol.optimizer_kwargs)`，
  丢弃旧 55 维 state、新 67 维参数冷启动（新 12 槽位无历史动量，等价）。实测 `optimizer.step()` OK。
- 已重跑 `--verify`：仍 0.000e+00 一致。
