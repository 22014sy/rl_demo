# P1 奖励与收敛修复（动作管线 / 奖励重写 / 成功判定 / 指标管线）

> 前置：P0-1（物理可行性）、P0-2（物体位置随机化 + seed 可复现）。
> 本文档记录 P1 的 4 项修复、验证结果，并附**设计问题 / 结构问题分析**与**工程规范建议**。

---

## 一、背景：为什么训练不收敛（根因）

50k 步训练日志的关键现象：`singularity_joint3` 警告每 ~10s 一次、成功率恒为 0、episode 步数恒 =100、奖励在 [-1,2] 内无趋势。逐项排查得到 4 个根因：

| # | 根因 | 后果 |
|---|------|------|
| 1 | **动作→执行器映射错误**：`panda.xml` 的 actuator1-7 是位置伺服（`biastype="affine" gainprm=4500`，即 `ctrl`=目标位置），但 `action_wrapper.apply()` 把动作当**速度**用（`当前速度 + clip(raw−当前速度, ±0.005)`），`step()` 再把它写进 `ctrl[:7]` → 手臂被命令向 q≈0 的塌缩位形，策略意图被抹掉 | `singularity_joint3` 警告频发、手臂几乎不可控 |
| 2 | **奖励几乎没有任务信号**：只生效位置项，且目标=物体中心 `(0.5,0,0.02)`，而 `ee_position` 是 hand 基座（最小 z≈0.06-0.10，物理上到不了物体中心）→ 奖励饱和在 ≈-0.6，对“最后对准→抓取”无梯度；无夹爪闭合信号，`is_grasped` 永不触发 | 奖励饱和、成功率 0 |
| 3 | **成功判定 / 预算**：`max_steps=100` 过短；夹爪闭合阈值下 `gripper_width` 语义、手指 qpos 方向/范围未核验 | episode 全超时 |
| 4 | **指标管线断裂**：`GraspingCallback` 读 `env.task_state`（SB3 `Monitor` 上不存在）；`TrainingMonitor` 从未被挂到真实环境 → JSON `episodes` 恒空，训练过程不可见 | 无法观测训练是否在学 |

另外发现一个隐藏问题：`config.py` 声明了 `control_freq=50`，但 `environment.py` **从未消费**它——每个 env 动作只跑 1 个 `mj_step`（2ms），位置伺服在一个控制周期内几乎不动（实测 0.02 rad 命令仅推进 0.0006 rad），手臂在预算内根本走不完。这也是 P1-1 一并修复的。

## 二、P1 改动明细

### 1. `config.py`

- `GraspingConfig.max_steps`：`100 → 300`（增量控制下给足行程）。
- `GraspingConfig.max_joint_delta = 0.05`（新增）：动作空间前 7 维的每步关节增量上限（rad）。
- `GraspingConfig.control_freq = 50`：注释更新——现在真正生效（子步进）。
- `TrainingConfig.normalize_rewards = False`：关闭奖励归一化。早期奖励接近常量、方差≈0，除小方差会把奖励放大到 ±10 以上导致不稳定；新奖励本身在 [-3,10] 有界，交给 PPO 优势归一化。
- `RewardConfig` 整体重写（见 §2）。

### 2. `reward.py` — P1-2 奖励重写

新签名：`calculate_reward(state, prev_state, action, grasp_info, reward_config=None)`。

关键点：**位置目标改为 pre-grasp 位姿** `obj + [0,0,0.10]`（hand 基座物理可达，消除饱和）。

```
r_dist   = -w_xy    * min(d_xy / xy_scale, 1)     # w_xy=1,   xy_scale=0.3
r_height = -w_height* min(dz / height_scale, 1)   # w_height=2, height_scale=0.15
r_orient = +w_orient* max(0, dot(ee_z_axis, world_z))  # w_orient=0.5，手指朝下
r_contact= +w_contact                             # 手指真实接触物体（法向力≥0.1N）
r_grasp  = +5.0      # is_grasped：到位+夹紧+接触
r_success= +10.0     # grasp_success（P1 中与 is_grasped 相同，见 §2.5）
r_step   = -0.01     # 轻时间惩罚
```

- `ee_orientation` 现在是**真实四元数**（`data.xquat[hand]`），方向奖励不再是常量（见 §3 `state.py`）。
- `contact_force` 来自真实物理接触（`data.efc_force[c.efc_address]` 法向力），不是旧的“肌腱张力启发式”。

### 3. `state.py` — 观测/状态正确性修复

- **肌腱位置/速度**：此前 `data.qpos[7]`/`data.qvel[7]` 在物体加 freejoint 后是**物体 freejoint 的 qpos/qvel**（索引全错）。改为 `model.jnt_qposadr/jnt_dofadr` 索引 finger 关节。
- **末端方向/速度**：此前硬编码默认四元数 `[1,0,0,0]` 和零速度 → 方向奖励恒为常量、观测无信息。改为 `data.xquat[hand]` / `data.cvel[hand]`。
- `gripper_state = tendon_position`（0=闭合, 0.04=全开），不再从错误的 `qpos[8]` 取。

### 4. `action_wrapper.py` — P1-1 增量式位置控制

- 动作前 7 维 = **每步关节增量**（rad），第 8 维 = 肌腱命令（0=闭合, 1=张开）。
- `apply()`：`joint_deltas = clip(raw[:7], ±max_joint_delta)` → 奇异点降速（在增量上缩放）→ `target_q = clip(当前qpos + 增量, 关节限位)` → 返回 `joint_commands`=**目标位置**（写 `ctrl[:7]`）。
- **删除**旧的速度积分（`当前速度 ± clip(..., ±0.005)`）与关节限位“预测”逻辑。
- `get_safe_initial_action()`：零增量（保持位形）+ 肌腱半开。

### 5. `environment.py` — P1-1 子步进 + P1-3 成功判定 + 接触检测 + P1-4 日志

- **子步进（action repeat）**：`_init_mujoco` 计算 `substeps = round((1/control_freq) / timestep) = 10`；`step()` 内跑 `substeps` 次 `mj_step`。每个 env 动作对应 20ms 物理仿真，伺服能收敛到目标（实测单步推进 0.0038 rad，30 步累计 0.11 rad；末端 30 步可走 0.17m）。
- **动作空间**：前 7 维 = `±max_joint_delta`，第 8 维 = `[0,1]`（原来是关节绝对角度，与执行器语义不符）。
- **reset**：夹爪 qpos 用 `jnt_qposadr` 索引（freejoint 后 qpos 地址≠关节 ID）；删除写 `qpos[7]=0.02` 的肌腱初始化（与 freejoint 冲突）。
- **成功判定（P1-3）**：`_update_grasp_state` 重写为
  `is_grasped = (dist(hand,obj)<0.10) AND (gripper_width<0.05) AND (左右两指都与物体真实接触)`。
  P1 以 `grasp_success = is_grasped`；“物体被抬起/搬运”留作后续细化（见 §七）。
  - 新增 `_check_grasp_contact()` / `_get_grasp_contact_force()`（基于 `data.contact` geom 对 + `efc_force` 法向力）。
  - 新增 `_get_gripper_width()`（用 `jnt_qposadr` 求和两个手指关节）。
- **奖励累计与日志（P1-4）**：`task_state['episode_reward']` 累计；episode 结束时把**累计奖励**（而非最后一步奖励）和 `grasp_success` 写入 `TrainingMonitor`。
- `_find_components`：机械臂关节用 `jnt_type == HINGE` 判定（排除手指滑动关节与 freejoint）。
- 观测维度注释 52 → 53。

### 6. `agent.py` — P1-4 指标管线

- `set_environment`：`real_env = env.env if hasattr(env,'env') else env`，把 `training_monitor` 挂到**真实环境**（旧代码检查 `Monitor` 包装层，永远为 False → 监控从未生效）。
- `GraspingCallback._on_step`：改为从 `self.locals['infos']` 读 `grasp_success`（成功计数）和 `info['episode']`（episode 计数），不再访问 Monitor 上不存在的 `env.task_state`。
- `train()`：删除未注册的死代码 `episode_callback`。

### 7. `training_monitor.py` — JSON 落盘修复

- `_save_to_log` 改为**内存持有全部 episode + 整体写盘**，不再每次读回文件。
- `json.dump(..., default=_json_default)`：numpy 标量（`np.bool_/np.float64`）转换。**根因**：此前 `success` 是 `np.bool_`，`json.dump` 序列化失败于写完一半时抛异常，把日志文件截断成非法 JSON——这也是历史日志 `"episodes": []` / 解析报错的另一层原因。

## 四、使用说明

```bash
cd rl_grasping_system
python scripts/verify_p1_incremental_control.py          # 环境级验证
python scripts/smoke_train_p1.py 4096                     # 短训练冒烟（指标管线验收）
python train_with_monitor.py                              # 正式训练（默认 50k 步，GUI）
```

- 动作约定：`action[:7] ∈ [-0.05,0.05]` rad/步（增量位置控制）；`action[7] ∈ [0,1]`（0=闭合, 1=张开）。
- 奖励约定：位置目标 = 物体中心上方 `pre_grasp_offset_z=0.10` m。
- 训练用 `use_fixed_position=False`（随机位置）；复现/调试用 `True`（固定 (0.5,0)）。

## 五、设计问题与结构问题分析

### 5.1 分层与职责不清

| 问题 | 位置 | 说明 |
|---|---|---|
| 注释中大量“？/语法？”类问题标记 | environment.py、state.py、config.py | 说明对接口语义不清晰，代码是“拼”出来的 |
| 一个类承担过多 | `PandaGraspingEnv` | 同时负责 MuJoCo 初始化、动作安全包装、奇异处理、任务判定、渲染、监控日志、奖励累计。建议拆 `MujocoBackend`（加载/前向/渲染）与 `GraspTask`（判定/奖励/预算） |
| 死代码与废弃逻辑共存 | action_wrapper（速度积分）、agent（未注册的 episode_callback）、reward（大段注释掉的公式）、state（`calculate_finger_forces`/`calculate_tendon_tension` 手写启发式与真实物理并存） | 严重妨碍理解，容易“改错地方” |

### 5.2 控制链不一致（本次 P1 修复的核心）

- 动作空间声明、动作包装器语义、执行器物理（`ctrl`=目标位置）、控制频率（声明了但未实现）四处各说各话。**一个约定必须只在一个地方定义，并被唯一消费**。
- 建议把“动作语义”抽成显式的 `ActionProtocol`（如 `IncrementalJointPosAction`），环境、包装器、文档、观测全部引用同一常量。

### 5.3 状态/观测隐患

- freejoint 加入后 `qpos/qvel` 地址 ≠ 关节 ID，旧代码多处硬编码索引（`qpos[7]`、`qpos[8]`）静默读错数据。**必须一律用 `model.jnt_qposadr/jnt_dofadr`**。
- 手写“接触力/张力/可操作度”是启发式，与真实物理（`data.contact`/`efc_force`/雅可比）并存且被喂进观测——要么删掉启发式，要么明确标注“近似特征”并留替换接口。

### 5.4 指标/监控断裂（P1-4）

- 监控器挂载靠 `hasattr` 探测包装层、回调读 `env.task_state` 但 env 已被 `Monitor` 包装——**代码作者未意识到 Gymnasium 的包装层次（env → Monitor → VecEnv）**。建议统一封装 `unwrap_until(env, PandaGraspingEnv)` 工具函数。
- 训练过程应从一开始就“可观测”：episode 累计奖励、成功率、奇异次数、步数分布缺一不可；本项目中 `TrainingMonitor` 与 `GraspingCallback` 功能重叠，建议合并为单一 `EpisodeLogger`。

### 5.5 配置散落与魔法数

- 阈值（距离/闭合/奇异）在 `config`、`environment`、`state`、`singularity_handler` 多处重复，且有的未被消费（`control_freq`、`RewardConfig` 部分字段）。建议配置全部收敛到 `config.py`，用 `getattr` 兜底默认值，杜绝“声明了但没用到”。

### 5.6 复现性

- P0-2 已把物体位置/初始位形纳入 `reset(seed)`。但完整实验对比还需：训练全程固定 seed 链路、`VecNormalize` 统计的保存/恢复、模型/日志/配置的版本归档。

## 六、工程规范建议（可落地清单）

1. **一个约定一个来源**：动作语义、控制频率、阈值、奖励系数只在 `config.py` 定义一次，其余地方引用。
2. **环境/任务/后端分层**：`MujocoBackend`（物理/渲染）← `PandaGraspingEnv`（gym 接口、子步进、观测）← `GraspTask`（判定、奖励、预算）；`action_wrapper` 只做纯函数变换（输入 raw，输出 ctrl），不做 I/O。
3. **包装层意识**：所有“拿到真实环境”的操作统一走 `unwrap_until(env, target_type)`；回调只从 `info` 读数据，禁止访问内部 `task_state`。
4. **观测/状态只用 MuJoCo 地址 API**：`jnt_qposadr/jnt_dofadr`、`geom_bodyid`、`xpos/xquat/cvel`，禁止硬编码 qpos 下标。
5. **删除死代码**：未注册的回调、被注释的公式、未被消费的配置字段，要么实现要么删除；合并 `TrainingMonitor` 与 `GraspingCallback` 为单一 `EpisodeLogger`。
6. **结构化日志**：episode 级（reward/length/success/奇异数/时间）+ rollout 级（success_rate/avg_reward）分离；JSON 落盘用 `default=` 处理 numpy 类型，避免写一半抛异常截断文件。
7. **测试即文档**：每个 P0/P1 里程碑配一个 `scripts/verify_*.py`（可重复、退出码语义化），改动后先跑回归再训练。
8. **收敛性验证步骤**：先环境级（动作能走、夹爪语义正确、奖励有限）→ 再短训练冒烟（指标出数）→ 再正式训练看 success_rate 曲线。任何一步不过就不进入下一步。

## 七、已知限制与后续（P2 清单）

**P1 内保留的简化：**

- `grasp_success == is_grasped`（到位+夹紧+接触即算成功）；“物体被抬起/搬运”尚未进入判定与奖励——真·抓取（lift）留作下一里程碑。
- 位置奖励在远距离处饱和（`min(d/scale, 1)`），初始位形下 z 项无梯度；当前靠“先平面接近、再下降”的次序学习。
- `state.py` 中 `calculate_finger_forces` / `calculate_tendon_tension` 仍是手写启发式（未接入真实接触），已标注近似特征。
- 观测仍 53 维含冗余/近似特征（如手写手指力、可操作度），未做特征精简。

**P2（训练规模与稳定性，未在本轮实现）：**

- `VecNormalize` 奖励归一化的稳定性问题已在 P1 通过关闭奖励归一化规避，后续如需开启需先解决早期方差≈0 的爆炸问题。
- 网络 `[512,512,256]` 对 53 维观测偏大，可先试 `[256,128]` 降低过拟合与算力开销。
- `total_timesteps=50k` 对 300 步/episode 的抓取任务偏低；建议按成功率曲线决定（可先跑 200k）。
- 课程式训练：固定位置 → 随机位置（`use_fixed_position=False`），并收紧 `workspace_bounds` 到实测可达域（P0-2 已知远角位脆弱）。
- `workspace_bounds` 边界（尤其 `x≈0.7, y≈±0.2`）建议按 P0-2 验证脚本的可达性结果收紧。


- __垂直分量只惩罚"俯仰"不惩罚"绕竖直轴自转"__：对桌上立方体（对称、无朝向要求）足够；若以后要抓有朝向的物体，需要把 `z_axis[2]` 换成与目标抓取姿态的四元数对齐项。

- 修复后初始位形会给一个常驻 +0.68 方向奖励，价值网络会吸收掉，不构成问题；`w_orient=1.0` 先不动，若需要可后续与 `w_height=2` 对比调参。

- 这是继 P1.1 距离去饱和&#x540E;__&#x7B2C;二个、也是更致命的一个奖励 bug__——方向项不是"没信号"，而是"信号反了"。

## P1.3 势能塑形（potential-based shaping）奖励修复（2026-08-19）

### 问题
P1.1 / P1.2 之后，奖励仍是**线性项（约 −1.3 级/步）**，带来三个问题：

1. **累计量级失真**：300 步 episode ≈ −390，与单次事件奖励（5 / 10）量级严重失衡，episode_reward 几乎被路径项淹没；
2. **价值网络学不动**：初始位形高势能 ⇒ 价值函数要把 0.1 量级、绝对值 1e3 的势能差编码进 V(s)，P1.2 已实测“价值损失降不下去”；
3. **诊断键泄漏进奖励**：`calculate_reward` 用 `sum(values())` 求和，把纯诊断键 `orient_align`、`z_axis_z` 也算了进去——而 `z_axis_z`=“手指朝上 +1 / 朝下 −1”，等于把 P1.2 修复掉的反向信号以系数 1 **重新注入奖励**。这正是方向项修了却不见效的原因。

### 修复
- 重写为**势能塑形**：`r_step = Φ(s_prev) − γ·Φ(s)`，`γ = shaping_gamma = 0.99`。
  - 单步奖励有界（≈ ±(1−γ)·Φ_max，量级 0.1）；
  - 沿任意路径的累计 = `(1−γ)·Φ(初始) − Σ事件`，与路径无关（不变式），彻底消除“每步 −1.3 级线性惩罚”。
- 势能 `Φ = w_xy·min(d_xy,cap)/xy_scale + w_height·min(dz,cap)/height_scale − w_orient·max(0,align)`。
  距离项沿用 P1.1 的去饱和线性势场；方向项沿用 P1.2 的 `max(0, align)`。
- `REWARD_KEYS` 白名单：`calculate_reward` 只对 7 个真实奖励键求和；
  `orient_align` / `z_axis_z` / `potential` 移入返回值 `b['diag']`，**绝不进入奖励**。
- 接口：`calculate_reward(state, prev_state, grasp_info, cfg)`——移除从未使用的 `action` 参数（调用方 environment / verify / diag 同步更新）。
