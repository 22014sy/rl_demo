## 1. 姿态表示与动作空间：四句设计声明核实

四句待核实声明：
1. 姿态存储用四元数（保证全局无奇异）
2. 网络输出用角速度（避免归一化约束）
3. Loss 计算考虑双覆盖（保证收敛平滑）
4. 与基线融合用小角度残差（简化线性映射）

### 1.1 逐条核实

| # | 声明 | 核实结论 | 代码依据 |
|---|---|---|---|
| ① | 姿态存储用四元数（保证全局无奇异） | ✅ 成立 | `state.py:113` `ee_orientation = data.xquat[hand_id]`（w,x,y,z）；`state.py:126` `target_orientation = env.target_quat`（`[1,0,0,0]`）；MJCF 模型用 quat（`models/universal_robots_ur5e/alignment_report.md`） |
| ② | 网络输出用角速度（避免归一化约束） | ⚠️ 语义成立、实现有出入 | PPO 输出**末端位姿增量**，速度模式下按 `v = Δ/T` 解释为速度（`environment.py:532-545`）；姿态维度输出**旋转向量**（`ik.axis_angle_to_quat`，`config.py:47` 限幅 0.05 rad），仅小角度下等价于角速度；且当前默认 `action_space_dim=3` 不输出角速度（姿态固定朝下，`config.py:45`） |
| ③ | Loss 计算考虑双覆盖 | ⚠️ 概念对、用词错 | 本项目是 PPO，无监督式四元数回归，**不存在 Loss**。双覆盖实际处理在**奖励**（`reward.py:56-62` `dot²` 消除）与**观测**（`environment.py:1443-1444` `q_rel` 规范化 w≥0） |
| ④ | 与基线融合用小角度残差 | ✅ 成立（有一限定） | `v_servo = v_nominal(t) + Δv/T` 速度空间线性叠加（`environment.py:548-552`、`docs/混合控制架构设计.md §5.2`）；小角度假设在 `ik.py:86` `quat_vec=2q[1:]`、`action_wrapper.py:66-70`、`max_orient_delta=0.05`。**限定**：标称基线角速度恒 0（`nominal_trajectory.py:98`），姿态侧无基线可融合 |

### 1.2 修正后表述（可直接用于简历/答辩）

| 原表述 | 修正表述 |
|---|---|
| 姿态存储用四元数（保证全局无奇异） | 位姿状态/观测用四元数存储，规避欧拉角表示奇异（运动学奇异另由阻尼伪逆/可操作度观测/奇异检测处理） |
| 网络输出用角速度（避免归一化约束） | 动作空间为末端增量，速度模式下按 Δ/T 解释为线/角速度，绕开四元数输出归一化约束 |
| Loss 计算考虑双覆盖（保证收敛平滑） | 奖励与观测处理双覆盖（`dot²` 对齐项 + `q_rel` 的 w≥0 规范化） |
| 与基线融合用小角度残差（简化线性映射） | 残差在速度空间线性叠加 `v = v_nominal + Δv/T`，小角度增量保证旋转向量≈角速度的线性映射成立（姿态侧基线当前为 0） |

> ⚠️ 重要区分：四元数消除的是**表示层奇异**（欧拉角万向节死锁），**机械臂本身的运动学奇异**（肘伸直/腕奇异）仍存在——项目用 `singularity_handler`、可操作度观测、IK 阻尼（`velocity_ik_lam=0.08`）处理。若四句话用于监督式回归/残差策略论文设计，则 ②③ 反而是对的；本仓库 PPO 实现按上表措辞修正。

## 2. 控制流水线逐节核对

待核对流水线（教科书级联控制）：
```
输入 x_target/x_actual
 → 外环 PI：期望速度 ẋ_des
 → 物理限幅 ±0.5 m/s + 积分分离（Anti-windup）
 → DLS：q̇_des = Jᵀ(JJᵀ+0.08²I)⁻¹ ẋ_des
 → 关节限幅 clip(q̇_des, ±1.0)
 → 积分输出 q_target = q + q̇_des·dt
 → 底层逆动力学（计算力矩）→ τ
```

### 2.1 结论

**7 步里只有第 4 步（DLS 阻尼伪逆）与代码完全一致；其余各步要么不存在、要么参数/机制不符。该流水线不是本仓库任何一个控制器的准确描述，而是教科书级联控制与实际实现的拼接。**

### 2.2 逐节对照表

| 你的描述 | 项目实际 | 结论 |
|---|---|---|
| ① 输入目标/当前位姿 | `state.py` 提供 `ee_position/ee_orientation`、`target_pos/target_quat` | ✅ |
| ② 外环 PI → 期望速度 ẋ_des | **无外环 PI**。期望速度来自 RL 策略输出 `v=Δ/T`（`environment.py:532`）或 residual 标称 P 速度场 `v_nominal=clamp(gain·(hover−ee), v_max)`（`nominal_trajectory.py:9`）——纯 P 阻尼场、无积分项 | ❌ |
| ③ 限幅 ±0.5 m/s + 积分分离 | **限幅值非 0.5**：当前契约 `v_max=0.125 m/s`（`max_ee_delta=0.005`/T=0.04s，`sim_to_real动力学匹配方案.md`；DEV_LOG 记录"速度环能力上限 ~0.5 会振荡"）；**无积分器故无 Anti-windup**，实际做动作限幅 + 一阶低通平滑（`action_smoothing_alpha=0.7`） | ❌ |
| ④ DLS：q̇=Jᵀ(JJᵀ+0.08²I)⁻¹ẋ | ✅ 完全一致：`dq=Jᵀ(JJᵀ+λ²I)⁻¹v`，λ=`velocity_ik_lam`=0.08（`ik.py:49-51`、`config.py:51`） | ✅ |
| ⑤ 关节限幅 clip(q̇, ±1.0) | **不存在**。dq 直接作速度环目标，关节速度仅被末端 v_max 与**力矩饱和**（forcerange 150/28 N·m，`environment.py:644/671`）间接限制 | ❌ |
| ⑥ 积分输出 q_target=q+q̇·dt | **主链路不做**。速度模式把 dq 作**速度伺服目标**直接跟踪；位置模式走 `solve_ik` 迭代反解（`action_wrapper.py`），非速度欧拉积分 | ❌ |
| ⑦ 底层逆动力学（计算力矩） | **非计算力矩**。实际为**速度 PID + 重力/惯性前馈** `τ=kp(dq−qvel)−kd·qvel+M_eff·dq_ff+qfrc_bias`（`environment.py:668`，复刻 UR speedJ）。计算力矩输入期望**加速度** q̈_des，此处输入期望**速度** dq，且无位置 PD | ❌ |

### 2.3 实际的两条链路

**A. `rl_grasping_system`（主项目，RL 速度控制）**
```
RL/标称 → 末端速度 v（限幅 0.125 + 平滑）→ velocity_ik 阻尼伪逆(λ=0.08)
        → 速度伺服 τ = kp(dq−qvel) + 前馈
```
DLS 是唯一与教科书流水线重合的环节。

**B. `panda/` 传统控制器**（如 `pid_panda_mujoco_motor.py`）
```
任务空间 PID（ki=0，实为纯 P）→ 输出×dt 当位置增量 → ikpy IK 求关节角
→ 关节 PID（条件积分 anti-windup，`pid_panda_optimized.py:170`）→ 力矩限幅 ±87 N·m
```
有 Anti-windup、有"增量积分"，但位置在**任务空间**积分、底层是关节 PID，仍非教科书描述。

## 3. 业界定位：为什么现有链路（RL 速度伺服）是主流

### 3.1 速度 twist 接口 = 业界标准中间层

| 对象 | 接口语义 | 说明 |
|---|---|---|
| **MoveIt Servo** | `Twist`（线/角速度 m/s, rad/s） | ROS 标准速度伺服接口，`docs/混合控制架构设计.md` 即按此设计 |
| **UR `speedJ`** | 关节速度 (rad/s) | 底层速度环，内置 PID + 重力补偿 |
| **UR `servoL`/RTDE** | 笛卡尔速度 (m/s, rad/s) | 高速 500Hz 笛卡尔伺服 |
| **本项目 `velocity_ik`** | 末端速度 (m/s, rad/s) | `dq=Jᵀ(JJᵀ+λ²I)⁻¹v`，语义=Servo twist |

→ 本项目的"末端速度 → 阻尼伪逆 → 关节速度"正是主流 Servo 链路，**不是被"内环不够好"逼出来的小众做法**。

### 3.2 残差 RL + 速度伺服是主流

- **Johannink et al. 2018**（ICRA 2019, arXiv:1812.03201）：*Residual Reinforcement Learning*，`v=v_nominal+Δv` 同构；
- **RMA**（Xia et al. 2021）、**Spot**（Boston Dynamics）：参考轨迹 + 学习残差的分层控制；
- **特斯拉 Optimus / Figure**：参考轨迹 + 学习修正分层；
- 速度级 Servo 是当前**人形/协作臂动态操作的默认执行层**。

### 3.3 实测数据支撑（本项目内部证据）

| 项 | 数值 | 说明 |
|---|---|---|
| 速度伺服实现率 | **96%**（v=0.125） | `dq` 精确匹配 qvel，干净跟随（`机械臂抖动分析与抑制.md`） |
| 速度环上限 | ~0.5 m/s 起相位滞后振荡 | 据此标定 `v_max=0.125` |
| 位置伺服实现率 | 8%~41% | 位置模式滞后的实证（`sim_to_real动力学匹配方案.md`） |
| 三路消融 | 静态 100% / 动态 90% / 动态+障碍 86.7%，残差全场景最优 | `docs/2026-08-29_架构与感知业界定位决策记录.md` |

→ 现有链路在**精度、稳定性、业界同构性**三方面都有据可查。

### 3.4 教科书级联链路的可取点（可作演进方向，不构成更换理由）

| 教科书环节 | 现有链路对应 | 取舍 |
|---|---|---|
| 积分（PI/位置） | 无积分器（纯 P 标称场 + RL 增量） | 不引入：P 阻尼场 + RL 增量已闭环，积分器在 RL 语义下会引入状态耦合/重置问题 |
| 关节 q̇ 限幅 | 无（靠 v_max + 力矩饱和） | 可加：作为**安全层显式关节限幅**（`docs/混合控制架构设计.md` §6 已规划未实现） |
| 计算力矩（期望加速度） | 速度 PID + 前馈 | 不更换：复刻 UR speedJ 的部署语义，sim2real 匹配优先 |

## 4. 控制物理量、UR 固件 PID 与项目方案清单

### 4.1 各层物理量流转（主项目速度模式）

```
RL 输出 Δ(m/rad) ──v=Δ/T──▶ 末端速度 v (m/s, rad/s) ──DLS──▶ 关节速度 q̇ (rad/s)
   ──速度PID+前馈──▶ 关节力矩 τ (N·m) ──▶ MuJoCo
    config.py:47        environment.py:532          ik.py:49         environment.py:668
```

| 层级 | 物理量 | 单位 | 代码 |
|---|---|---|---|
| 策略输出 | 末端位置增量 Δ | m | `max_ee_delta=0.005`（config.py:47） |
| 任务空间命令 | 末端速度 v=Δ/T | m/s（+rad/s 6D 模式） | environment.py:532，T=0.04s |
| 关节空间 | 关节速度 q̇ | rad/s | `dq=Jᵀ(JJᵀ+λ²I)⁻¹v`，λ=0.08 |
| 底层 | 关节力矩 τ | N·m | `τ=kp(dq−qvel)−kd·qvel+M·dq_ff+qfrc_bias`（environment.py:668），限幅 forcerange 150/28 |
| 夹爪 | 位置伺服 ctrl | 0–255 | `fingers_actuator`（kp=100） |

**关键点**：主链路全程不控制位置。速度命令不积分成 q_target，直接作速度伺服目标跟踪，是"速度伺服级联"而非"位置伺服级联"。默认 3D 动作空间只控线速度（姿态固定朝下）。

### 4.2 UR 固件 PID：真实硬件有，仿真里没有 → 项目"复刻"它

**真实 UR5**：固件内置多环（位置→速度→力矩，PID + 重力补偿），对外只开放位置/速度接口（`moveJ/servoJ/moveL/servoL/speedJ/speedL`），**力矩环不开放给用户**。

**但 MuJoCo 仿真没有"厂商固件"**。若直接用 MuJoCo 内置 velocity-servo actuator，实测在重力静载荷下会拉塌臂/力矩饱和，与真实 UR speedJ 不一致。因此：

> "arm 关节用 motor(力矩)，环境内实现'速度 PID + 重力补偿前馈'：`tau=kp*(dq-qvel)+qfrc_bias`。纯 MuJoCo velocity-servo 与真实 UR speedJ（内置 PID + 重力补偿）不一致；**motor+PID 复刻真实行为**。"（`models/universal_robots_ur5e/make_ur5e_robotiq2.py:84-87`）

→ 这不是重复造轮子，而是**在仿真里补齐"固件那层"**，保证训练侧速度环语义 = 部署侧 `speedJ` 语义（sim2real 关键，`RL_DEPLOY_CONTRACT.md:72`）。不匹配的后果有实测记录：训练侧速度实现率仅 5–14%，部署侧可近 100%，实机位移比训练大一个量级（`sim_to_real动力学匹配方案.md:19`）。

## 5. 动作空间：为什么输出"位置增量"而非直接速度

### 5.1 等价关系（先澄清）

增量与速度**数学等价**：`Δ = v·T`，决策周期 T 固定时一一对应。项目名义上输出"每步位移 Δ"，执行层按 `v=Δ/T` 实现——**"增量"就是"定标后的速度命令"**。

### 5.2 选增量的五个工程原因

| # | 原因 | 说明 |
|---|---|---|
| ① | 限幅语义贴任务几何 | `max_ee_delta=0.005`="一步最多走 5mm"，直接对标物体尺寸/接近距离/夹爪触发阈值（均 m 量级），调试直观 |
| ② | 与部署契约（Servo twist）同构 | 契约本质是"一个决策周期 T 内实现位移 Δ"，增量显式把周期嵌入动作，两端语义一致（训练侧 Δ/T，部署侧 Servo 同位移） |
| ③ | 与决策频率解耦 | `v=Δ/T`，`T=substeps×action_repeat×timestep`。改决策频率时增量不变、速度自适应，动作几何稳定、不用重训 |
| ④ | 量纲与观测/奖励一致 | 观测位置(m)、奖励距离(m)、动作增量(m) 同量纲，策略"动一步"与"离目标多近"直接可比，梯度信号最直接（`P3_末端位姿控制与动作空间重构设计.md:50`） |
| ⑤ | 一动作空间兼容两控制模式 | velocity 模式解释为 Δ/T 速度；position 模式直接当位置伺服目标（solve_ik），无需两套动作空间 |

### 5.3 两种模式其实都有

- **delta 模式**：RL 独立输出增量（`v=Δ/T`，无标称）——历史/单任务；
- **residual 模式**：RL 输出**速度残差** `Δv/T`（m/s），叠加到标称速度场 `v_servo=v_nominal+Δv/T`（`environment.py:548-552`）——主架构（D1 起）。

### 5.4 业界对照

- 部署侧（MoveIt Servo / UR `speedJ`）：twist 速度接口；
- 训练侧（Diffusion Policy / BC action chunk）：输出"未来 N 步位姿增量序列"，执行层按步长转速度。

→ 项目取"增量输出 + 速度伺服执行"，即**策略侧稳定可控、底层实现率高**的业界折中。

## 7. 为什么用速度 IK 不用位置 IK

### 7.1 核心：不是"替代"，是不同链路的环节

| 环节 | 输出 | 服务链路 |
|---|---|---|
| 速度 IK（`ik.py:38`） | `dq`（rad/s 关节速度） | **速度伺服级联**：`v → dq → 速度PID → τ`（`environment.py:655-668`） |
| 位置 IK（`ik.py:153`） | `q_target`（rad 关节角） | **位置伺服链路**：需要位置伺服 ctrl，主链路不用 |

### 7.2 六个原因（全部有实测/代码依据）

| # | 原因 | 依据 |
|---|---|---|
| ① | 链路一致性：速度 IK 输出 dq 直接喂速度环；位置 IK 输出 q_target 属位置伺服链路 | `environment.py:655-668`、`action_wrapper.py` |
| ② | 实时性：速度 IK 单步矩阵运算（1 次 `mj_jacBody`+6×6 求解，~2ms）；位置 IK 每次迭代要 `mj_forward+mj_jacBody+6×6`，5000 次曾实测 **0.84s/步卡仿真**，修复 500 次+停滞退出后奇异/不可达仍退化 | `ik.py:58-64`、`ik.py:160-165` |
| ③ | 奇异鲁棒：阻尼伪逆 λ=0.08 压低奇异附近伪逆增益（等价实机奇异降速）；位置 IK 近奇异收敛慢/落局部极小（实测 tip 水平偏 12cm） | `ik.py:63-64`、`docs/简历项目知识整理.md:41` |
| ④ | 实现率/sim2real：速度模式 ~96% vs 位置模式 8%~41%；速度 IK 语义=MoveIt Servo twist/UR speedJ，部署免改写 | `机械臂抖动分析与抑制.md`、`sim_to_real动力学匹配方案.md:19`、`RL_DEPLOY_CONTRACT.md:72-73` |
| ⑤ | 连续性：速度 IK 每步小增量局部线性化连续跟踪，无解分支跳变；位置 IK 多解分支相邻两步可跳解致抖动 | v_max=0.125，每步 ≤5mm |
| ⑥ | RL 高频决策兼容：25Hz 决策周期 T=0.04s，位置 IK 的迭代成本抖动不可控 | `config.py`（T=0.04s） |

### 7.3 位置 IK 仍在用（分工，非删除）

- 位置模式（对照）：`action_wrapper.py` → `solve_ik` → 关节位置伺服目标（`environment.py:604-610`）
- 复位/验证/可达性：`verify_ee_pose_control.py`、`verify_grasp_success_criterion.py`、`verify_radius_006_reachability.py`
- 奇异恢复：`singularity_handler.get_safe_config`

> 一句话：**速度 IK 是"速度伺服级联"链路里唯一自洽的一环**（输出 dq 喂速度环、单步快、奇异鲁棒、96% 实现率、真机同语义）；位置 IK 是"位置伺服链路"的环节（迭代慢、奇异退化、实现率低、多解跳变），主链路不用，只留给"一次性求关节目标"。
