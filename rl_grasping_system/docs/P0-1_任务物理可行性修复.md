# P0-1 模型/任务物理可行性修复记录

> 阶段目标：让抓取任务在**物理上可行**，并用**纯 MuJoCo**（不依赖 RL 训练代码）实证验证"能抓起"。
> 本文件记录改动原因、实测数据、改动清单与验证结果，作为后续 P0-2..5 的基础。

---

## 1. 问题背景（为什么必须做 P0-1）

原始模型 `models/franka_emika_panda/single_cube_scene.xml` 存在两个使任务**物理上不可能成功**的缺陷，
这是"训练成功率恒为 0"的根本原因，调任何超参数都无法解决：

| 缺陷 | 后果 |
| --- | --- |
| `target_cube` 是**静态物体**（无任何关节，焊接在世界上） | 夹爪永远无法把它抓起/抬升；即使夹住，物体也不会随夹爪移动 |
| 物体边长 **0.1m**，而夹爪指尖内表面最大开口实测仅 **≈0.056m** | 物体根本**放不进夹爪**，物理上无法包住 |

## 2. 夹爪几何实测（MuJoCo 实测，非估算）

对 `panda.xml` 直接读取 `geom_xpos` 得到的数据：

| 手指关节值 f | 左右指尖(衬垫中心) y 坐标 | 内表面开口 |
| --- | --- | --- |
| 0.00（全闭） | ±0.0039 | ≈0（指尖相触） |
| 0.02 | ±0.0180 | ≈0.028 |
| 0.04（全开） | ±0.0322 | **≈0.0563** |

- 左右手指沿 `hand` 局部 ±y **对称滑移**（`right_finger` 的 `quat="0 0 0 1"` 是绕 Z 转 180°）。
- 指尖衬垫 `fingertip_pad_collision_1`（box `0.0085 x 0.004 x 0.0085`）在 finger 局部 `y=+0.0055`，故
  实际开口比“2×0.04=0.08m”小，**最大内表面开口 ≈0.0563m**。
- 肌腱/执行器语义（位置伺服，实测）：
  `ctrl8=0 → 手指闭合(0)`；`ctrl8=255 → 手指全开(0.04)`；`手指位置 ≈ ctrl/255 × 0.04`。

**结论**：物体边长需 **≤0.04m** 才有可靠抓取余量（0.04 < 0.056）。本修复采用 **0.04m 立方体**。

## 3. 改动清单

### 3.1 `models/franka_emika_panda/single_cube_scene.xml`（模型修复，核心）

`target_cube` body 改动如下：

```xml
<body name="target_cube" pos="0.5 0.0 0.1">
  <freejoint/>                                                  <!-- 新增：物体可移动/可被抓取 -->
  <inertial pos="0 0 0" mass="0.064"
            diaginertia="1.7067e-5 1.7067e-5 1.7067e-5"/>        <!-- 新增：显式质量/惯性（0.04m 立方体） -->
  <geom type="box" name="target_cube_geom" size="0.02 0.02 0.02"
        material="target_material"/>                            <!-- 尺寸 0.05→0.02（边长 0.1→0.04m） -->
</body>
```

改动点：

1. **新增 `<freejoint/>`**：物体从"焊接在世界上的静态 geom"变为 6-DoF 自由物体，可被夹爪抓起/抬升。
2. **尺寸 0.05 → 0.02**（边长 0.1m → 0.04m）：放入实测开口 0.0563m 内，留出抓取余量。
3. **新增显式 `<inertial>`**：质量 0.064kg（=1000kg/m³ × 0.04³），保证动力学确定性。
4. geom 增加 `name="target_cube_geom"`，便于调试/按名修改摩擦等。

> 注意：`freejoint` 使物体成为自由体，reset 后物体会从 `pos="0.5 0.0 0.1"` **自由落体**到地面
> （z≈0.02）。这是符合物理的正确行为，后续 P0-2/5（奖励、成功判定、观测）需基于"物体落定后位置"处理。

### 3.2 `rl_grasping_system/environment.py::_set_object_position`（配套兼容性修复）

加 `freejoint` 前，目标物体无关节，此函数里 `for i in range(njnt): if jnt_bodyid[i]==object_id` **永远不命中**（静默无效）。
加 `freejoint` 后会命中，但原代码只写**一个** qpos 分量（只写 x），会破坏物体位姿。修复为按关节类型写完整位姿：

```python
def _set_object_position(self, position: Optional[np.ndarray] = None):
    if position is None:
        position = np.array([0.5, 0.0, 0.1])
    position = np.asarray(position, dtype=float)
    if self.object_id is not None:
        for i in range(self.model.njnt):
            if self.model.jnt_bodyid[i] == self.object_id:
                jt = self.model.jnt_type[i]
                if jt == mujoco.mjtJoint.mjJNT_FREE:
                    self.data.qpos[i:i + 3] = position                       # 位置
                    self.data.qpos[i + 3:i + 7] = np.array([1, 0, 0, 0])     # 四元数
                elif jt == mujoco.mjtJoint.mjJNT_BALL:
                    self.data.qpos[i:i + 4] = np.array([1, 0, 0, 0])
                else:
                    self.data.qpos[i] = position[0]
                break
    self.logger.debug(f"设置目标物体位置: {position}")
```

另外把原来每次 reset 都刷屏的 `logger.info` 降为 `logger.debug`。

## 4. 新增验证脚本（纯 MuJoCo，不依赖 RL 代码）

`rl_grasping_system/scripts/verify_grasp_feasibility.py`

- 用**阻尼最小二乘(DLS) IK**（基于 `mj_jacBody` 雅可比）把 `hand` 送到目标 6-DoF 位姿（指尖朝下、手指沿 y 捏合）。
- 流程：物体落定 → 张开手指移向预抓取位 → 下降到抓取位（指尖对准物体中截面）→ 闭合手指 → 抬升 0.12m。
- 判定：`物体抬升高度 > 0.06m` 且抬升末端**指尖仍与物体接触** ⇒ PASS（退出码 0）。

关键实现细节（踩坑记录）：

1. **物体带 freejoint 会自由落体**：必须先让机械臂停住、物体落到地面稳定后，再以“落定位置”计算抓取目标，否则指尖悬空永远碰不到物体。
2. **`solve_ik` 必须是纯函数**：最初版本直接在主 `data` 上迭代，导致 IK 完成后机械臂被“瞬移”到目标位姿、物体被留在原地、接触瞬间丢失。修复为在临时 `MjData` 副本上求解，所有运动统一由 `move_to_q` 线性插值 + 位置伺服平滑驱动。
3. **接触判定需包含 `left_finger/right_finger`**：物体与夹爪的接触发生在手指 body 上，而非 `hand` 本体。

## 6. 兼容性影响（对后续 P0 步骤）

- **qpos 布局不变，所有既有硬编码索引仍有效**：加 `freejoint` 后
  `nq: 9 → 16`，但顺序为 `qpos[0:7]=机械臂`、`qpos[7:9]=手指`、`qpos[9:16]=物体 freejoint(位置+四元数)`，
  因此 `state.py` 中的 `qpos[7]/qpos[8]`、环境中的 `qpos[:7]` 等全部不受影响。
- 环境 `reset()` 实测正常：`nq=16`、`object_id=12`、`obs` 53 维一致。
- `_set_object_position` 修复已实测：从 (0.7,0.3,0.15) 正确写回 (0.5,0,0.1) + 单位四元数。
- **注意**：物体 reset 后会落定到地面 (z≈0.02)，后续 P0-2/5（奖励距离项、成功判定、观测）
  应基于物体实际位置（`data.xpos[object_id]`）而非 XML 初始位置。
