# 2026-08-27 部署分工重构与最小验证（MoveIt + RL 混合架构讨论记录）

> 状态：架构讨论已完成 → 最小验证执行中
> 背景：v5→v12b 八版训练证明"RL 同时学抓取+绕障"路线全部失败（详见 CHANGELOG P5.x / 决策记录决策 9-11），
> 本文记录转向"部署分工"路线的完整讨论与验证。

## 1. 失败证据链回顾（为什么必须换路线）

| 版本 | 配方 | 成功率 | 碰撞率 | 结论 |
|---|---|---|---|---|
| v6 | warm-start v5，无障碍先验 | **79%** | 57~65% | 抓取最优但感知锁死（actor obstacle 权重≈0，探针 diff=0） |
| v9 | 从零 300k | 0.5% | **7.5%** | 唯一学会避障，但抓取崩（够不到） |
| v10 | 从 v9 续训 500k | 2~5% | 18~23% | 避障保留、抓取补不上（final_dist 0.53m） |
| v11 | warm-start v6_obsseed2 + 弱惩罚 | 68~71.5% | 53~62% | 感知激活（探针 diff 2.68）但碰撞率不降 → 奖励经济学：穿障 -90 < 成功 +120 |
| v12 | v11 + 碰撞即失败(max_streak=1)+penalty-20+3障碍 | **25%** | **71%** | 碰撞终止压死探索（episode 均 25 步），学不到绕障（v3 教训复现） |
| v12b | v12 + max_streak=3 | 15% | — | 更差；max_streak 1/3 均无效 |

**核心结论**：
1. **warm-start 学不会绕障**（权重先验锁死 + 直接上满难度）——v5→v12b 七版全败；
2. **从零能学会避障但丢抓取**——RL 同时学"抓取+绕障"存在基本矛盾；
3. **碰撞终止压死探索**（v3/v12/v12b）——失败信号不能掐掉试错路径。
→ 必须改变分工：**让 RL 不再同时承担抓取与避障**。

## 2. 部署分工矩阵（本方案的基石）

| 技能 | 真机部署负责方 | 训练端 RL 需要学吗 |
|---|---|---|
| 抓取（静态目标） | **MoveIt 规划**（OMPL 无碰撞轨迹） | ❌ 不需要 |
| 静态避障（已知障碍） | **MoveIt 规划** | ❌ 不需要 |
| 动态避障（移动障碍） | **RL 残差** | ✅ 只学这个 |
| 动态抓取（移动目标） | **标称轨迹 + 目标速度前馈** + RL 修正 | ✅ 学"修正"（与避障同源） |

本质：标称轨迹 = MoveIt 仿真替身（`nominal_trajectory.py`），负责"规划内"的一切（抓取接近 + 静态避障）；
RL 残差 = 只负责"规划外"的实时修正（移动障碍避让 + 跟踪误差补偿）。这正是 residual 架构的纯粹形态：
`v_servo = v_nominal(t) + Δv`，静态场景残差→0，动态场景残差出手。

### 2.1 关键前提（必须落实）
- **训练端标称替身必须具备静态避障能力**：否则 RL 在训练时看到静态障碍挡路仍被迫学静态绕障，
  回到死结，且与真机（MoveIt 做静态避障）不一致。
- 实现：`nominal_trajectory.py` 加简单几何避障（已知静态障碍在路径上时，标称横向绕行）。

## 3. 动态避障可行性（微小绕障 RL）

### 3.1 能力圈量化
| 参数 | 数值 |
|---|---|
| 决策频率 | 25Hz（control_freq=50 × action_repeat=2） |
| 速度契约 v_max | 0.125 m/s（max_ee_delta=0.005 / 0.04s） |
| 残差横向分量（估计） | ~0.05–0.1 m/s |
| 1~2 秒横向移动 | 5~20cm |
| 绕过单障碍所需横向偏移 | ~10–15cm（球 r=5cm + 臂半宽 ~5cm） |

### 3.2 结论
- **静态障碍正落路径**：需一次性横向 10–15cm（中等绕行）——超出"微小"，是 v5→v12b 学不会的任务。
- **动态障碍（0.05 m/s）**：每决策步仅移动 2mm，策略只需"追踪微调"——完全在残差能力圈内。
- **动态避障 = 追踪而非绕行**：是"感知→微小动作响应"技能（残差本职），一旦学会基础映射
  （v9 从零证明 RL 能学，碰撞 7.5%），动态障碍自然接上。
- 障碍速度边界：≤0.1 m/s 无压力（每步 4mm 增量）；>0.2 m/s 需 50Hz 决策（ROADMAP 已规划）。
- **动态阶段同样禁止碰撞终止**（v12 教训），保持温和惩罚 + 成功折扣。

## 4. 动态抓取（移动目标）

### 4.1 现状：标称已支持追踪，但纯 P 控制有滞后
`nominal_trajectory.py` 速度场天然支持移动目标（target_pos 实时变化，标称自动跟踪），但**无速度前馈**：

| 目标速度 | 纯 P 稳态跟踪误差（≈v/gain, gain=3） | 对齐阈值（3cm） |
|---|---|---|
| 0.03 m/s | 1.0 cm | ✓ 够 |
| 0.05 m/s | 1.7 cm | ✓ 够（边界） |
| 0.1 m/s | **3.3 cm** | ✗ 卡边界，成功率掉 |

### 4.2 动态抓取 = 三个子问题
| 子问题 | 归属 | 方案 |
|---|---|---|
| ① 追踪 | 标称 + **目标速度前馈** | `v_nominal += k·v_target`（~10 行），确定性消滞后 |
| ② 精确对齐 + 闭合时机 | RL 残差 + 状态机 | RL 补"前馈后剩余误差"；闭合时机需验证（动态下目标位移 vs 手指容差） |
| ③ 动态避障叠加 | RL 残差 | 同一网络输出，综合修正 |

### 4.3 训练端职责（回答"还要不要同时训练抓取+避障"）
**不需要再学完整抓取**。训练分布三合一（同一残差网络）：
- 40% 静态无障（残差→0，防漂移）
- 30% 动态目标（学跟踪误差修正）
- 30% 动态目标 + 动态障碍（学综合修正）

抓取本体（接近→对齐→状态机闭合）由标称 + 状态机保证。

### 4.4 三个风险点
1. **闭合时机**（最关键）：对齐触发→手指夹住的 ~0.1-0.2s 内目标位移（0.05 m/s→5-10mm）是否小于手指容差；可能需要"预测提前闭合"。
2. **目标运动模式**：训练三角波 vs 真机传送带单向；建议训练覆盖两种。
3. **决策频率**：0.1 m/s 目标每步 4mm，25Hz 够；更快需 50Hz。

## 5. 奖励设计建议（若 RL 仍需学修正，配合上述分工）

> 注意：分工重构后"奖励经济学"死结（穿障 -90 vs +120）**基本消解**——RL 不再为抓取奖励负责，
> 只需"避开就无惩罚、撞上就惩罚"，信号干净。以下建议用于 RL 学修正阶段 + 兜底场景。

### A1. 成功奖励与碰撞挂钩（结构化成功）
`r_grasp = +100`（无碰撞）→ `+100×(1−k·count)`（有碰撞，k≈0.1~0.2）。让"穿障抓到"净收益被压缩，
"绕障抓到"拿满额。参考 OpenAI 灵巧手"任务分解"。

### A2. 碰撞惩罚温和但不终止
当步 -10~-15，`max_streak=0`（不终止，保探索空间）。惩罚管"让穿不舒服"，成功折扣管"让穿不划算"，
终止管"留试错路径"——三者各司其职（v7/v12 错在把终止当惩罚用）。

### A3. 接近惩罚范围扩大
`obstacle_range` 0.15→0.25~0.30m（提前避让有梯度）；`obstacle_w` 0.5~1.0（不淹没抓取信号）。

### B. 障碍难度课程（warm-start 学不会绕障的真正解法）
| 阶段 | 障碍配置 | 难度 | 目标 |
|---|---|---|---|
| S1 | 无障碍 | 无 | 基线（v6，79%） |
| S2 | 路径旁边（lateral ±0.12） | 看得到不用绕 | 学感知+不打断抓取 |
| S3 | 路径边缘（±0.05~0.08） | 轻微挡 | 学小幅绕 |
| S4 | 路径上（0~±0.03） | 必须绕 | 学大幅绕 |
| S5 | 多障碍+随机 | 满 | 泛化 |

每阶段 warm-start + mix 0.3，成功率守 ≥60% 再进阶。

### C. 残差架构缓解（参考 Residual RL 论文 arXiv:1812.03201）
- C1：课程后期放宽 Δv 上限（0.125→0.2）、`residual_reg_w` 0.5→0.2
- C2：标称轨迹几何避障（RL 回归小修正本职，也满足 §2.1 前提）

### D. 备选（成本高，暂缓）
- D1：从零激活（v9）+ 策略蒸馏保抓取（policy distillation）
- D2：HER（PPO on-policy 不直接适用）

## 7. 最小验证（2026-08-27 执行）

### 7.1 验证目标
**"标称 + 目标速度前馈能否纯抓取"**——这是"RL 只做修正角色"的地基假设：
若纯标称（残差=0）在静态/低速动态下抓取成功率达标（≥~50-70%），则 RL 只需纯修正；
若不达标，则 RL 必须兜底学抓取（回到老问题）。

### 7.2 验证方法
- `GraspingEnv` residual 模式 + **零残差动作**（Δv=0 → v=v_nominal，纯标称执行）
- 静态目标 / 动态目标（0.03/0.05/0.1 m/s）各 N 个 episode
- 指标：成功率、失败原因（够不到/夹不住/超时）、平均步数

### 7.3 验证结果（2026-08-27，已执行）

**已实现的前馈改动（保留，check_d1 无回归）**
- `nominal_trajectory.py`：`reference_velocity` 加 `target_vel` 参数 + `v_nominal += k_ff·v_target`
  （k_ff=`nominal_feedforward_gain`=1.0）；`config.py` 加字段；`environment.py` `_update_dynamic_target`
  维护 `_dyn_target_vel`（三角波斜率 ±v）并传入标称。

**结果表（各 30 eps）**

| 目标速度 | 纯标称（无前馈） | 纯标称（前馈） | 结论 |
|---|---|---|---|
| 0.00（静态） | 30~47%（多轮波动） | 27~40% | 未达 50% 达标线 |
| 0.03 | 3.3% | 3~13% | 极低 |
| 0.05 | 23.3% | 23~30% | 低 |
| 0.10 | 0% | **10%** | 前馈方向有效 |

**失败根因诊断（单 episode 步进，决定性）**
1. **对齐精度差一点**：标称把 pad 送到 hover，`align_xy` 收敛到 **2.9cm**（触发阈值 3cm，但对
   4cm 边长 cube 半宽仅 2cm → pad 在 cube 表面外 0.9cm）→ closing 手指从 cube 边缘滑过，
   开度收敛到 **0.020 = grasp_min_width 阈值** → 判"空闭合"重开。
2. **重开滞回死锁**：重开后 pad 悬停不动（标称收敛），不满足"离开 gripper_open_distance=0.22m
   才允许再闭合"→ 永久卡 open → 200 步超时。
3. `nominal_gain` 3→6→9 无显著改善（速度环死区，非增益问题）。

**结论（最小验证判定）**
- ❌ **极端分工"RL 纯修正、标称独立抓取"不成立**：纯标称静态仅 ~30%（对齐精度不足 + 死锁）。
- ✅ **"标称主体 + RL 修正"架构成立**：v11（residual + RL，无障碍）71.5% 正是 RL 残差把
  "2.9cm 对齐误差"修到"可抓精度"的实证——RL 修正是必要组件而非可选项。
- ✅ **动态目标速度前馈方向正确**（0.10：0→10%），但动态抓取**主要瓶颈是精确对齐而非追踪**
  （失败端距恒 0.135m=hover 高度；前馈补追踪滞后，对齐仍需 RL 残差）。
- **训练端 RL 职责界定（修正）**：学"精确对准 + 追踪 + 动态避障"的修正（微小但必要），
  不需要学完整抓取规划（标称负责接近段）。比"纯动态避障"重一档，比"完整抓取+绕障"轻得多。
- **重开死锁是纯标称场景 artifact**：RL 训练时 pad 会移动（离开-再闭合），不会死锁。

**选项①执行（2026-08-27，完成 ✅）——标称对准微调落地**
- **改动**：
  1. `config.py`：`closing_align_speed` 0.02→**0.08**（closing 阶段 pad 快速对正到 cube 中心再合拢；
     手指合拢 ~10 步内 pad 移动 32mm，3cm 宽触发下也能夹住 4cm cube）。
  2. `config.py` + `nominal_trajectory.py`：`nominal_horizontal_gain=6.0`（水平对准增益与垂直分离）。
  3. 前馈（§7.3 已加）：`nominal_feedforward_gain=1.0`。
- **验证结果（纯标称 residual+零残差，40 eps）**：
  | 配置 | 静态成功率 |
  |---|---|
  | 原（closing 0.02, tol 3cm） | 42.5% |
  | tol 收窄 3cm→2cm/1.5cm/1cm | 40%/30%/30%（阈值非关键） |
  | closing 0.05 | 55% |
  | **closing 0.08（落地）** | **70%** ✅ 达标 |
- **关键机制**：失败根因是"触发时 pad 偏 2.9cm（cube 表面外 0.9cm）+ 手指合拢太快、closing 微调
  (0.02) 来不及对正 → 空闭合重开死锁"。提高 closing 微调速度后，触发后 pad 快速对正到 <1cm，
  手指合拢时包住 cube → 成功。
- **RL 兼容性冒烟**：v11 模型 + 无障碍 + closing 0.08 评估 **83.3%**（50/60）——不破坏已有 RL 策略。
- **回归**：check_d1 / check_d2 全 PASS。
- **含义**：训练端标称替身现在具备独立抓取能力（静态 70%）——"MoveIt 做抓取（+静态避障）、
  RL 只做动态修正"的极致分工**在仿真端成立**。动态目标仍低（0.03~0.1 为 20-35%），
  需 RL 追踪修正（选项②训练分布），但那是 RL 的"微小修正"本职。

**P1 升级（2026-08-27，完成 ✅）——IK 两段关节伺服 → 纯标称 97.5%**
- **动机**（用户追问"标称能不能到 90%+，真 MoveIt 可以"）：70% 是**速度场 P 控制**的精度上限
  （pad 停 2-3cm 收敛误差），真 MoveIt 的 90%+ 来自 **IK 精确解算**（`solve_ik` 实测 0.2mm）。
- **实现**（`/tmp/verify_ik_grasp.py`，验证用）：
  1. `solve_ik` 解算抓取位姿（pad 中心 = cube 中心，IK 误差 0.14mm）；
  2. **关节位置 PID 伺服**（位置误差→关节速度目标 + 速度PD + 惯性前馈 M·dq_ff + 重力补偿，
     对齐环境速度环 604-636 实现）精确到位；
  3. **两段接近**（复刻 MoveIt 无碰撞轨迹）：先到 cube 正上方 +0.15m 高处（水平对齐、不扫过物体），
     再垂直下降到 hover。
- **结果**：纯标称（无 RL）静态成功率 **97.5%**（39/40，单段伺服 67.5%→撞飞 cube 60%→两段 97.5%）。
- **失败模式修正**：单段关节插值从 home 直插抓取位会**扫过 cube 撞飞物体**（alignXY 变 8-23cm）；
  两段接近（先高后降）消除。
- **意义**：标称（IK 机制）可达 90%+，与真 MoveIt 同源——"MoveIt 做抓取 + RL 纯修正"在仿真端闭环。
- **落地挑战（未做，P2 范围）**：
  - 关节伺服与 RL 残差（Δv 速度叠加）不兼容 → 需把 IK 轨迹转为笛卡尔速度轨迹 v_nominal(t)，
    或训练用速度场、评估/部署用 IK（职责分离，RL 学通用修正）。
  - 动态目标需每段 re-plan（solve_ik 2-5ms/次，25Hz 下可接受）。

**下一步（未执行）**
- 按"标称 + RL 修正"训练（40% 静态无障 + 30% 动态目标 + 30% 动态目标+障碍），
  RL 学追踪/避障/精对准的微小修正（v11 为起点，无障碍场景已验证 83%）。
- 真 MoveIt 侧（D6）：标称替身的能力契约（分离增益 + closing 0.08 + 前馈 + IK 两段）需与真 MoveIt 对齐。

## 8. P2 路线图（"接下来怎么改"，2026-08-27 决策）

### 8.1 核心矛盾（必须解决的分叉点）
部署架构接口是 `v = v_nominal(t) + Δv`（RL 输出**速度残差**，MoveIt Servo 语义）。
验证里 97.5% 的 IK 两段伺服是**关节力矩控制**（绕过速度环），**不能直接叠加 RL 残差**。
→ 分叉点：**速度环执行"IK 轨迹采样速度"时，pad 能否到位到 closing 微调能救的精度（<2cm）？**

### 8.2 路线
- **P2a（半天，决定性分叉实验）**：`NominalTrajectory` 加 IK 轨迹模式（solve_ik 解算 hover 位姿 → 两段
  接近/下降输出**笛卡尔速度** → 速度环执行）。判定：纯标称静态 **≥85% → 路线 1**；**<70% → 路线 2**。
- **P2b（半天-1天）**：按 P2a 落地——
  - 路线 1：`nominal_trajectory.py` 升级为状态化 IK 轨迹替身（IK 解算 + 分段速度 + 动态 re-plan），RL 残差照常叠加；
  - 路线 2：保持速度场训练（现状），记录"部署契约"：评估/部署用 IK 两段伺服（97.5%），RL 学通用修正技能。

## 9. P3 第一轮训练（v13_p3，2026-08-27）——动态抓取分布 + 结果归因

**训练**：warm-start v11 + 两段 nominal + `scenario_mix=(0.4,0.3,0.3)`（新增 per-episode 场景采样）
+ 动态目标 0.05 + 动态障碍（fixed_pos 运动）+ residual_reg 0.5，500k（训练成功率 54%→73%）。

**评估矩阵（各 60 eps）**：

| 场景 | 成功率 | 碰撞率 | 判定 |
|---|---|---|---|
| 静态无障 | 80.0% | 0% | ✗（纯标称 90%，RL 残差反干扰 10pp） |
| 动态 0.03 | **73.3%** | 0% | ✅ 达标（>60%） |
| 动态 0.05 | 35.0% | 0% | ✗ |
| 动态+障碍 | 70.0% | **78.3%** | ✗（>v11 的 53%） |

**两个根因（诊断 + 修复）**：
1. **残差恒定 0.216 ≈ √3×0.125（速度上限饱和）**——RL 残差不是"≈0 微调"而是满幅干扰。
   v11 残差为单段标称学的（有益），warm-start 到两段标称后把准路径搞偏（80%<90%）。
   → **修复**：`residual_reg 0.5→1.5`（压静态残差到 0）。
2. **动态障碍布局错误**：`--obstacle` 用 fixed_pos(0.06,0.40) 在 robot 侧、**不扫过抓取路径**，
   RL 学不到避障价值（碰撞是臂靠近 robot 侧撞上）。且 `--obstacle-on-path` 分支未应用
   `--obstacle-vel`（bug，障碍被钉住成静态）。
   → **修复**：`--obstacle-on-path --obstacle-vel 0.05`（障碍从路径锚点沿轴扫过）+ train_with_monitor.py
   on-path 分支补 obstacle_vel（bugfix）。

**v14_p3b（修复训练，2026-08-27 完成 ✅）**：warm-start v13_p3 + on-path 动态障碍 0.05
+ residual_reg 1.5，500k（训练成功率 60%→87%）。**评估矩阵（各 60 eps）**：

| 场景 | v13_p3 | **v14_p3b** | 验收线 |
|---|---|---|---|
| 静态无障 | 80.0% | **95.0%** ✅ | ≥90% |
| 动态 0.03 | 73.3% | **83.3%** ✅ | ≥60% |
| 动态 0.05 | 35.0% | **66.7%** ✅ | ≥60% |
| 动态+障碍 | 70% / 碰撞78.3% | 70% / **碰撞93.3%** ❌ | 碰撞<53% |

**结论**：两个根因修复都生效——残差正则 1.5 压住静态残差（80→95%）、动态追踪也受益（0.05: 35→67%）。
**遗留**：**动态+障碍双动态场景碰撞率 93.3%（均 22.2 碰撞/ep）**——奖励经济学重演：
"追踪抓取 +100" 主导，双动态样本仅 30% + 障碍接近惩罚（obstacle_w=1）太弱 → 穿障抓到仍划算。

**v15_p3c（双动态专项，2026-08-27 完成 ✅）**：warm-start v14_p3b + 双动态样本 50%
（scenario_mix=(0.2,0.3,0.5)）+ obstacle_w 2 + collision_penalty -5 + residual_reg 1.5，500k
（训练成功率 87→86%）。**评估矩阵（各 60 eps）**：

| 场景 | v14_p3b | **v15_p3c** | 验收线 |
|---|---|---|---|
| 静态无障 | 95.0% | **96.7%** ✅ | ≥90% |
| 动态 0.03 | 83.3% | **91.7%** ✅ | ≥60% |
| 动态 0.05 | 66.7% | **83.3%** ✅ | ≥60% |
| 动态+障碍 | 70% / 碰撞93.3% | 90% / **碰撞80.0%** ⚠️ | 碰撞<53% |

**Week1 结论：3/4 验收达标**（静态 96.7%、动态 0.03 91.7%、动态 0.05 83.3%）。
**遗留 trade-off**：动态+障碍场景成功率 90%（达标）但碰撞率 80%（未达 <53%）——"双动态"下
成功 +100 vs 穿障成本（collision -5 + 接近惩罚）的奖励经济学残余；v12 核心矛盾的缩小版。

课程化（先静态障碍绕行再动态障碍）。
