# 混合控制架构设计：MoveIt2 标称轨迹 + RL 残差 + 实时安全层

> 状态：规划稿（2026-08-23）

> 关联：`docs/ROADMAP.md`；`rl_grasping_system/`（RL 侧代码）；`../ros2_moveit2_ur5e_grasp/`（ROS2 侧代码）

## 1. 架构总览（三层）

```
┌────────────────────────────────────────────────────────────────────┐
│  静态层 MoveIt2（慢而稳，确定性）                                    │
│  深度相机 → 点云 → 聚类 → 几何碰撞体 → planning scene                │
│  → OMPL 标称轨迹（含静态避障）→ 执行                                │
└──────────────────────────────┬─────────────────────────────────────┘
                               │ 标称轨迹 + 参考速度（twist）
┌──────────────────────────────┼─────────────────────────────────────┐
│  动态层 RL 残差（快而灵，学习）                                     │
│  观测 = 深度图/点云序列 + 状态 + 标称参考速度                        │
│  动作 = 末端速度残差 Δv  → MoveIt Servo 叠加执行                     │
└──────────────────────────────┬─────────────────────────────────────┘
                               │ 实时监控
┌──────────────────────────────┼─────────────────────────────────────┐
│  安全层（独立、实时、任何模式兜底）                                  │
│  CBF 式约束 / 速度-力矩限幅 / 分离距离监控（ISO/TS 15066 风格）      │
└────────────────────────────────────────────────────────────────────┘
```

**分工原则**：
- MoveIt2 保证"存在一条无碰撞路径，且它合规可审计"。
- RL 只学"偏差"：动态障碍来袭时修正标称轨迹，静态场景残差自然趋近 0。
- 安全层独立于两者，实时（1kHz 级）兜底，MoveIt2 planning scene 不做实时安全。

## 2. 为什么选残差策略（业界依据）

| 方案 | 业界实证 | 结论 |
|---|---|---|
| 模式切换（静态 MoveIt2 / 动态 RL 接管） | 工业状态机常见，但"切到学习控制"少见 | 切换冲击难处理、检测有延迟 → 不选 |
| RL 主控 + MoveIt2 安全过滤 | 大厂受限场景；审计难过 | **MoveIt2 planning scene 只有几 Hz，做不了实时安全** → 不选 |
| **残差策略**（标称轨迹 + RL 修正，Servo 执行） | Silver et al. 2018 residual RL；RMA（Xia et al. 2021）；波士顿动力 Spot = 参考轨迹 + 学习残差 | **选此方案** |

残差策略的优势（本项目受益点）：
1. **样本效率高**：RL 只学偏差，不重学整个任务，收敛快。
2. **sim2real 友好**：MoveIt2 保证标称轨迹的域一致性，RL 残差受域差影响小，契合本仓库已有 sim2real 文档。
3. **可审计**：标称路径合规可查，RL 修正有记录。
4. **安全天然**：残差幅度受限，异常时残差归零即回到安全标称轨迹。

## 3. 避障方案：不用 OctoMap

### 3.1 MoveIt2 避障的本质

```
障碍物表示（planning scene 中的碰撞体）→ OMPL 采样时做碰撞检测
```

OctoMap 只是"障碍物表示"的默认实现之一（点云→八叉树体素→planning scene），**不是唯一方案，也不是必需方案**。

### 3.2 替代方案对比

| 方案 | 实现路径 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 点云聚类→碰撞物体** | 点云→RANSAC 去桌面→欧式聚类→AABB/OBB/凸包→`add_collision_object` | 规划最快；零 octomap 依赖；静态场景一次性添加、更新频率自控；与 MoveIt API 原生集成 | 需自己实现分割/聚类/拟合（Open3D 数十行）；复杂形状近似精度有限 | ✅ **静态层采用** |
| B. 降采样点云直接当碰撞体 | `planning_scene.add_point_cloud()` | 最简、精度最高 | 规划显著变慢；量大必须降采样 | 稀疏场景备选 |
| C. 3D 栅格（OccupancyGrid） | 深度图→体素→发布 | 无 octomap 依赖 | MoveIt 对 3D 栅格支持不成熟；更新开销大 | 不推荐 |
| D. 控制层距离反应式（势场/RL 残差） | 不建地图，按最近障碍距离实时修正 | 实时、轻量、与 RL 融合自然 | 无全局规划保证、有局部极小；需全局路径兜底 | ✅ **动态层采用** |

### 3.3 业界依据

- **工业界（ABB/KUKA/UR/产线）**：静态障碍用 CAD/几何碰撞体直接进 planning scene；动态障碍（人机协作）遵循 **ISO/TS 15066**，用 **SSM（速度与分离距离监控）**，即距离反应式控制——不建动态地图。工业界实际不用八叉树做机械臂避障。
- **学术界（2020+）**：动态避障主流是 MPC 滚动时域 / CBF / 反应式势场 / RL 残差，**无人用"octomap 高频更新 + 全局重规划"做动态避障**（全局规划频率跟不上）。OctoMap 更多是研究原型的环境表示与可视化工具。
- **边界情况**：环境完全未知、障碍多而杂、需全工作空间连续更新时，体素/八叉树仍是主流。本项目是桌面抓取（目标 + 少量静态障碍 + 动态补偿），OctoMap 属过度设计。

### 3.4 结论

**不使用 OctoMap**。静态层用方案 A，动态层用方案 D（RL 残差），安全层用 CBF 式约束。
如需论文对照组，保留 `use_octomap: bool` 开关把 OctoMap 作为 Phase 1 对照方案。

## 4. 静态层（MoveIt2）设计

### 4.1 感知 → 碰撞体流水线（替代 octomap_server）

```
/depth/points ──→ 平面移除（RANSAC，去桌面/地面）
               ──→ 欧式聚类（距离阈值 ~0.02~0.05m）
               ──→ 每类拟合碰撞体（优先 OBB，其次 AABB / 凸包）
               ──→ planning scene: add_collision_object
               ──→ OMPL 规划（碰撞检测）
```

要点：
- **坐标系**：点云先转到 `base_link` 或 `world` 帧，避免规划时 TF 抖动。
- **膨胀**：每个碰撞体按机械臂末端尺寸 + 安全余量（建议 0.03~0.05m）膨胀。
- **更新频率**：静态场景 1~2 Hz 更新即可；检测到物体移动才触发重聚类。
- **目标物体排除**：抓取目标从碰撞体中剔除（或用较小膨胀），避免"抓不到"。

### 4.2 抓取状态机（demo 升级）

```
idle → 检测目标（YOLO + 深度反投影）→ 更新目标位姿
     → pre-grasp（目标上方，朝下姿态）→ grasp（闭合状态机，复用 RL 侧语义）
     → lift（抬升 lift_height）→ place（放置位）→ 返回 ready
```

## 5. 动态层（RL 残差）设计

### 5.1 观测空间

```
obs = [
  机械臂状态（关节位置/速度，末端位姿/速度），           # 现有 58 维中的状态部分
  目标感知特征（3D 位置 + 置信度/噪声方差），            # Phase 2 由 oracle 改为感知
  深度图/点云降维特征（最近障碍距离 + 方向向量），       # Phase 2~4
  标称轨迹参考速度（twist），                           # 残差策略必要输入（Phase 2 预留）
  障碍物相对位姿 + 速度（Phase 4 引入），                # 动态障碍
]
```

设计原则：
- **先保持动作/奖励不变，只换观测**（Phase 2 降级方案），隔离变量。
- 深度图不进全分辨率（训练慢），用**降维特征**（最近障碍距离/方向/聚类质心）优先，CNN 编码器作为后续增强。

### 5.2 动作空间（残差速度）

```
a = Δv_ee ∈ R³（末端速度残差增量，m/s）
执行：v_servo = v_nominal(t) + Δv_ee
      → MoveIt Servo（twist 命令，限幅 v_max = 0.125 m/s）
```

与现有 RL 系统的衔接（已在 `config.py` 定义）：
- `max_ee_delta=0.005`、`action_repeat=2`、`control_freq=50Hz` → 决策周期 25Hz（动态场景需提频，见 §7）。
- 速度级 IK + 速度 PID 执行语义保留，训练/部署两端一致。

### 5.3 奖励设计（在现有 `reward.py` 基础上扩展）

| 项 | 现有 | Phase 4 新增 |
|---|---|---|
| 接近/抓取 | ✅ 距离势能塑形、方向项、接触、抓取门控 | 不变 |
| 动态避障 | — | 障碍物接近惩罚（随距离指数增长） |
| 碰撞 | — | 碰撞立即终止（terminated），大负奖励 |
| 安全距离 | — | 保持与障碍最小距离 ≥ 安全阈值的势能项 |
| 残差量 | — | 残差幅度正则（鼓励少修正，仅动态时出手） |

### 5.4 课程学习

```
静态 → 慢速单障碍（≤0.3 m/s）→ 中速（≤0.6）→ 多障碍快速
每级达标（成功率 ≥ 阈值）再升级；MuJoCo 与 Gazebo 障碍同构，保证域一致。
```

## 6. 安全层（独立实时）

- **CBF 式约束**：基于最近障碍距离 d 与相对速度，求解最小修正量使 d 保持在安全区内（实时可解的最小二乘/二次规划）。
- **速度/力矩限幅**：关节速度上限、末端 v_max、力矩饱和（复用 UR 侧安全限速语义）。
- **分离距离监控**：ISO/TS 15066 风格，距离过近 → 先降速后停机。
- **实现位置**：独立节点，订阅机械臂状态 + 最近障碍距离，发布安全修正/急停信号。**训练期即模拟限幅**，保证部署一致性。

## 7. 接口契约（两世界打通的核心）

### 7.1 URDF ↔ MJCF 对齐表（Phase 0 建立，示例）

| 项 | MoveIt2 (URDF) | MuJoCo (MJCF) | 说明 |
|---|---|---|---|
| 关节名 | shoulder_pan_joint … wrist_3_joint | 同左（UR5e 六关节） | 需核对大小写/前缀 |
| 末端坐标系 | `rq_base_mount` | 同左 | `_find_components` 依赖 |
| 夹爪测量 | `rq_pad_left/right_site` | 同左 | 抓取宽度语义 |
| 动作语义 | Servo twist（m/s, rad/s） | 末端速度增量（m/s） | **必须一致** |
| 速度上限 | UR 安全限速 | `v_max = 0.125 m/s` | sim2real 契约已定义 |

### 7.2 动态避障的频率需求

| 模式 | 决策频率 | 说明 |
|---|---|---|
| 静态抓取 | 25Hz（现状） | 足够 |
| 动态避障 | 50~100Hz | 需减小 `action_repeat`，Servo 实时模式 |

## 9. 里程碑与验收汇总

| 阶段 | 核心验收 |
|---|---|
| P0 | 两系统运行基线 + 对齐表 |
| P1 | 静态抓取 ≥95%；静态避障 ≥90%（随机 50 场景 ≥85%） |
| P2 | 感知噪声下成功率下降 <10% |
| P3 | 轨迹相似度 >90%；两端成功率差 <15% |
| P4 | 动态成功率 ≥70%；碰撞率 <5% |
| P5 | 动态 ≥80%；静态不劣于纯 MoveIt2 的 90% |
