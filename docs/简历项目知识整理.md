## 0. 叙事定档（先读这一节：为什么这么讲）

一个项目最忌「头重脚轻」——把最没做完的部分顶在最前。本项目的排序是**按完成度**，不是按技术炫酷度：

| 档位 | 叙事 | 完成度 | 定位 |
|---|---|---|---|
| **P1 头条** | **残差 RL 抓取（速度场标称）**：静态 100% / 动态 90% / 动态+障碍 86.7%，三路消融残差全场景最优 | ✅ 完整闭环、有 checkpoint、可复现 | 项目的主线，简历第一段 |
| **P2 第二叙事** | **RL+MPC（标称层升级为运动学 MPC）**：定位残差饱和根因 → cap 解耦 → 高密度障碍碰撞 34×↓；但**残差没在成功率上打赢纯 MPC**、static3 未解 | ⚠️ 部分成功 / 进行中 | 诚实交代，展示「会归因、会验证、会止损」 |
| **P3 技巧叙事** | **peg-in-hole**：评审成功判据时发现判据缺陷 → **主动撤回数字**重修 | ⚠️ 数字撤回、只讲方法论 | 证明「报数前先验证自己的指标」 |

**为什么敢投**：招 RL 运动控制实习，最看的不是「你有没有一个全绿的 SOTA」，
而是「你能不能把一个复杂系统拆开、归因、验证、并在该收手时收手」。P1 给结果，P2/P3 给判断力。

## 1. 一句话项目介绍

> 在 MuJoCo 中搭建 UR5e + Robotiq 2F-85 机械臂抓取环境，采用**混合残差架构**
> （标称层 + PPO 残差修正，`v = v_nominal(t) + Δv`），两代演进：
> - **第一代（速度场标称，P1，已完成）**：两段式速度场标称轨迹 + PPO 残差，动态抓取
>   **静态 100% / 动态目标 90% / 动态+障碍 86.7%**（n=30 确定性），三路消融验证残差全场景最优；
> - **第二代（MPC 标称，P2，部分成功/进行中）**：标称层升级为**运动学 MPC**（SLSQP 滚动最优控制，
>   `mpc_nominal.py`）；定位残差饱和根因（奖励经济学账）→ **残差预算与 MPC 可行域解耦**
>   （cap 0.125→0.05 m/s）→ 高密度障碍场景**平均碰撞 34×↓**（mixed3 40.03→1.17，mixed_z 25.57→0.73）。
>   诚实边界：cap 解耦是**安全增益而非成功率增益**——残差在成功率上未打赢纯 MPC（动态+障碍 76.7% vs 纯 MPC 90.0%），
>   且 static3 场景全版本 0%（根因指向 MPC `D_SAFE` 几何拒行，未解）。
>
> **一句话的自我定位**（面试可直接说）：*我的项目不是「RL 打赢了 MPC」，而是「一个能诊断、能验证、
> 也知道自己边界在哪的混合控制闭环」。*

## 3. 核心知识点分层（面试考察点）

### 3.1 机器人学基础
- **正运动学**：由关节角求末端位姿（MuJoCo `mj_forward` / `mj_jacBody` 隐式完成）。
- **逆运动学（IK）**：位置级 DLS 迭代（`ik.solve_ik`，500 次迭代 + 停滞提前退出）
  与 **速度级 IK**（`velocity_ik`，雅可比阻尼伪逆）的区别与取舍：
  - 位置级：迭代慢（目标不可达曾 0.84s/步 → 修复到 ~9ms）、适合一次性求关节目标；
  - 速度级：`dq = Jᵀ(JJᵀ+λ²I)⁻¹v` 单步矩阵运算、快、奇异鲁棒、语义与真实 Servo 一致。
- **雅可比阻尼伪逆**：λ（`velocity_ik_lam=0.08`）在奇异附近抑制速度爆炸（对应实机奇异降速）。
- **奇异点**：UR5e 已知奇异位形（肘伸直 elbow≈0、腕奇异 wrist_2≈0）检测 + 渐进回安全位形；
  `manipulability`（雅可比条件数）进观测。
- **四元数**：乘法/共轭/旋转向量↔四元数/相对接近姿态 `q_rel = q_target ⊗ q_ee⁻¹`（P2-2 显式给策略对齐误差）。
- **末端执行器 + 夹爪状态机**：两指夹爪“近距自动闭合状态机”（open→closing→closed），
  抓取成功 = 手指被物体挡住合不上（开度仍 > 阈值 + 双指接触确认）。

### 3.2 强化学习核心
- **PPO**：裁剪目标、GAE 优势估计（λ=0.95）、熵系数 0.01、Actor-Critic 双头网络 [512,512,256]。
- **MDP 设计**：
  - 观测 67 维：关节位置/速度/力矩(18) + 夹爪(3) + 末端位姿/速度(13) + 目标(7) + 可操作度/接触力/手指力(7) + 相对接近四元数(4) + 夹爪相位(1) + **标称参考速度(6) + 障碍相对位姿/速度(6)**（残差策略关键输入，第一天即最终形态）；
  - 动作 3 维位置增量（`action_space_dim=3`，姿态固定朝下——**6D 姿态学习已验证无信号**，见失败回顾）；
  - 奖励 = 势能塑形（距离 + 近距离锚定 + 朝向）+ 事件奖励（接触/闭合/抓取/完成）+ 步惩罚 + 障碍接近惩罚 + 残差幅度正则。
- **势能塑形（Potential-based Shaping）**：`r = Φ(s_prev) − γ·Φ(s)`，单步有界、不改变最优策略、
  消除“300 步累计 −800 淹没成功 +16”的尺度问题（P1.3 修复）。
- **奖励经济学**：穿障负收益 < 成功正收益 → 穿障是理性解；`obstacle_clear_bonus`（干净成功奖励）
  把“绕障再抓”变为独立正收益。
- **观测归一化**：SB3 `VecNormalize`（obs_rms 单独存 pkl——SB3 的 zip **不含** obs_rms，
  必须单独保存恢复，否则评估失配乱走）。
- **课程学习**：固定位置 → 小半径随机（±3cm）→ 扩范围；障碍数量 1→2；warm-start 续训。
- **迁移学习（warm-start）**：55→67 维观测的“输入层手术”（`scripts/migrate_d1_checkpoint.py`，
  新槽位权重 0 + obs_rms 先验 0/1，行为逐 bit 不变）——也埋下了“感知锁死”的坑（见失败回顾）。

### 3.3 MuJoCo 仿真
- **MJCF**：`<body>/<geom>/<joint>/<site>/<camera>/<tendon>/<actuator>` 组织；
  UR5e 六关节 + 2F-85 夹爪（8 个 rq_*_joint 须从臂关节中排除）。
- **自由关节 freejoint**：目标物体/障碍用 freejoint 承载，`qvel` 赋值实现可编程运动（动态目标/动态障碍）。
- **接触与碰撞检测**：`data.contact` 查询臂-障碍碰撞；衬垫 `site_xpos` 测量抓取宽度/接触力。
- **执行语义**：`control_freq=50Hz`、子步 `timestep=0.002×substeps`；
  `action_repeat=2`（决策 25Hz）解决“小增量实现率仅 8%”问题（见失败回顾）。
- **渲染**：GUI（GLFW）与离屏（EGL）分离；`mujoco.Renderer` 深度图直接给物理距离（米）。

### 3.4 控制与执行层
- **速度 PID + 重力/惯性前馈**：`τ = kp·(v_target − v) − kd·qvel + gravity + inertia`，
  按关节标定增益（肩/肘 200，腕 100/60）；阻尼项抑制微颤。
- **冲击抑制**：末端接近物体限速（`approach_speed_limit=0.12`）+ 动作一阶低通平滑（对应 Servo smoothing）。
- **残差执行语义**：`v_raw = v_nominal(t) + Δv/T`，再限幅到 `v_max=0.125 m/s`——训练/部署两端一致。

### 3.5 架构设计（本项目最大卖点）
- **为什么残差 RL**：Residual RL（Johannink et al. 2018）——RL 只学“偏差”而非重学整个任务；
  业界对应 RMA（Xia et al. 2021）、波士顿动力 Spot。
- **为什么不用端到端**：8 版端到端“抓取+避障联合”失败归因 → 奖励经济学（成功奖励绑架碰撞惩罚）
  与探索动力学（碰撞终止掐死试错路径）是**结构性矛盾**，调参不可解 → 必须任务分解。
- **分工**：标称层（确定性、可审计、静态避障）解决“规划内”；RL 残差解决“规划外”
  （动态目标追踪、动态障碍避让）；安全层（CBF 式限幅）独立兜底。
- **两代标称层演进**：① 速度场（仿真替身两段轨迹，**非 MoveIt，是自实现的仿真替身**）→ ② **运动学 MPC**
  （SLSQP 滚动最优控制，`v_max=0.125` 契约速度，`mpc_nominal.py`）。MPC 阶段的关键洞察：
  **残差预算必须与 MPC 可行域解耦**（v25b2 cap 0.125→0.05 m/s = MPC 40%）——满幅残差与 MPC 同级时是
  「破坏源」，解耦为微调后成「有限增益源」（高密度障碍平均碰撞 34×↓）。残余教训：**纯奖励权重（L1 三件套）
  拉不动 warm-start 的满幅习惯**，下一步需结构性门控（Δv=gate·π）。
  **但必须同时说清**：解耦带来的是**安全增益，不是成功率增益**（mixed3 成功 0%→6.7%，mixed_z 13.3% 持平；
  dyn_both 残差 76.7% 仍低于纯 MPC 90.0%）——这条比数字本身更能体现判断力。
- **sim2real 视角（设计，非现状）**：速度级 IK + Servo 叠加语义与真机 MoveIt Servo 的 twist 接口同构
  （**训练侧从未调用 MoveIt，MoveIt 只出现在部署端设计**）；训练端用“等价感知观测”（噪声/漏检模拟相机误差）
  而非全分辨率深度图——感知特征接口契约两端对齐。真机部署是明确后续阶段。

### 3.6 工程实践
- **多进程并行**：SubprocVecEnv + `fork`（Linux）、worker 无头、主进程统一写监控；
  吞吐 70.9 步/s vs 单进程 7.7（↑9.2×）。
- **监控与早停**：episode 奖励/成功率/奇异点/训练趋势（最近 10 vs 前 10）；
  `VecNormalize` 保存、CheckpointCallback 崩溃恢复（曾因 GLFW demo 窗口 segfault 丢过模型）。
- **评估方法论**：确定性评估（`deterministic=True`）、场景矩阵（静态/动态目标/动态+障碍）、
  n=30、失败模式分类（超时 vs 碰撞 vs 奇异）、三路消融、`--zero-residual` 纯标称 baseline。

## 5. 整体搭建过程（分阶段）

### Phase A：基础环境（P0）
- 选定 UR5e + Robotiq 2F-85（MJCF），从 home 位形开始；物体位置固定 → 随机化
  （`workspace_bounds` + IK 可达性打点验证，`scripts/verify_radius_006_reachability.py`）。
- **教训**：桌面半边长曾 0.45 → 伸入上臂活动区产生 356 N·m 约束压崩速度环 → 缩到 0.24，
  后扩大桌面时保持 Y 下界 0.18 不碰下臂。

### Phase B：奖励与收敛（P1）
- 距离项去饱和（线性势场）、方向项改四元数对齐 cos(θ)、P1.3 改**势能塑形**（解决奖励尺度爆炸）。
- **P2-2**：显式给“相对接近姿态四元数”进观测（方向任务从“合成”变为“直读”）。

### Phase C：动作空间重构 + 执行层（P3/P4/P5）
- 6D（位姿增量）→ **3D（仅位置、姿态固定朝下）**：6D 姿态维度无学习信号（w_orient 时梯度为 0 实证）。
- 位置伺服 → **速度级 IK + 速度 PID**：小增量实现率 8% → 96%（动作真正“推得动”）。
- **action_repeat=2**：决策 25Hz、每步物理 0.04s，小增量实现率 23%（↑3×）。
- P3.1 IK 卡顿修复（不可达 0.84s → 9ms）；P4 抬升速度标定（0.003 m/s 物体 100% 刚性跟随）。

### Phase D：并行化 + 监控（2026-08-22）
- 12 进程 SubprocVecEnv + fork、无头 worker、主进程监控、演示窗口与训练进程分离。
- 吞吐 7.7 → 70.9 步/s（↑9.2×），可跑 60 万步级训练。

### Phase E：端到端 8 版失败（→ 架构转折点）
- v5→v12b 连续失败，产出四类机制归因（详见 §6.1）→ **决策：改残差架构**。

### Phase F：残差架构 + 动态化地基（D1，2026-08-24）
- `action_mode: delta|residual` 开关；标称速度场；观测扩到 67 维（+6 标称速度 +3 障碍位姿 +3 障碍速度）；
  动态目标/障碍可编程；55→67 迁移工具。

### Phase G：动态抓取闭环（v13→v15，2026-08-27）
- per-episode 场景采样（40% 静态 / 30% 动态目标 / 30% 动态+障碍）；
  两段标称轨迹（先到高处再垂直下降，静态 60%→90%）；
  residual_reg 0.5→1.5（压掉“残差饱和干扰标称”）。
- **Week1 交付**：静态 96.7%、动态 0.05 83.3%、动态+障碍 90%。

### Phase H：双障碍达标（v16→v18，2026-08-28）
- 碰撞经济学（penalty/obstacle_w/clear_bonus）逐步强化；双障碍训练占比 80%；
  **v18：1 障 83.3%、2 障 90%、碰撞 26.7%（达标模型）**。

### Phase I：证伪与交付（v19/v20 + 消融，2026-08-28）
- v19（强惩罚）保守瘫痪 / v20（折中）策略震荡 → **证明 v18 是当前架构 Pareto 前沿**；
- 三路消融对比 + 对比图 + 深度相机基础设施（眼在手外渲染、桌面扩大）。

### Phase J：MPC 标称 + 残差饱和修复（v24→v25b2，2026-09-07~09）
- 标称层替换为**运动学 MPC**（SLSQP 滚动最优，`mpc_nominal.py`），单变量对照 v23（v24_mpcres）；

  （满幅成本 18.7/集 ≪ 成功 +130）+ 残差预算与 MPC v_max 同级（可完全覆盖安全速度）。
- **v25 三路修复**（`docs/2026-09-08_残差饱和分析与奖励重塑方案.md` §10 完整记录）：
  1. **cap 解耦**（0.125→0.05 m/s = MPC 40%）→ **机制验证成功**：v25b2 实测 mixed3 平均碰撞

  3. **5 场景高密度课程**（~25% episode 高密度障碍）→ 高密度障碍从零样本硬扛变为可解。
- **v25b2（最新，结构门控）**：Δv=gate·π，门控常态关死残差（static3 res≡0）、关键帧触发。
  六场景实测：static 90% / dyn_target 80% / dyn_both 76.7% / static3 0% / mixed3 6.7% / mixed_z 13.3%。

  增益巨大。static3 的 0% 仍未解（根因指向 MPC `D_SAFE=0.20` 几何拒行）。

  dyn_both D=4 时残差 50.0% vs 纯 MPC 36.7%（**Δ=+13.3pp**）；dyn_target D=4 时 +3.3pp；

  如实写「方向一致但未达显著，需 n≈300/arm 才能确证」。详见数字真值表 §4。

## 6. 失败回顾（面试最值钱的部分）

### 6.1 八版端到端失败（“RL 同时学抓取+绕障”全败）

| 版本 | 配方 | 成功率 | 碰撞率 | 失败机制 |
|---|---|---|---|---|
| v5 | 无碰撞惩罚 | 74% | **98-99.5%** | A 无信号：策略完全不感知障碍 |
| v6 | +penalty -2 | 79% | 65.5% | B 奖励经济学：穿障 -30 < 成功 +100 |
| v7/v8 | penalty -5 + 随机化 | 69.5% | ~57% | 强信号伤成功率、碰撞不降 |
| v9/v10 | **从零** 训练 | 0.5-5% | 7.5-23% | 多任务干扰：避障压过抓取，抓取长不出来 |
| v11 | 权重注入解锁感知 | 68-71.5% | 53-62% | C 感知锁死（可破）但 B 经济学死结未解 |
| v12/v12b | 碰撞即失败（终止） | 15-25% | 71% | D 探索压死：episode 均 25 步，无试错路径 |

**四类独立机制**（每条都能展开讲）：
- **A 无信号**：`collision_penalty=0` → 最优策略就是无视障碍（证据：碰撞 98-99.5%）。
- **B 奖励经济学（结构性）**：穿障平均 -90 < 抓取 +120 → RL 的理性选择就是穿障；调惩罚只会
  “压制哪种失败”而不是“创造好行为”（v7/v19 两次独立复现：成功率掉一档）。
- **C 感知锁死（warm-start 特有）**：探针实验（改观测槽位看输出 diff=0）证明 actor 输入层障碍权重
  norm 0.178（≈0，完全忽略）；value 网络却感知（12.1）——“评估到风险但策略不管”；
  权重注入（randn×0.1）解锁感知，成功率保留但碰撞不降。
- **D 探索压死（结构性）**：碰撞即终止剥夺“碰→退→绕”试错路径，学习动力学崩坏。

**结论**：B 与 D 只要“RL 承担抓取+避障双目标”就永远存在 → **必须任务分解**
（确定性标称层管规划内、RL 残差只管规划外动态修正；部署侧这层由 MoveIt 承担）。

### 6.2 v19/v20 碰撞经济学强化失败（“再压碰撞率”证伪）
- v19（penalty -15/w4/bonus+40）：2 障成功率 63.3%（-26.7pp），11 失败全超时、5 个 coll=0 = “不敢动”。
- v20（折中）：2 障碰撞率 36.7%（**比 v18 还高 10pp**）——warm-start 扰动 + 折中惩罚两头不讨好。
- **结论**：v18（penalty -10/w3/bonus+30）已是“成功率×碰撞率”联合 Pareto 最优点；
  进一步压碰撞必须换维度（观测升级全障碍 / 延长训练 / 速度感知），而不是调经济学。

### 6.3 工程层失败与修复（体现诊断深度）
| 症状 | 诊断 | 修复 |
|---|---|---|
| 训练 0% 成功 | 小增量实现率仅 8%（伺服过阻尼追不完） | 速度级 IK + action_repeat=2 |
| 仿真卡顿 | IK 目标不可达时 5000 次迭代跑满（0.84s/步） | iters→500 + 停滞提前退出（→9ms） |
| 策略“悬停”不下降 | 奖励塑形：下降边际收益 < 步罚 | 近距离锚定势能（斜率变陡） |
| 物体被“撞下桌面” | closing 阶段单侧压着 cube 侧向推挤 | 接触力阈值停止 XY 微调 + Z 微降安全条件 |
| 6D 动作不学姿态 | 姿态维度 w_orient 时梯度为 0（实证） | 降维 3D（姿态固定朝下） |
| 纯标称抓不到 | 单段速度场直插会扫过 cube | 两段标称轨迹（先高处水平对齐再下降） |
| 抬升物体滑移 2cm | 伺服/动态滞后非几何极限 | lift_speed 0.005→0.003（100% 刚性跟随） |
| 失败全超时（消融） | 端到端“没学会到达”而非“撞坏” | 无碰撞终止、无奇异 → 证据：final_dist 大 |

### 6.4 失败分析方法论（简历可写“归因能力”）
1. **单变量原则**：每版只改一个配方因子，归因干净；
2. **探针实验**：改观测槽位看策略输出 diff → 区分“感知问题”vs“奖励问题”；
3. **机制分类**：四类独立机制，分别破解/证伪；
4. **学习动力学视角**：不只盯最终指标，看 episode 长度（v12 均 25 步是死因信号）；
5. **负结果也是结果**：v19/v20 完整负证据链 → 路线级决策（停止调参、换维度）。

### 6.5 v24/v25 残差饱和：失败→归因→机制验证（MPC+RL 阶段，2026-09-08/09）

- **现象（v24）**：avg_residual_norm 全场景恒 ≈0.2165 = clip 上界（√3×0.125）——策略学到「恒定满偏置」
  而非「状态→修正量」映射；高密度障碍安全崩塌（mixed3 coll 86.7%、avg_coll 40.03）。
- **根因 = 奖励经济学（与 6.1-B 同型）+ 权限超界**：满幅残差 L2 惩罚仅 ~18.7/200步 ≪ 成功 +130 →
  残差「几乎免费」，PPO 的 tanh 高斯策略在 Q 梯度指向边界时自然停在 clip；且残差预算（±0.125）与
  MPC `v_max`（0.125）**同级**，满偏置可完全覆盖 MPC 刚算出的安全速度 → SLSQP 每步重算也追不回 → 反复碰撞。
- **v25 三路修复 → 单变量逐一验证**：
  1. **cap 解耦**（0.125→0.05 m/s = MPC 40%）→ **机制验证成功**：v25b2 实测 mixed3 平均碰撞
     40.03→1.17（**34×↓**）、mixed_z 25.57→0.73（**35×↓**）——安全属性质变，证明「残差与 MPC 同级
     是破坏源，解耦后成有限增益」；**但成功率几乎未提升**（mixed3 0%→6.7%、mixed_z 13.3% 持平）
     ——这是本项目最诚实的一条结论：**解耦买到的是安全，不是成功率**；
  2. **L1 稀疏三件套**（L2+L1+激活步罚）→ **完全未生效**：res 恒 = 新 cap 满幅，0.2165→0.0866
     的降幅全部来自 cap 机械缩小。教训：**纯奖励权重拉不动 warm-start 继承的满幅习惯**
     （L1 满幅成本 60 < 成功 130，残差满幅在训练中仍有助于成功）；
  3. **5 场景高密度课程**（~25% episode 高密度障碍）→ 高密度障碍从零样本硬扛变为可解。
- **残差 vs 纯 MPC 的正面对比（必须主动交代）**：n=30 下纯 MPC 动态+障碍 90.0%、动态目标 83.3%，
  而 v25b2 残差是 76.7% / 80.0%——**残差在成功率上没有打赢纯 MPC**。本项目的价值不在「RL 赢 MPC」，
  而在「把两者接起来 + 定位出安全瓶颈在残差权限而非 RL 本身」。
- **方法论升级**：从「负结果证伪」（6.1/6.2）到「机制验证」（v25 三路逐一验证 + 诚实记录 L1 负结果）→
  修正判定为「有条件 Go」，转向**结构性门控**（Δv=gate·π）+ **模型失配鲁棒性验证**（执行延迟），
  而非再加权重。延迟实验已完成：方向一致但 n=30 未达显著（真值表 §4）。

> ⚠️ **数字纪律**：v25 早期版本曾报「40.03→0.40（100×↓）」与「mixed3 20%/23.3% 可用」，
> 但其 JSON 已丢失、无法复现；保留 artifact 的是 v25b2 实测 1.17（34×↓）。**面试只讲 34×/35×。**

## 8. 面试刁难问题准备（Q&A）

**Q1：为什么不用 Isaac Sim / 真机？**
> 仿真先行用于隔离变量：先证明奖励设计与控制架构正确（真机成本高、不可回滚）；
> 仿真栈与真机栈已对齐（速度级 IK + Servo twist 契约、v_max=0.125m/s、sim2real 文档化），
> 真机部署是明确的后续阶段（MoveIt2 + RealSense 深度相机 + 手眼标定路线已写）。

**Q2：观测为什么是 oracle（上帝视角）？**
> 刻意拆分“感知-控制”两通道：先证明控制层收敛（oracle），再用感知噪声/漏检量化感知容忍度——
> 工程方法而非偷懒。**2026-09-10 已做固定种子配对重跑**（`results/perception_seeded/*.json`，
> 真值表 §5）：v18_p3f，dyn_both 场景，`--seed 12345`、n=50/臂，四路剂量-响应（σ=0.01/0.02/0.03）
> + 两路漏检（σ=0.02 + 10%/20% 丢帧）。结果：**σ≤3cm / 漏检≤20% 下未观测到成功率的系统性下降**——
> Δ 在 [−8, +2]pp 间来回摆、无单调趋势，n=50 下单格标准误约 9.5pp，**所有差异均不显著**——oracle
> 不是瓶颈的探测性证据；深度图渲染基础设施也已就位（眼在手外相机 + 降维特征，两端感知接口契约）。
> *（口径提醒：严格意义的「感知鲁棒」需要更大 n 或更噪声量级，此处只能说「未观测到系统性下降」。
> 原 2026-08-28 D6 那组 73.3%→73~90% 的数字**已弃用**——它无种控、且 oracle 对照重跑反而低于带噪臂，
> 是感知噪声与场景随机源共用 RNG 造成的假象；该 bug 已修复。
> **另一处口径限制**：感知噪声/漏检这两个开关是 2026-09-08 之后才加进环境的，钉住的复现 commit `cadd00e`
> 里没有，所以本探测只能在 HEAD 默认口径下跑——此刻基线是 **66%**，而非 v18_p3f 的原生 **78%**（原因见
> `数字真值表_20260910.md` §6）。四路剂量共用同一基线，**剂间比较仍自洽**，但绝对水平偏保守，
> 不能把 66% 当 v18_p3f 的成绩读。）*

**Q3：对比过端到端吗？数据会不会是“你端到端没训好”？**
> 三路消融 n=30 正式对比：**残差三场景全部第一**；端到端整体最弱（8-28 版全场景最低，
> 但 9-10 现场复现时端到端数值上浮、dyn_target 上略高于纯标称——**所以稳妥话术是「残差三场景最优」，
> 不是「端到端全场景最差」**）。且 8 版端到端（不同配方：惩罚强度/终止/从零/权重注入）全部失败，
> 归因为**结构性机制**（奖励经济学 + 探索动力学）而非调参问题；残差架构下这两类矛盾被任务分解天然消解。

**Q4：碰撞率 26.7% 不高，为什么不压下去？**
> v19/v20 用 120 万步证明：在单网络+最近障碍观测架构下，进一步提高碰撞经济学只会破坏
> 成功率（v19 保守瘫痪 / v20 策略震荡），v18 已是 Pareto 前沿；压碰撞的正确方向是换维度
> （全障碍观测 / 障碍速度感知），而不是调奖励权重——这个“知道何时停止调参”本身是判断力。

**Q5：奖励函数是你设计的吗？讲讲 reward shaping？**
> 势能塑形 Φ(s_prev)−γ·Φ(s)：单步有界、不改变最优策略、解决奖励尺度爆炸；
> 近距离锚定（斜率变陡）修复“悬停”；障碍接近惩罚 + 残差幅度正则；诊断键（orient_align 等）
> 与奖励键分离（曾经 sum(values()) 把诊断键泄漏进奖励的教训）。

**Q6：动态障碍避障，观测里没有障碍速度吗？**
> 有的，67 维含障碍相对位姿(3) + 速度(3)；动态目标还加了速度前馈（k_ff=1 完全补偿）
> 抵消 P 控制稳态滞后；残差策略正是靠这些槽位学“绕障”。

**Q7：多进程训练细节？**
> SubprocVecEnv + Linux fork（避免 forkserver 的 __main__ 依赖）；worker 无头
> （render_gui=False，避免 fork 后继承 GLFW/X 连接触发 XIO fatal）；Monitor 在 worker 内、
> 主进程统一写监控 JSON（多进程写同一文件会冲突）；demo 环境在主进程、先 fork 再创建
> （否则子进程继承 GLFW 连接）。

**Q8：sim2real 你做了什么实质工作？**
> 执行层语义对齐（速度级 IK 阻尼伪逆 = Servo twist；v_max 契约）；动作低通平滑 =
> Servo smoothing；接近限速 = 实机慢速 Servo；观测归一化 stats 单独保存（避免评估失配）；
> 训练端“等价感知观测”（噪声/漏检）与部署侧相机特征接口契约。

**Q9：v24 残差为什么饱和？**
> 奖励经济学：满幅残差 L2 惩罚 ~18.7/200步 ≪ 成功 +130 → 残差几乎免费，PPO 的 tanh 高斯策略在
> Q 梯度指向边界时停在 clip（avg_residual_norm 恒 = clip 上界 √3×0.125=0.2165）；且残差预算与 MPC v_max
> 同级（±0.125），满偏置可完全覆盖 MPC 安全速度 → 高密度障碍反复碰撞（mixed3 coll 86.7%）。

**Q10：cap 解耦为什么能把碰撞降一个量级以上？**
> 残差从「可覆盖 MPC」降为「微调」（cap 0.125→0.05 m/s = MPC 的 40%），满幅也推翻不了 MPC 刚算出的安全
> 速度方向 → 避障规划主导 → v25b2 实测 mixed3 平均碰撞 40.03→1.17（34×↓）、mixed_z 25.57→0.73（35×↓）。
> 机制层面证明：**安全瓶颈不在 RL，在「残差权限」**。
> ——但要诚实补一句：**它买来的是安全，不是成功率**（mixed3 成功 0%→6.7%，mixed_z 持平）。

**Q11：L1 稀疏为什么失败？残差还是满幅？**
> 诚实负结果：avg_residual_norm 恒 0.0866（=新 cap 满幅），L1+step 三件套没让策略稀疏。原因：L1 满幅成本
> 200 步 ≈60 < 成功 130，训练中残差满幅仍有助于成功；warm-start 自 v24 的满幅习惯 + 300k 步不足以拉回。
> 结论：纯奖励经济学无法克服成功吸引，需要结构性机制（门控），不是权重问题——「知道失败在哪、为何失败」。

**Q12+：说了这么多，你的残差 RL 到底有没有打赢纯 MPC？**（面试官大概率会直接问）
> **没有。** n=30 确定性评估下：动态+障碍 纯 MPC 90.0% vs 残差 76.7%；动态目标 83.3% vs 80.0%。
> 我从不把它讲成「RL 打赢 MPC」。这个项目的价值是三条：
> ① 我把 MPC 和 RL 真正接起来了（同一个闭环里标称层 → 残差层，语义一致）；
> ② 我定位出安全瓶颈是**残差权限**而不是 RL 能力（cap 解耦前后碰撞差 34 倍，而 RL 权重改动 L1 完全无效）；
> ③ 我知道它没赢，并且说得出为什么、下一步该怎么验证（模型失配域 + 结构门控）。
> ——**能诚实报出「我的方法没赢」并给出机制解释，比报一个漂亮但站不住的数更有说服力。**

**Q12：下一步门控（Δv=gate·π）怎么设计？**
> gate 由 MPC 可行性信号驱动：SLSQP 无解/裕度低/预测碰撞/接近目标时开放残差预算（MPC 无解时放大 cap 补
> static3），常态 gate≈0 → 同时治「简单场景回退」（残差不干扰最优轨迹）、「饱和」（残差真稀疏）、
> 「MPC 卡死」（无解时允许突破）。已在 v25 数据中定位到需要它的证据（L1 纯权重路线被证伪）。

## 11. 六个核心问题的完整答案（面试可直接展开讲）

> 本章把散落在 §3/§5/§6/§8 的知识组织成**六个必问问题的完整答案**，

### 11.1 仿真环境如何搭建

**步骤（对应代码：`environment.py` + `models/universal_robots_ur5e/`）**

1. **选基座模型**：UR5e 六轴 + Robotiq 2F-85 两指夹爪（官方 MJCF），保留真实关节名/几何/惯性，
   为 sim2real 保留语义（真机部署对应 ROS2 MoveIt2 的同一 UR5e URDF）。
2. **改造场景**（`ur5e_robotiq_cube.xml` + 生成脚本 `make_cube_scene.py`，产物与手改 diff 为空 = 可复现）：
   - 桌面：半边长 0.35、中心 (0.1, 0.53)、顶面 z=0.30（0.70m 见方接近真实实验台）；
   - 目标立方体：freejoint 承载 → reset 时 `_set_object_position` 设 qpos 即可随机/固定位置；
   - 障碍体 ×3（`obstacle/obstacle_2/obstacle_3`）：同样 freejoint，可编程运动（随机游走/往返）；
   - 眼在手外相机（Phase 2 感知基础设施）：`mode="track"` 对准工作区中心，深度渲染可提取降维特征。
3. **环境类初始化**（`GraspingEnv`，`environment.py`）：
   - `_init_mujoco` 加载模型；`_find_components` 定位臂关节（须排除 2F-85 的 8 个 rq_*_joint）、
     末端 body（`rq_base_mount`）、衬垫 site（`rq_pad_left/right_site`，测量抓取宽度与接触）；
   - `_setup_spaces` 定义 Box 观测(67) / Box 动作(3)；初始化奇异点处理器、夹爪状态机。
4. **执行层**：默认速度模式——RL 动作(增量) → 目标速度 → **速度级 IK**（雅可比阻尼伪逆）
   → 关节速度 PID + 重力/惯性前馈；另保留位置模式（旧行为，对照用）。
5. **夹爪状态机**：open → closing（对齐触发闭合）→ closed（手指被物体挡住合不上 + 双指接触确认）；
   失败（空闭合/滑脱）→ 重开重试（带滞回）。RL 不控制夹爪，只控制末端位置——任务分解的第一层。
6. **动态化地基**（D1 起就位）：目标 per-step 三角波往返、障碍随机游走，全部开关控制（L1 静止/L2 动态），
   观测槽位第一天就留好——环境自始为动态设计，不返工。
7. **验证闭环**（每个改动都要过）：
   - IK 可达性打点（`verify_position_randomization.py`：重置回 home 再解 IK，12/12 可达）；
   - 桌面-机械臂碰撞检查（home + 100 随机步接触 = 0、`qfrc_constraint` < 1 N·m）；
   - 执行层验证（`verify_ee_pose_control.py`：指令位移 vs 实际实现率、零漂移）；
   - 抓取成功判据验证（`verify_grasp_success_criterion.py`）；回归 `check_d1.py` 全断言。

**踩过的坑（面试加分）**：桌面半边长曾 0.45 → 伸入上臂活动区产生 **356 N·m** 约束压崩速度环 →
缩到 0.24，扩大桌面时保持 Y 下界 0.18 不碰下臂。教训：**场景几何必须与机械臂工作空间/安全距离联合设计**。

### 11.2 观测、动作和奖励如何设计

**观测（67 维，`_get_observation`）——设计原则："本体感知为主 + 显式给对齐误差 + 残差槽位第一天就位"**

| 段 | 维度 | 为什么 |
|---|---|---|
| 关节位置/速度/力矩 | 6+6+6 | 本体状态，PPO 学习"动力学"的最低信息 |
| 夹爪开度/速度/张力 | 1+1+1 | 状态机反馈 |
| 末端位置/四元数/速度 | 3+4+6 | 末端级状态（速度模式动作直接作用于此） |
| 目标位置/朝向 | 3+4 | 任务目标 |
| 可操作度/接触力/双指力 | 1+1+3+3 | 奇异/接触感知 |
| 相对接近姿态四元数 `q_rel` | 4 | **显式对齐误差**（P2-2：策略不用自己合成转角，直读） |
| 夹爪相位 | 1 | 状态机告知策略当前阶段 |
| **标称参考速度 v_nominal** | 6 | 残差策略关键输入（D1 就位，delta 模式占位 0） |
| **障碍相对位姿 + 速度** | 3+3 | 动态避障关键输入（D1 就位） |

**动作（3 维）——设计原则："只给末端位置增量，姿态/夹爪/时序交给结构化层"**
- `a = [dx, dy, dz]`（位置增量 m），经速度级 IK 反解关节速度执行；
- 为什么 3D 而不是 6D：**姿态维度在 w_orient 设置下梯度为 0（diag 实证）**，6D 白耗样本；
  姿态固定"朝下顶抓"（顶面抓取任务足够）；
- 限幅：`max_ee_delta=0.005`、`v_max=0.125 m/s`（对应 UR5e 安全限速与 MoveIt Servo 契约）；
- 夹爪/抬升由环境状态机接管（RL 只管"走到哪"，不管"怎么捏"）。

**奖励（`reward.py`）——设计原则："塑形单步有界、事件稀疏大额、惩罚表达经济学"**
```
r = Φ(s_prev) − γ·Φ(s)              # 势能塑形：距离(xy/z) + 近距离锚定 + 朝向
  + w_contact·[接触] + close_trigger + grasp_reward + completion_reward   # 事件奖励（上升沿一次性）
  − step_penalty                    # 时间惩罚
  − obstacle_w·(1−d/range)          # 障碍接近惩罚（连续）
  − residual_reg·‖Δv‖²              # 残差幅度正则（静态小/动态大）
  + obstacle_clear_bonus·[成功且0碰撞]  # v16 奖励经济学：绕障成功 > 穿障成功
```
- **势能塑形**：`Φ(s_prev)−γ·Φ(s)` 单步有界、不改变最优策略（Potential-based），解决"300 步累计 −800
  淹没成功 +16"的尺度爆炸（P1.3）；
- **近距离锚定**：`w·min(d/d_target,1)` 使近距离斜率变陡，修复"悬停不下降"（下降边际收益 < 步罚）；
- **奖励经济学**：穿障平均 −90 < 成功 +120 → 穿障是理性解，惩罚强度调不回来（v7/v19 实证）；
  干净成功 bonus 让"绕障再抓"独立正收益；
- **诊断键隔离**：`REWARD_KEYS` 只对奖励求和，orient_align/z_axis_z 等诊断键放 `diag` dict——
  曾因 `sum(values())` 把诊断键泄漏进奖励（方向项反向信号以系数 1 注入）导致修了不见效。


### 11.3 策略如何训练和评估

**训练管线（`train_with_monitor.py` + `agent.py`，PPO/Stable-Baselines3）**

1. **并行采样**：12 环境 SubprocVecEnv（Linux fork），worker 无头；吞吐 70.9 步/s（单进程 7.7，↑9.2×）；
   CPU 即可跑 60 万步级训练（单版 600k 步约 2-3 小时）。
2. **算法配置**：PPO——`n_steps=2048×12env`、batch 1024、`n_epochs=10`、lr 3e-4、clip 0.2、
   GAE λ=0.95、ent_coef 0.01、网络 [512,512,256]；**VecNormalize 观测归一化**（obs_rms 单独存 pkl，
   否则 SB3 zip 不含 obs_rms，评估失配乱走）。
3. **课程学习 + warm-start 迁移**（一步步放宽，每步"成功率不降"检查点）：
   - 阶段 0：固定位置从零训练基线；
   - 阶段 1：位置随机 ±3cm（`--position-random --radius 0.03 --load-model ...`）；
   - 阶段 2+：扩范围/加障碍（`--obstacle-count 1→2`）；55→67 维观测迁移用"输入层手术"
     （`scripts/migrate_d1_checkpoint.py`：新槽位权重 0 + obs_rms 先验，行为逐 bit 不变，并重建 optimizer
     解决 SB3 optimizer state 维度不匹配崩溃）。
4. **场景采样与防遗忘**：`--scenario-mix 0.4,0.3,0.3`（40% 静态无障 / 30% 动态目标 / 30% 动态+障碍）
   每 episode 采样，强制覆盖全局开关；障碍版加入 **~30% 无障碍混合采样**防"旧抓取技能被覆盖"。
5. **训练命令示例（对应 v13→v15 动态抓取闭环）**：
   ```bash
   python train_with_monitor.py \
     --action-mode residual --dynamic-target --target-vel 0.05 \
     --obstacle --obstacle-vel 0.05 \
     --scenario-mix 0.4,0.3,0.3 --obstacle-count 2 \
     --load-model models/xxx.zip --save-model models/v15_p3c.zip \
     --total-timesteps 500000 --no-demo
   ```
6. **监控**：TrainingMonitor 主进程统一记录（episode 奖励/成功率/奇异点/训练趋势=最近10 vs 前10）；
   `CheckpointCallback` 定期保存（崩溃最多丢 save_freq 步——曾因 GLFW demo 窗口 segfault 丢过模型，
   教训：长训练用 `--no-demo`）。

**评估管线（`evaluate.py`，面试要讲清楚"数字口径"）**

1. **确定性评估**：`agent.predict(obs, deterministic=True)`（去掉 PPO 采样噪声，可复现）；
   n=30/场景。
2. **场景矩阵**（与训练分布解耦，暴露泛化）：
   ```bash
   # 静态无障
   python evaluate.py --model_path models/v18.zip --action-mode residual \
     --scenario-mix 1,0,0 --n_episodes 30
   # 动态目标 0.05 m/s
   python evaluate.py --model_path models/v18.zip --action-mode residual \
     --scenario-mix 0,1,0 --target-vel 0.05 --n_episodes 30
   # 动态目标 + 动态障碍（产品场景）
   python evaluate.py --model_path models/v18.zip --action-mode residual \
     --scenario-mix 0,0,1 --target-vel 0.05 --obstacle-vel 0.05 --obstacle-count 2 --n_episodes 30
   ```
3. **失败模式分类**：每个失败 episode 归因——200 步超时（够不到/到不了位）vs 碰撞终止 vs 奇异
   vs 抬升失夹；只看成功率会掩盖"是没学会到达还是撞坏"。
4. **三路消融**（架构论证）：`--zero-residual`（纯标称 baseline）与端到端 v11 对比，脚本
   `scripts/run_ablation.sh` + `plot_ablation.py`，产出对比图（8-28 原始：静态 100/83.3/26.7、
   动态 90/66.7/63.3、动态+障碍 86.7/70/43.3，残差/纯标称/端到端；9-10 复现见真值表 §1，
   **可主张的是「残差三场景最优」，不是「端到端最差」**）。复现须跑在 pre-gating commit `cadd00e`。
5. **结果落库**：每个评估存 JSON（episode 级 summary：success/final_distance/collision_count/length），
   版本号管理（v5→v20），历史可追溯。


### 11.4 为什么可能实现 Sim2Real

> ⚠️ **本节是「设计论证」，不是「现状」**：训练侧从未接入 MoveIt、无真机、无真实相机硬件。
> 讲的时候务必加「设计上 / 待实现」——把设计讲成现状是面试里最容易被戳穿的地方。

**核心论点：本项目从"执行层、观测、架构、参数、感知"五个层面为 sim2real 做了对齐，不是仿真玩具。**

1. **执行层语义对齐（最关键，设计层面）**：仿真里 RL 动作 = 末端速度增量 → 速度级 IK（阻尼伪逆）→ 关节速度
   Servo。**这套语义与真机 MoveIt Servo 的 twist 接口同构**（都是 v_ee → Servo 执行，故部署时可对接）；
   `v_max=0.125 m/s`、`action_smoothing_alpha=0.7`（对应 Servo smoothing_filter）、
   接近限速（对应实机慢速 Servo）——训练时用的就是部署时的控制语义。
2. **观测对齐（本体感知为主）**：观测是关节位置/速度/力矩、末端位姿、目标位置等**本体感知量**，
   不是仿真特有量；唯一 oracle 的"目标位置"在部署侧由深度相机给出（感知接口契约：训练端等价感知
   观测 = 真值+噪声+漏检，两端特征分布一致，`docs/2026-08-28_深度相机分工与桌面扩大眼在手外.md`）。
   **感知噪声探测已落地并量化**：`perception_noise_std`/`perception_dropout`（观测通道加噪+漏检），
   2026-09-10 固定种子 n=50 配对四路重跑（`results/perception_seeded/*.json`，真值表 §5）——
   σ≤0.03m/漏检 20% 下**未观测到成功率的系统性下降**（Δ∈[−8,+2]pp，单格 SE≈9.5pp，均不显著）。
   （口径：因 n 与噪声量级所限，只能说「未观测到下降」，不说强「鲁棒」；原 8-28 D6 数字已弃用，见 §8-Q2。）
3. **架构对齐（残差 = sim2real 友好）**：确定性标称轨迹保证"分布内"，RL 残差只学小偏差——
   **残差受域差影响小**（消融实证：桌面域变化下端到端静态 68%→26.7%，残差仍 100%）；
   异常时残差归零即回到安全标称轨迹（可审计兜底）。
4. **参数契约文档化**：`docs/sim_to_real动力学匹配方案.md` 记录了速度环实现率、
   v_max 来源、伺服滞后测量等标定方法；`RL_DEPLOY_CONTRACT.md` 是训练-部署契约。
5. **域随机化预留**：4 周计划已规划摩擦/质量/位姿随机化（sim2real 前提），真机迁移需重标定
   的参数（摩擦、间隙、力增益）已列出。
6. **节奏策略**：仿真先行用于隔离变量（先证明奖励/控制架构，再上真机）；真机阶段 = 手眼标定
   （eye-to-hand 外参）→ 点云聚类碰撞体 → RL 域随机化与校准 → 安全层实机化
   （急停/速度力矩限幅/分离距离监控 ISO/TS 15066 风格）。

### 11.5 真机可能出现哪些问题

| 问题 | 仿真表现 | 真机风险 | 应对 |
|---|---|---|---|
| 动力学失配 | 速度环理想、参数已知 | 摩擦/惯量/电机延迟/关节间隙 → 轨迹偏差 | 速度环增益实机重标定（仿真的按关节标定方法可复用）；残差架构容错 |
| 观测噪声 | 关节力矩/位置无噪声 | 力矩传感器噪声、关节编码器量化 | 训练端加噪声/漏检（感知噪声探测，见 §8-Q2）；观测归一化 stats 实机重采集 |
| 目标定位误差 | oracle 真值 | 相机标定误差、YOLO 检测抖动、深度反投影误差（±cm 级） | 训练端加感知噪声；手眼标定精度控制；抓取接近段靠接触力/视觉伺服修正 |
| 决策延迟 | 25Hz 决策即时生效 | Servo 通信延迟、ROS2 消息延迟、控制周期抖动 | 预留延迟预算；动态场景提频 25→50Hz（`action_repeat 2→1`）；残差小步长容忍延迟 |
| 安全风险 | 无真实后果 | 奇异/碰撞/超速可能损坏设备或伤人 | **独立实时安全层**：速度/力矩限幅、分离距离监控（ISO/TS 15066 SSM）、急停；训练期即模拟限幅 |
| 奇异与限位 | 奇异=失败信号（惩罚+超时） | 奇异处速度爆炸、关节限位撞停 | 奇异检测实机化（阻尼伪逆 λ 已预留奇异降速语义）；safe_config 回退 |
| 抓取物理 | 刚体接触理想 | 物体材质/摩擦/重心不确定、夹爪磨损 | 域随机化（μ∈[0.3,0.9]）；抓取力控接口（2F-85 set_gripper_force）；衬垫接触参数校准 |
| 抬升/放置 | 速度标定 100% 跟随 | 物体滑移、振动、与桌面干涉 | 抬升降速 + 力控；放置位姿规划（MoveIt 管） |
| 传感器缺失 | 无相机也能训 | 真机必须视觉 | 部署侧深度相机链路已设计（YOLO + 深度反投影 + TF） |
| 环境差异 | 桌面固定几何 | 真实桌面杂乱、光照变化 | 点云聚类碰撞体动态更新（静态层 MoveIt）；RL 只管动态修正 |

**核心策略**：真机不是"把仿真策略直接跑"，而是**"仿真训练 + 感知/动力学校准 + 安全层兜底 + 残差归零可回退"**
——每一步都有文档化接口，这是本项目区别于"纯仿真 toy"的关键设计。


### 11.6 如何通过日志和实验逐步定位失败原因

**可用证据链（本项目实际使用的"取证工具"）**

| 工具 | 作用 | 位置 |
|---|---|---|
| `training.log` | 每次实验的完整配方 + 奖励/成功率/训练趋势 + 异常栈 | `rl_grasping_system/training.log` |
| 评估 JSON | episode 级 summary（success/final_distance/collision_count/length/残差幅度） | `results/*.json` |
| 失败模式分类 | 每个失败 episode 归因：超时 vs 碰撞 vs 奇异 | 评估脚本统计 |
| `reward_breakdown` | 每个奖励分量的贡献（r_dist_xy / r_dist_z / r_obstacle …） | `scripts/plot_reward_breakdown.py` |
| 验证脚本 | 物理/执行层单项验证（实现率/成功判据/IK 可达） | `scripts/verify_*.py` |
| 探针实验 | 改观测槽位看策略输出 diff → 区分感知问题 vs 奖励问题 | v11 感知锁死诊断 |
| 训练趋势 | 最近 10 vs 前 10 rollout 奖励对比（↗️/↘️） | TrainingMonitor |
| episode 长度 | 学习动力学信号（v12 均 25 步 = 探索被压死） | 评估 JSON |

**四步定位法（面试按这个顺序讲）**

1. **复现 + 分层取证**：先确认失败是可复现的现象，再分"物理/执行层、奖励层、训练层"定位。
   例：训练 0% 成功 → 先用 `verify_ee_pose_control.py` 证明执行层——发现小增量（Δz=0.003）
   实际实现率仅 8%（伺服过阻尼追不完）→ 根因在**执行层**（改速度级 IK + action_repeat=2）；
   若执行层正常，才怀疑奖励/训练层。
2. **单变量实验**：每次只改一个配方因子（惩罚强度/终止阈值/障碍布局），其余不动 → 归因干净。
   例：v18→v19 只改 collision_penalty/obstacle_w/clear_bonus 三连（v19 教训：三者同时强化无法归因，
   后 v20 回退一半单变量验证）。
3. **拆解/探针实验**：把"黑盒策略"拆开看。
   - **探针**：改观测槽位看输出 diff——v11 时 actor 障碍输入权重 norm 0.178（≈0）但 value 网络 12.1，
     → 证明"感知锁死"（策略根本没把障碍当输入），而非"奖励不足"；
   - **reward breakdown**：悬停问题 → 看 r_dist_z 在近距离的斜率 vs r_step 量级 → 证明
     "下降边际收益 < 步罚"（奖励塑形问题）；
   - **episode 长度**：v12 碰撞即失败 → episode 均 25 步 → 证明"探索被压死"（终止信号剥夺试错路径）。
4. **归因 → 决策**：区分"可调参修复"vs"结构性问题"：
   - 可修复：执行层实现率（速度级 IK）、悬停（近距离锚定）、撞桌（closing 微调约束）；
   - **结构性**：8 版端到端失败（奖励经济学 + 探索动力学在"双目标单网络"下不可解）→
     **路线级决策：改残差架构**，而非继续调参；v19/v20 证伪"提高碰撞经济学"→ 停止调参、换维度。

**三个完整案例（面试最有力的素材）**

1. **训练 0% 成功**：现象→执行层验证（实现率 8%）→ 归因：动作执行不到物理上
   → 修复：速度级 IK + action_repeat=2 → 验证：实现率 8%→96%，训练从 0 开始收敛。
2. **策略"悬停"不下降**：现象→reward_breakdown → 归因：近距离塑形斜率 < 步罚，收益权衡失衡
   → 修复：近距离锚定势能（斜率 ×3.5）→ 验证：下降段正常、成功率回升。
3. **v19 压碰撞失败（保守瘫痪）**：现象→评估失败归因：11/11 超时、其中 5 个 coll=0（"不敢动"）
   → 归因：惩罚过强使"接近障碍"期望值为负，动态障碍下学不会时序等待 → 决策：回退 v18 经济学，
   **承认 v18 是 Pareto 前沿，停止这条路线**——"知道什么时候收手"本身就是工程判断力。

**方法论总结（可直接写进简历"归因能力"）**：复现→分层取证→单变量→探针/拆解→归因→
"可调参修复 or 结构性问题"→决策。每版实验都留档（CHANGELOG + JSON），证据链完整可追溯。

## 12. 部署端架构与训练↔部署契约（面试素材）

> 部署端 = 兄弟仓库 `ros2_moveit2_ur5e_grasp`（ROS2 Humble + MoveIt2 + UR5e + Robotiq 2F-85 +
> Gazebo，Docker 一键启动）。两侧通过 `rl_grasping_system/docs/RL_DEPLOY_CONTRACT.md`（v3）绑定语义。

### 12.1 部署端三层架构（与训练侧混合架构一一对应）

```
┌──────────────────────────────────────────────────────────┐
│ 静态层 MoveIt2（确定性、可审计）                            │
│   深度相机 → 点云 → RANSAC去桌面 → 欧式聚类 → AABB碰撞体     │
│   → planning scene → OMPL 无碰撞标称轨迹（含静态避障）       │
└───────────────────────────────┬──────────────────────────┘
                                │ v_nominal(t)（Servo twist 参考速度）
┌───────────────────────────────┼──────────────────────────┐
│ 动态层 RL 残差（25Hz）                                    │
│   观测 = 关节状态 + 末端位姿 + 目标(视觉) + 标称速度 + 障碍  │
│   动作 = Δv → v_servo = v_nominal + Δv → Servo 叠加执行     │
└───────────────────────────────┼──────────────────────────┘
                                │ 实时监控
┌───────────────────────────────┼──────────────────────────┐
│ 安全层（独立实时兜底）                                     │
│   CBF 式约束 / 速度力矩限幅 / ISO/TS 15066 SSM 分离距离监控 │
└──────────────────────────────────────────────────────────┘
```

**分工矩阵**（为什么静态归 MoveIt、动态归 RL——直接对应训练侧残差架构）：
| 技能 | 负责方 | 训练端 RL 学吗 |
|---|---|---|
| 静态抓取 / 静态避障 | MoveIt OMPL 规划 | ❌ |
| 动态避障 / 动态抓取 | RL 残差 + 目标速度前馈 | ✅ 只学"修正" |

### 12.2 训练↔部署接口契约要点（`RL_DEPLOY_CONTRACT.md` v3）

- **动作**：`[dx,dy,dz]` 3D 位置增量（姿态固定朝下），**残差语义** `v = v_nominal + Δv/T`，
  限幅 `max_ee_delta=0.005` / `v_max=0.125`；
- **观测**：**67 维**（对齐训练侧布局：关节18+夹爪3+末端13+目标7+诊断7+四元数4+相位1+标称速度6+障碍6）；
  部署侧缺失的力矩/手指力/接触力等诊断通道**置 0 占位**（VecNormalize 归一化兜底，形状必须一致）；
- **执行**：速度 PID + 重力补偿前馈（复刻 UR speedJ）、速度级 IK 阻尼伪逆（λ=0.08）、决策 25Hz；
- **状态机**：approach → align（对齐触发）→ closing（力控闭合）→ closed → lift → place，两侧参数一致
  （`grasp_align_xy_tol=0.030`、`grasp_min_width=0.02`、`grasp_force_limit=20`、`lift_speed=0.003`）；
- **模型产物**：SB3 `.zip` + `_vecnormalize.pkl`（**必须一起**，zip 不含 obs_rms）；产品模型 v18_p3f。

### 12.3 部署侧感知链路（现状代码）

```
RealSense（Gazebo 仿真插件）
  ├─ /color/image_raw + /depth_registered → obj_detect.py（YOLOv11 检测 + 深度反投影 → /detection）
  ├─ det_tf.py（检测结果 → TF frame cube1..cubeN，camera_color_optical_frame 系）
  └─ /depth/points → point_cloud_processor.py → /depth/points_filtered
                       （Phase 1 升级：RANSAC 去桌面 + 欧式聚类 + AABB 碰撞体 → planning scene）
```

|---|---|
| `ur_bringup` | 启动 Gazebo 仿真 + MoveIt + 视觉（`simulation.launch.py`） |

## 13. 面试前自检清单（出门前过一遍）
